## 一、起因：用户说"文件选择器还没做，我无法导入"

用户拒绝手点真链路，理由是这个。而我上一轮的原话是
"**真文件选择器 ❌ 没测（真机自检点不了系统弹窗）**" —— **"没测"被读成了"没做"**，这个锅在我。

但顺着这条线查下去，**发现了一件真事**：用户并不是误会，而是**真的点不出来**。
证据来自本轮刚加的日志（见 §四）——用户在 `19:29:40` 打开面板、`19:29:41` 点了「导入 CSV」：

```
19:29:41  table import ask 文件选择器（getFileForOpening types=csv,txt,tsv）
19:29:41  table import FAILED 文件选择器抛错：Plugin is not permitted to access the file picker. Manifest entry not found.
```

## 二、根因：`requiredPermissions` 是空的

`manifest.json` 里原本是 `"requiredPermissions": {}`。
Adobe《UXP Filesystem Operations》明写 `localFileSystem` 的三个取值：

| 值 | 含义 |
|---|---|
| `"plugin"` | **默认**。只给沙箱（插件目录 / 数据目录 / 临时目录） |
| `"request"` | **允许用文件选择器请求用户授权** ← 我们要的就是这个 |
| `"fullAccess"` | 整盘不受限 |

空对象 ⇒ 落到默认 `"plugin"` ⇒ **选择器被拒**，报的就是"manifest entry not found"。

**修法**（取最窄的够用值，不请 `fullAccess`）：

```json
"requiredPermissions": {
  "localFileSystem": "request",
  "clipboard": "readAndWrite"
}
```

### 🔴 顺带纠正一条**错误结论**（并且顺手否掉自己的假设）

`docs/37` ⑧ 写着「剪贴板没有 ⇒ 导出只能走文件」，依据是 S38 里
`uxp.clipboard` 与 `require("clipboard")` **都拿不到**。我当时的假设是"那也是权限问题"。
本轮把 `clipboard: "readAndWrite"` 声明上、重载插件后再测：

> `②剪贴板：manifest.clipboard=readAndWrite、模块=拿不到、真写读回=没试（模块拿不到）`

⇒ **假设被实测否掉**：声明了权限照样拿不到 ⇒ 旧结论成立，只是理由要改成"权限已给、模块仍不可达"。
（唯一保留的可能性：**PS 重启后**再复测一次——权限是宿主启动时读取的。列为待办。）

## 三、🔴 这一轮最值钱的教训：**"存在" ≠ "能用"**

S35 / S38 当初是怎么写的：

```js
const hasOpen = typeof lfs.getFileForOpening === "function";   // ← 只问了"有没有"
```

然后就在档案里写成「`getFileForOpening` 有」，并在 `docs/40` 的"没验清单"里
把它归为"**没测**"——**其实它是"实测不可用"**。这两件事差得很远：
前者是"还没验"，后者是"用户点一次就撞墙"。

这已经是同一类错误在项目里的**第三次现场**：

| 次数 | 形态 |
|---|---|
| v0.3.9 S37 | 只验了 `center` 一档，差点写成"三档都通"（一档成立不许推广） |
| docs/40 的外框 | `fillEnabled:false`+`strokeEnabled:true` 这个**组合**没验就发了（卡死宿主） |
| **本轮** | **API 存在就被写成"有"，而权限没声明 ⇒ 调用直接抛** |

⇒ **写成可复用纪律**（已进 `MEMORY.md`）：
**"API/属性存在"只是"能调"的必要条件；写"有"之前必须真调一次、且要有能区分成败的读数。**
本轮的修法就是这条纪律的模板 —— S35 现在会**读插件自己的 `manifest.json`**，
判 `requiredPermissions.localFileSystem` 是否 `request`/`fullAccess`：

```
getFileForOpening=API 存在　manifest.localFileSystem=request ✓（选择器已授权）
```

这是**因果判据**（错误文案点名的就是"manifest entry 缺失"），且**可自动化**，
不必去弹那个系统窗口。它证明"门开着"，但**不证明"对话框一定弹得出来"**——那一步还是要人点（见 §七）。

## 五、给"系统弹窗点不了"这个死结开一条同源入口

既然自动化点不了系统文件选择器，就让面板自带一条**不弹窗**的入口：
**「内置样例」**（`tools/table.js` 的 `SAMPLE_SPECS` + `loadSample()`）。

- 三份样例放在**插件自己的目录** `vellum-toolbox/samples/`（随 ccx 一起走，已确认进包）：
  `prices-2026.csv`（UTF-8）/ `prices-2026-gbk.csv`（**GBK**）/ `prices-2026-tab.tsv`（制表符）
- 🔴 **关键设计**：`loadSample()` 与 `doImport()` 在"拿到字节之后"**共用同一个 `ingest()`**
  —— 同样 `read({format:binary})`、同样 `csv.readBytes()`。**两条路只差"怎么拿到字节"这一件事。**
  所以自检在这条路上跑通，就等于验了除"系统弹窗"以外的**全部**环节。
- 顺带它也是个真功能：第一次装插件的人不用先去找 CSV 就能看到效果。
- 样例字节**不许被 git 归一**：`.gitattributes` 里 `samples/* -text -diff -eol`
  （CSV 解析器要覆盖 CRLF/BOM/GBK，被换成 LF 就不再是"真实文件"了）。

## 六、面板整链自证：S42（并且我在这条探针上自己错了三次）

**S42**：建临时文档 → `showTool("table")` → 点「GBK」样例芯片 → 等预览 → 点「生成表格」
→ 验文档层数增量。期望值**独立算**：7 行 × 5 列 = 35 文字 + 外框 4 + 横线 6 + 竖线 4 + 表头背景 1 + 组 1 = **51**。

```

```

### 我在这条探针里错的三个地方（都值得记）

1. **`ps.findLayerDeep is not a function`** —— 我用了没导出的函数，而它一抛，
   **前面四条读数全跟着丢了**，只剩一句异常文本。
   ⇒ **读数必须比异常先到**：所有读数先声明在 try 外面，找组那一步单独兜异常。
2. **等的条件比要判的东西早了一步** —— 第一版等"层数涨到 51"（那只是第①批发完，
   状态栏还是"正在生成…"）；第二版改等"按钮从『正在生成…』恢复"，**又早一步**：
   `doGenerate` 在恢复按钮之后还要 `await` 一次日志落盘才 `setStatus`。
   ⇒ 最终判据：**等状态栏本身**，且要求它**与点击前不同**（否则同一会话连跑两轮会读到上一轮的陈旧文案）。
3. **🔴 我的探针伪造了一个"骇人读数"** —— 第一版在阶段二还没结束时就去关临时文档，
   于是日志写出 `m3 build 完成　新增 20 层　改名 1`。我一度把它当成产品缺陷在查。
   修好等待条件后取证显示：**阶段二 35/35 全对**，那个数字是**探针自己造的假象**。
   ⇒ **读到"惊人结论"时，先怀疑测量装置。**

### 阶段二的真实性能取证（顺带产出的真结论）

```
格数 12 → 选中 12/12 改名 12/12 对齐 12/12　耗时 599ms（19:37 那轮 579ms）
格数 35 → 选中 35/35 改名 35/35 对齐 35/35　耗时 9595ms（19:37 那轮 8494ms）
table build ok=true added=51/51 ms=11812 phase2=9595ms 选中35/35 改名35 对齐35
```

⇒ 阶段二 **≈50ms/格（12 格）→ ≈250ms/格（35 格）**，明显**超线性**。
51 层的表总耗时 **≈12s**，其中阶段二占 **9.6s**。
这是下一步该优化的一条实打实的目标（把逐格"选中 + set paragraphStyle"合并成一次 `batchPlay`，
或减少 DOM 选中轮转），已知可改、不必猜。

## 七、这一轮之后，**只剩一件事**要人做

**在 PS 面板里点一次「导入 CSV」**（权限已声明，预期这次对话框会弹）。

- 该做的准备都做好了：`manifest.localFileSystem = "request"`、三条失败路径都写日志、
  日志里会有 `table import ask …` 打头。
- 结果无论成败都**有读数**：
  - 成功 → `table import ok file=… via=picker enc=… rows=… cols=…`
  - 失败 → `table import FAILED 文件选择器抛错：<原文>`
- 期间**不需要手点**也能用「内置样例」跑完整条链（S42 已经替你跑过，两轮）。
