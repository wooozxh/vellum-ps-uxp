# 19 · 面板无法停靠（吸附）排查：不是代码问题，但暴露了加载方式问题

> 2026-10-10 · 第 13 次会话（与 `docs/18` 同轮，用户中途报的"新 BUG"）
> 触发：用户「**插件窗口无法吸附在主界面内**」
> 结论：**manifest/代码里没有可改的东西** —— UXP 平台不允许插件声明停靠位置。
> 但排查过程中查出本机一个真实的结构性问题：**插件一直是 UDT 开发态加载，从未正式安装**。

---

## §一 用户原话

> **新BUG：插件窗口无法吸附再主界面内**

（原文"再"应为"在"）

---

## §二 先说结论（三句话）

1. **停靠本身是平台支持的** —— Adobe 官方原文：「UXP panels ... **can be resized, docked,
   opened and closed just like native Photoshop panels.**」
2. **但插件没有资格声明"我要停在哪"** —— 官方明确：**没有这个机制，停靠位置完全由用户手动拖**。
   社区里流传的 `location` / `dockConfig` 字段**不在官方字段表里，PS 会忽略**。
   ⇒ **这一条我改不了代码，manifest 里也没有可改的字段。**
3. **本机的真实变量**：插件一直是 **UDT 开发态加载**（有 `.uxprc` 会话文件、数据落在
   `PluginsStorage\...\**Developer**\`、没有 `External` 目录、没有 UPIA）。
   Adobe 工程师明确说过：**开发态加载的插件，面板位置不进工作区** ——
   这能解释"吸上去也留不住 / 每次重载又回到浮动"。

---

## §三 查证到的四条事实（都带出处）

| # | 事实 | 出处 |
|---|---|---|
| ① | UXP 面板**可以**像原生面板一样缩放 / **停靠** / 开关 | Adobe 官方 UXP for Photoshop 概览 |
| ② | **插件无法指定停靠位置**：「There is currently no mechanism to specify where you'd like to be docked; **the user has full control over this**.」 | Adobe 论坛，kerrishotts（Adobe / PS 团队），2021-07 |
| ③ | 「Plugins **cannot currently indicate where they'd like to appear in the workspace**」 | 同上，另一帖（Modify the location of an UXP plugin） |
| ④ | 「You can use Photoshop's Workspaces though. This **only works on startup with a packaged/installed plugin**; in the case of a plugin loaded with the **UDT** one would need to **reset the workspace** to reposition the panel.」 | Adobe 论坛，Timothy_Bennett（Adobe），2022-11 |

**manifest v5 官方字段表**（[manifest-v5 文档](https://developer.adobe.com/photoshop/uxp/2022/guides/uxp-guide/uxp-misc/manifest-v5/)）里，
panel 类 entrypoint 只有这 8 个字段：

```
type / id / label / minimumSize / maximumSize
preferredDockedSize / preferredFloatingSize / icons        （v5 另加 title）
```

**没有 `location`，没有 `dockConfig`，没有任何"初始停靠位置"字段。**
社区帖里有人试过写 `location.dockConfig.dockTarget = "right"`，结论是 **PS 不认**。

> 我们的 `manifest.json` 与 Adobe 官方 v5 示例**逐字段一致**（panel 段只有上面那几项，
> 尺寸也在官方示例的量级内）。所以：**这块没有"改一改就好了"的空间。**

## §四 本机的真实情况（证据）

| 证据 | 读数 | 说明 |
|---|---|---|
| `%CommonProgramFiles%\Adobe\UXP\Developer\settings.json` | `{"developer": true, "hostAppPluginWorkspace": true}` | **开发者模式已开** |
| `vellum-toolbox/.uxprc` | `pluginSessionId: 46e12504-…`、`app.version 27.2.0`，mtime 18:54 | **UDT 的会话文件**，证明插件是**会话式加载**的 |
| `%APPDATA%\Adobe\UXP\PluginsStorage\PHSP\27\` | 只有 `Developer` / `Internal` / `Shared` | **没有 `External`** —— `External` 才是"正式安装的插件"落点 |
| `C:\Program Files\Common Files\Adobe\UXP\Plugins\` | 不存在 | 同上 |
| `…\Adobe Desktop Common\…\UPI\UnifiedPluginInstallerAgent\` | **不存在** | 装 `.ccx` 的正规通道缺失 |

⇒ **这台机器从来没有正式安装过任何 UXP 插件**，`vellum-toolbox` 一直是 UDT 开发态加载的。
这正是事实 ④ 描述的场景。

## §五 该怎么做（按代价从低到高）

**第 1 步｜确认你拖的是"标签页"而不是面板主体。**
PS 的停靠是靠**面板顶部的标签（tab）**：按住标签往屏幕右侧（或左侧）的面板停靠区拖，
**拖到边缘出现一道高亮落位提示**再松手，它才会嵌进侧栏。
拖面板中间的 UI 区域是不会有任何吸附反应的。

**第 2 步｜先让停靠区露出来。**
菜单 **窗口 › 工作区 › 复位基本功能**；若 PS 是"拼合窗口"以外的状态，
先 **窗口 › 排列 › 拼合窗口**。停靠区看不见的时候，往哪拖都不会有落点提示。

**第 3 步｜接受"开发态不保留位置"这件事。**
开发态加载（UDT）下面板位置不进工作区 —— 重载插件 / 重启 PS 后，
面板会回到左上角浮动。**这不是 bug**，要它记住位置就得走正式安装。

**第 4 步（治本）｜正式安装一个 `.ccx`。**
正式安装的插件才算工作区成员，停靠位置才会被记住。但本机目前**装不了**：
UPIA 缺失、Creative Cloud 桌面端缺失（见 `docs/01` §5）。
一旦补上 CC，安装命令是：

```
cd "C:\Program Files\Common Files\Adobe\Adobe Desktop Common\RemoteComponents\UPI\UnifiedPluginInstallerAgent"
UnifiedPluginInstallerAgent.exe /install "D:\ps-uxp-dev\dist\com.vellum.toolbox_PS.ccx"
```

或者直接双击 `.ccx`（会在 CC 桌面端里走一遍安装确认）。

## §六 这一轮我实际做了什么

排查结论是"没有可改的代码"，但不能空手收工 —— 顺手把**唯一真正阻塞第 4 步的东西**修了：
`dist/com.vellum.toolbox_PS.ccx` 还是 **14:51** 打的，早于 v0.2.0 / 0.2.1 / 0.2.2 / 0.2.3，
既不完整也不能用来分发。

**新增 `tools/build-ccx.cjs`** —— 自己写 zip 打包，不再依赖 UDT 的 Package 按钮：

```bash
node tools/build-ccx.cjs            # 打包
node tools/build-ccx.cjs --check    # 只列条目做验收
```

三条硬约束（都写进脚本头了）：

- **`manifest.json` 必须在 zip 根**（不能套一层目录），否则 UPIA 认不出这是插件包；
- **必须排除开发态文件**：`verify.flag`（自检开关，带上会让用户一开 PS 就闪临时文档）、
  `.uxprc`（UDT 会话文件）、所有点开头的文件/目录；
- **写完必须回读校验**（中央目录条目数一致 + manifest 在包根），不是"写完就当成功"。

> 为什么不用 PowerShell 的 `Compress-Archive`：这个环境里 PowerShell 的 stdout 拿不到，
> 第一次执行**静默失败**（退出码 0 但文件没生成）——已经踩过一次，不再用。

**产物**：`dist/com.vellum.toolbox_PS.ccx`，v0.2.3，**237,291 字节 / 23 个条目**，
`manifest.json` 在包根，回读校验通过，无任何开发态文件。
