# 25 · 两个界面需求的可行性评估（下拉筛选控件 / 拖到画布指定位置）

> 会话：2026-10-11（第 18 次）
> 触发：用户提出两个界面需求 ——
> **需求 A**：通用库的二级筛选现在是一排按钮，**UI 臃肿**；建议二层改成**下拉选择控件**（样式沿用现有风格）。
> **需求 B**：能否**把素材拖动到画布指定位置**。
> 本文只做**评估**，不实现 —— 结论都带证据，未验的如实标"未验"。
>
> **本轮不动业务代码**，只新增了一个诊断项（自检 **S23**，v0.2.9）把能力问清楚。

|---|---|---|

## 一、需求 A：二级筛选改成下拉控件

### 1.1 真机实测（自检 S23，PS 27.2.0 / UXP 9.0.2）

**① 原生 `<select>` / `<option>` —— 能用，但读值必须绕道**

```
建出✓ 几何=120x24　options=3　option[1].textContent="节日素材"
setAttribute("value","festival") 之后 .value        = "undefined"   ← 官方 known-issues 说的坑，真实存在
改走 option[1].selected = true 之后：
    option.selected = true
    select.selectedIndex = 1
    select.value = "festival"        ← ✅ 这条路是通的
```

⇒ **`<select>` 可用，但纪律是**：**不要**用 `setAttribute("value")` 或直接赋 `.value` 去设选中项
（设了读不回来），**必须用 `option.selected = true`**；读值用 `.value` / `.selectedIndex` 都可以。

**② Spectrum 组件（sp-picker / sp-dropdown / …）—— 不可用**

```
sp-button      [未注册  display=block  shadow=无  几何=0x0]
sp-textfield   [未注册  display=block  shadow=无  几何=0x0]
sp-picker      [未注册  display=block  shadow=无  几何=0x0]
sp-dropdown    [未注册  display=block  shadow=无  几何=0x0]
sp-menu-item   [未注册  display=block  shadow=无  几何=0x0]
基准·sp-not-a-real-thing-xyz [未注册  display=block  shadow=无  几何=0x0]   ← 伪造标签名，读数一模一样
‖ 注册表 API：define=function  get=function  whenDefined=function
```

**三个判别 + 一个基准**：
- `customElements.get()` 全部"未注册"；
- `shadowRoot` 全部"无"；
- computed `display` 全部 `block`；
- **伪造的标签名三项读数与真组件** **逐项相同**。

而**注册表 API 是真实存在的**（`define`/`get`/`whenDefined` 都是 function）——
所以"未注册"是**可信读数**，不是"注册表不存在所以查什么都说未注册"。

> ⚠️ **我这一项第一版判错了**，留痕：第一版我用"设了宽高之后 `sp-picker` 几何=120x24"当证据，
> 结论写成"渲染出来了"。**但把伪造标签名放进去，几何同样是 120x24** ——
> 那个读数只证明"我给它设的宽高生效了"。加上"不设宽高 + 伪造标签名当基准"之后才看清真相。
> （同族错误在本项目已是**第六次**：判据描述的是"看起来像的东西"，不是"我等的那个东西"。）

**③ 结论：下拉控件要自绘。**

---

### 1.2 三个方案对比（结论：**自绘**）

| 方案 | 可行性 | 代价 |
|---|---|---|
| **原生 `<select>`** | ✅ 可渲染、可读值（走 `option.selected`） | ① 已知 issues 一串（arrow key、`value` 反射、宽度要显式给……）；② **下拉弹层能否正常打开未验**（要真点击）；③ **样式无法沿用现有风格**（原生控件外观改不动，与我们的 token 体系对不上） |
| **Spectrum `sp-picker`** | ❌ **实测不可用**（未注册） | — |
| **自绘下拉**（`div[role=button]` + 绝对定位列表） | ✅ 原料齐（见 2.3 的鼠标事件有实物基准） | 要自己写展开/收起/点外关闭 |

**建议：自绘。** 理由三条：
1. 用户明确要求"**样式沿用目前风格**"—— 原生 `<select>` 恰恰做不到这一点；
2. Spectrum 那条路已经实测死掉；
3. 自绘的**唯一真风险我们刚好踩过并已有纪律**：浮层与触发条的**振荡回路**
   （调色板的悬停闪烁就是这么来的）。

**自绘下拉要遵守的硬纪律**（直接沿用调色板那次的四条）：
- **浮层不得覆盖触发条**（纵向留间隙，放下方）——否则指针落到浮层 → 触发条失焦 → 浮层消失 → 又出现 → **疯狂闪烁**；
- 关层逻辑**不绑被覆盖元素的 `mouseout`**，由**容器根节点正着判**"指针还在不在这个组件内"；
- 状态**幂等**（没变化就不写 DOM）；
- 尺寸**让帧之后**再量（布局是异步的）。

## 二、需求 B：拖到画布指定位置

### 2.1 结论分两半（别混为一谈）

| 子问题 | 结论 | 依据 |
|---|---|---|
| **真·拖放到画布**（从面板拖出去、松手落在光标处） | ❌ **不可行** | 两条独立证据见 §〇；本项目实测再加一条：**`DataTransfer` 在 UXP 里根本不存在** ⇒ 标准拖放**没有数据通道** |
| **"放到指定位置"** | ✅ **可行**（已验证到像素级） | 见 2.2 |

> 也就是说：做不到"**用鼠标拖过去**"，但完全做得到"**落点由用户指定**"。

### 2.2 `placeEvent` 的落点行为（MCP 真机实测，临时文档 400×400，素材 320×240）

```
默认（offset 0,0） → 图层 bounds = 40,80,360,320     ⇒ 画布居中、且**不缩放**（仍是 320×240）
offset (64,48)     → 图层 bounds = 104,128,424,368   ⇒ Δ = 正好 +64 / +48，**1:1 精确**
```

⇒ **`offset` 是像素级精确的定位参数**，`Δoffset = Δbounds`。
插件侧要"放到 (x,y)"，只需要：

```
offsetX = x − (画布宽 − 素材宽) / 2
offsetY = y − (画布高 − 素材高) / 2
```

而这两项插件**都已经有**：画布尺寸来自 `lib/ps.js docInfo()`，
素材宽高来自镜像里的 `asset.width / asset.height`（契约 §5.4 必填字段）。
**⇒ 不需要任何新能力，现有接口就能算出来。**

### 2.3 三个交互选项（按实现代价排序）

| 选项 | 交互 | 代价 | 状态 |
|---|---|---|---|
| **(a) 九宫格落点** | 面板里选「左上 / 上中 / … / 居中 / … / 右下」+ 一个边距值 | 小（纯面板内 + 一个 `offset` 计算） | ✅ 原料全备 |
| **(b) X/Y 数值输入** | 两个输入框，精确到位 | 中（输入控件 + 校验） | ✅ 原料全备 |
| **(c) 读选区当落点** | **你在画布上框一块，插件就放在那儿**（最贴近"指定位置"的直觉） | 中（要读选区 bounds + 置入后按矩形缩放） | ⚠️ **未验**（见下） |

### 2.4 (c) 选区落点 —— **未验，且有一条"看起来像结论"的读数必须说清**

我在 MCP（**ExtendScript** 通道）上试造选区，结果：

```
S0 selection 对象存在        → 有
S1 selectAll()              → ✅ 0,0,400,400        ← **基准：选区对象本身是可用的**
S2 deselect()               → ✗ 错误: 没有这种元素
S3~S7 带区域的 select(…)    → ✗ 全部失败（没有这种元素 / 非法参数，5 种写法都试了）
```

⚠️ **这条不能读成"选区落点不可行"**：
- 失败的是 **ExtendScript 的 legacy DOM**（MCP 走的就是这条）；
- 而**插件走的是 UXP DOM + batchPlay，完全是另一条路**；
- 并且**基准（`selectAll`）是成功的** —— 说明"选区对象可用"，失败的是**那几种区域写法**。

⇒ 如实记为：**选区落点"未验"**，需要单独做一次探针（用插件侧的 UXP/AM 去建/读选区）。
**在验证之前，不把它写进方案。**

## 三、其他相关实测（顺带拿到，后面会用到）

| 项 | 读数 | 意义 |
|---|---|---|
| `draggable` 属性 | 被记住（`"true"`） | 属性本身生效，**但没用** —— 没有 `DataTransfer` |
| `DataTransfer` | **`undefined`** | 标准拖放没有数据通道 |
| `setPointerCapture` / `releasePointerCapture` | 都是 `function` | 自绘拖拽的原料在 |
| `on*` 反射属性（`onmousedown` 等） | `false` | ⚠️ **不影响 `addEventListener`** —— 调色板的 hover / click / dblclick 全是 `addEventListener`，是**实物基准**；`on*` 只是 UXP 没做 IDL 反射 |

**鼠标事件是"有实物基准"的**（调色板在生产里跑着），所以**自绘拖拽建议基于鼠标事件 + 自己的状态机**，
而不是押"pointer 事件真会触发"（那一条只能由人手动试）。

## 四、建议的推进顺序

1. **需求 A 直接做自绘下拉**（风险低、收益明确、样式可控）；
2. **需求 B 先做 (a) 九宫格落点**（零新能力依赖，立刻可用）；
3. **(c) 选区落点** 单独立一个探针（S24）：先在插件侧把"建选区 / 读选区 / 置入后按矩形缩放"三件事验掉，
   成立再升级成"**框哪儿放哪儿**"——那才是用户真正想要的"指定位置"。
4. 拖放本身（真拖）**不做**，但在 `docs` 里记一条"等 Adobe 修"的观察点（论坛显示已有修复在排队）。

## 五、诚实清单（未验 / 不能断言）

1. **`<select>` 的下拉弹层**能否正常打开 —— 要真点击才能验（我只验了"能建、能读值"）。
2. **选区当落点** —— 未验（ExtendScript 侧区域写法失败，但基准 `selectAll` 成功；插件侧的 UXP/AM 是另一条路）。
3. **置入后按目标矩形缩放**（fit 到 rect）—— 未验。`offset` 只管**位置**，不管**尺寸**。
4. **自绘拖拽的鼠标事件真触发** —— 需要人用真鼠标验证（合成事件不算）。
5. **当前视图中心**（而不是画布中心）作为落点 —— 未查 PS 是否暴露视图滚动位置。
