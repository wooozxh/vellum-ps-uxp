## 契约加法（草案，供你按 §十「加法」流程落进契约正文）

> §十 明确：**新增 scope 属「加法」，不升版本**；两侧各自在 DECISIONS.md 记一条。
> 下面是插件侧给出的字段定义草案 —— 你确认后写进契约对应章节（§4 目录图 / §5 新增 5.7 / §六 规则 8 的 scope 白名单）。

### (1) manifest.json 的 scopes[] 加一条

```jsonc
{ "id": "tpl", "label": "模板", "file": "tpl.json", "revision": 1, "count": 8 }
```
（`revision` 与既有两库同语义：内容一变就 +1，插件靠它判断"要不要重读"。）

### (2) 新文件 `tpl.json`（放 `library\` 下，与 task.json / brand.json 并列）

```jsonc
{
  "contract": "vellum-link/1",
  "scope": "tpl",
  "revision": 1,
  "generatedAt": "2026-10-17T03:40:00+08:00",
  "items": [
    {
      "id": 1,
      "name": "易拉宝 80×180（含3mm出血）.psd",
      "ext": "psd",
      "kind": "template",
      "size": 2400000,
      "width": 1772,          // ★ 模板画布像素宽。**必填**（见下方注）
      "height": 4134,         // ★ 必填
      "resolution": 150,      // ppi，读不到可 null
      "mode": "CMYK",         // 读不到可 null
      "usage": "易拉宝",       // 用途（可选）—— 插件据此筛/排
      "frameMm": "800×1800",  // 成品尺寸（可选，给人看）
      "bleedMm": 3,           // 出血（可选）
      "thumb": "thumb/p1.png",
      "missing": false,
      "modifiedAt": "2026-10-10T10:00:00+08:00",
      "absPath": "D:\\...\\模板\\易拉宝80x180.psd",
      "tags": ["易拉宝", "展架"]
    }
  ],
  "groups": []
}
```

注：§5.4 允许素材的 `width`/`height` 为 null（视频/PDF 等）。**模板不同 —— 尺寸是必填**：
它是列表上唯一能让同事一眼分辨的信息，读不到就不该收录。

### (3) 缩略图命名空间：模板用 `p<id>`

现有：任务库 `t<id>`、通用库 `b<id>`（两库 id 各自从 1 起，靠前缀防同名覆盖）。
⇒ 模板库请用 **`p<id>`**（例 `thumb/p1.png`）。
（对插件**透明** —— 它把 `thumb` 当不透明相对路径，从不解析文件名。）

### (4) handoff 复用，不新建通道

模板 PSD 的搬运**沿用既有 handoff**（契约 §六），只是 `scope` 换成 `"tpl"`：
  插件写 req.json（`{ assetId, scope: "tpl" }`）→ 你在 **tpl scope 内**反查 → 拷成
  `handoff/incoming.psd` → 写 res.json → 插件 app.open 打开它。

## ⚠️ 三条技术注意（每条都能让整件事失败）

1. **`incoming.<ext>` 的扩展名必须跟着源文件走。** PSD ⇒ `incoming.psd`。
   现有实现若把扩展名写死成 `.jpg` / `.png`（历史默认是图片），模板会**全军覆没**。
2. **`scope` 白名单要加上 `tpl`。** 契约 §六 规则 8 写明「**未知取值 → `ok:false` + `error:"bad_request"`**」
   —— 不加就会被插件收到"参数错误"，而现象很像"软件没响应"。
   （§六 规则 8 就是当年 brand 库那段占位桩忘拆、导致"通用库永久无法置入"的教训。）
3. **mtime 归零（§六 规则 6b）对模板更重要。** 它是「拷贝后把时间戳盖成现在」那条规则；
   模板往往是"很久以前做的"，带着旧时间戳必被你们自己的过期清理（>10 分钟）误杀。
   顺序对（规则 6）还不够，**时间戳也要对**。

另：**体积**。handoff 是把整份 PSD 拷进**插件在 C 盘的 `PluginData`**。
⇒ 请在**收录时**就按 **≤ 20 MB** 卡住（拍板第 4 项）。模板应只含版式与图层结构，
**不要把大图打包进模板 PSD**。超限就拒绝收录 + 提示"请瘦身"，不要静默放过。

## 插件侧已经做过的实测（你不用重验，地基是实的）

判据全部是"读回"，读数已写进插件侧 DECISIONS.md：
  ✅ `presetJSON` 建稿能携带参考线（600×400 @300 → 回读 guides=4）
  ✅ 存成 PSD 后**重新打开，参考线仍在**（回读仍是 4）—— 你要的"参考线打好直接调用"成立
  ✅ `app.open(Entry)` 能打开插件目录里的文件（**必须在模态里**调）
  ✅ `Entry.delete()` 可用、文件真会被删掉（⇒ 插件侧**能自己清理** handoff 残留了，
     你们那边的过期清理可以保留、但不是唯一保障）
  🔴 `Document.name` **不可改**（赋值不生效）⇒ 插件打开 handoff 来的 PSD 时，
     文档名**一定是 `incoming.psd`**（PS 拿文件名当文档名）。
     插件侧会**如实提示用户**"这是模板副本，请另存为你的文件名"—— 你这边不用为它做特殊处理。

## 验收标准

  1. 软件侧新增「模板」分区（**独立于**通用素材库），能收录/改名/删除 PSD 模板，可见参考线预览
  2. 收录时卡 20 MB 上限并把"尺寸（wn×h）"读出来（读不到就拒绝收录并说明原因）
  3. 镜像里出现 `tpl.json` + `thumb/p<id>.png`，`manifest.json` 的 `scopes[]` 出现 `tpl` 条目
     （注意 §5.6：`manifest.json` 是**合并写** —— 加 tpl 那条时**别丢掉 task / brand 两条**）
  4. handoff：收到 `scope:"tpl"` 的 req → 在该 scope 内反查 → 落 `incoming.psd` → mtime 归零 → 写 res
  5. **补回归断言**（照你们既有 accept 的做法，建议至少 4 条）：
     合法 tpl 反查成功 / 未知 id → not_found / 未知 scope → bad_request / 超 20 MB → 拒绝
  6. 完成后在 `D:\vellum-link\LINK-LOG.md` **末尾追加**一条：
     `- [软件侧] 2026-XX-XX · <做了什么>（含 accept 断言数变化）`
     —— 按公告板硬性格式：角色 + 日期 + 一句话；需要插件侧动作时才写"需要对方"

## 边界与如实交代

  - 插件侧**还没有**模板读取的实现（等你这边能写出 tpl.json 后做）；
    在契约加法落定前，插件侧**不会**按任何一方的字段定义硬编码。
  - 插件侧**不能**读你工作区的任意路径（`placeEvent`/打开都拒裸路径，§9.1 第 9 条）
    ⇒ 模板的原图搬运**只能靠 handoff**，没有替代方案。
  - 「模板参考线读回坐标」在插件侧仍是未解决项（`doc.guides[i]` 只回 `_id`）
    ⇒ 插件**不读**你模板里的参考线坐标，它只保证"打开后线还在"。所以**参考线必须由你在模板 PSD 里打好**。
