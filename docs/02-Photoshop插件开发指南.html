02技术路线选型

Adobe 在 Photoshop v22.0（2021）引入新扩展平台 UXP，逐步取代旧的 CEP / ExtendScript。新项目一律走 UXP，旧技术仅在维护老插件时才需要了解。

UXP Plugins（插件）

推荐 · 主线

用 HTML / CSS / JavaScript 构建面板与模态对话框，可直接调用 Photoshop DOM API 与 UXP API，无需字符串序列化桥接。是用 AI 开发的首选形态。

PS ≥ 22.0JS / HTML / CSS.ccx持续开发

UXP Scripts（脚本）

入门最快

直接写现代 JS 自动化重复任务，无需打包和完整插件结构，适合验证想法、跑批处理。文件后缀 .psjs。

PS ≥ 23.5JavaScript ES6+.psjs

UXP Hybrid Plugins（混合）

进阶

JS / HTML / CSS 配合 C++（WASM 原生模块），适合需要高性能计算或访问原生能力的场景。

PS ≥ 24.2C++ + JS.ccx

CEP + ExtendScript

已停止开发

旧插件体系（PS 14–20），Adobe 已不再积极开发，未来将逐步移除。仅用于维护存量插件，且不兼容 Apple Silicon 与 Windows ARM。产物 .zxp。

PS 14–20ExtendScript (ES3)

C++ Plug-in SDK

底层

最底层的原生插件（过滤器、图像格式、选择工具等），性能最强但门槛最高。PS CS3+ 均支持。

C++DLL / EXE / DMG

Photoshop API（云端 REST）

服务端

在云端用任意语言调 REST API 批量处理图片，支持播放 Photoshop 动作。不是本机插件，适合服务端自动化。

任意语言REST / APIs

产品形态：先想清楚是 Command 还是 Panel

Command（命令）

一次性动作：从菜单触发，执行一个任务后结束，只有可选的输入/确认对话框，没有常驻 UI。

entrypoints: [{ type: "command" }]

Panel（面板）

常驻工作区：停靠在宿主自带面板旁边，整个会话期间持续存在、可交互。复杂工具几乎都是这个形态。

entrypoints: [{ type: "panel" }]
产品形态未定也不必卡住：两者可以同时存在于一个插件里。建议先各做一个最小样例找手感，再定方向。

配置 / Manifest（v5 为当前版本）
  • UXP Manifest v5 规范 当前版本，需 PS ≥ 23.3 / UXP 6.0+。新增权限模型与 WebView
  • Manifest v4（历史版本） 字段逐一说明，读 v5 的差异对照时用
  • Photoshop Manifest 附录 PS 特有字段与版本破坏性变更说明
Manifest v5 三个必记要点：① 顶层写 "manifestVersion": 5，UI 入口用 entrypoints（v4 时代叫 uiEntryPoints）；② 权限默认全关，用到的能力必须在 requiredPermissions 显式声明；③ 权限类型：network.domains / clipboard / localFileSystem(request·plugin·fullAccess) / launchProcess / webview / ipc / enableUserInfo。
// 最小可用 manifest.json（官方示例精简）
{
  "manifestVersion": 5,
  "id": "com.yourname.plugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "main": "index.html",
  "host": { "app": "PS", "minVersion": "23.3.0" },
  "entrypoints": [
    { "type": "panel", "id": "mainPanel",
      "label": { "default": "My Panel" },
      "minimumSize": { "width": 230, "height": 200 } }
  ],
  "requiredPermissions": { "localFileSystem": "request" }
}

建议的学习路径

  1. 写一个 UXP Script（.psjs）

    不打包、不建工程，直接在 PS 里跑一段 JS 操作图层，先理解 app / document / layer 对象模型与异步写法。

  2. 跑通 vanilla starter

    用 UDT 建 ps-starter / hello-world-panel-js-sample，理解 manifest、entrypoints、面板加载流程。

  3. 进阶到框架 starter

    改用 ui-react-starter / ui-vue-starter，引入 Node 构建链，做更复杂的 UI。

  4. 用 Alchemist + batchPlay 做真实功能

    录一段你常做的操作 → 生成 batchPlay → 包进 executeAsModal → 做成自己的工具按钮。

  5. 打包发布

    UDT 一键打包 .ccx；上架 Marketplace 则去 Developer Console 申请正式插件 ID 并走审核。

补齐缺口：五步走

  1. 装 Creative Cloud 桌面端并安装 UDT

    下载安装 CC 桌面端 → 登录 Adobe 账号 → Apps 分区搜索 "UXP Developer Tools" → 点 Install。UDT 目前无法单独下载，CC 是唯一官方通道。

  2. 启用开发者模式（Developer Mode）

    首次启动 UDT 会弹窗提示，点 Enable 并授予管理员权限。
    兜底（需管理员）：在 %CommonProgramFiles%\Adobe\UXP\Developer\ 建 settings.json，内容 {"developer": true}（macOS 为 /Library/Application Support/Adobe/UXP/Developer/）。
    同时在 Photoshop 内：设置 → 插件 → 勾选「启用开发人员模式」，然后重启 PS。

  3. 创建插件工程

    两种方式：① UDT 里点 Create Plugin，填 Name / Plugin ID / Host = Adobe Photoshop / 版本，模板选 ps-starter（vanilla）或 ps-react-starter。
    ② 克隆官方示例仓库里合适的 starter：

    git clone https://github.com/AdobeDocs/uxp-photoshop-plugin-samples.git
cd uxp-photoshop-plugin-samples/ui-react-starter
corepack enable          # 如需 yarn，Node 自带，无需另装
yarn install && yarn build   # 生成 dist/

  4. 加载到 Photoshop 调试

    保持 Photoshop 运行 → UDT 左侧应出现 "Adobe Photoshop"（含宿主版本与 UXP 版本）→ 插件行点 Load（或 ••• → Load）。
    框架工程注意：加载路径要指向 dist/manifest.json，而不是源码根目录。

  5. 迭代与验证

    Watch 模式下改 HTML/CSS/JS 自动热重载；改 manifest.json 不会热重载，必须先 Unload 再 Load。调试用 ••• → Debug 打开开发者控制台。

最小工程结构：manifest.json（配置）+ index.html（面板 UI）+ index.js（逻辑）+ icons/（图标）。框架工程在此基础上加 package.json / webpack.config.js / src/，产物在 dist/。

08AI 辅助开发

用 AI 写 PS 插件完全可行，但必须理解 UXP 的边界——它不是浏览器，也不是 Node。把正确的上下文喂给 AI，是效果好坏的分水岭。

必须先让 AI 知道的硬约束

UXP ≠ 浏览器 / ≠ Node

只支持 HTML/CSS/JS 的子集。引宿主模块用 require("photoshop") / require("uxp")，不是 import 那套；没有完整 DOM。

改文档必须包模态作用域

所有会修改文档的操作都要放进 core.executeAsModal(async () => {...})，否则报错（模态被占用返回错误码 9）。这是 AI 最容易写错的地方。

API 未覆盖 → 用 batchPlay

Photoshop DOM API 仍在完善，未暴露的功能靠 batchPlay 回放 Action Manager 描述符。不能让 AI 凭空编，要用 Alchemist 录。

权限默认全关（v5）

文件、网络、剪贴板、本地存储等必须在 manifest 的 requiredPermissions 显式声明，沙盒不会默认放开。

给 AI 的「知识来源」建议

方式做法适用
文档上下文把 DOM API / UXP API / Manifest v5 / Spectrum 文档关键页贴进会话或做成知识库通用编码辅助
官方示例当模板让 AI 参考 uxp-photoshop-plugin-samples 里的同类 starter 再改快速起步
TS 类型定义引入 @adobe-uxp-types/photoshop，让 AI 有类型提示、减少瞎编 APITypeScript 工程
Alchemist 录 batchPlay录出真实描述符再交给 AI 改，而不是让 AI 猜功能实现
MCP 直连用 adb-mcp 让 AI 直接驱动 PS 并自我验证自动化与验证

可直接粘贴给 AI 的上下文模板

【项目】Photoshop UXP 插件开发
【宿主】Photoshop 2026 (27.x)，Windows
【规范】manifest v5；UI 用 HTML/CSS/JS（UXP 子集）+ Spectrum 组件
【硬约束】
1. UXP 不是浏览器也不是 Node：引模块用 require("photoshop") / require("uxp")，不是 import。
2. 任何修改文档的操作必须包在 core.executeAsModal(async () => {...}) 内。
3. DOM API 未覆盖的能力，用 batchPlay 回放 Action Manager 描述符（不要编造 DOM 方法）。
4. 文件/网络/剪贴板/本地存储等权限必须在 manifest 的 requiredPermissions 显式声明。
5. 面板入口用 entrypoints（type: "panel"），命令入口用 type: "command"。

09常见坑与备忘

改了 manifest 不生效

manifest.json 不参与热重载。改完必须 Unload → 重新 Load。

框架工程加载失败

UDT 里要指向 dist/manifest.json，不是源码根目录。

UDT 连不上 PS

确认 PS ≥ 22.0、已开启开发人员模式、UDT 以管理员权限运行。

改文档报错

检查是否遗漏 executeAsModal 包裹；模态被占用会返回错误码 9。

权限被拒

v5 起权限默认全关，用到什么就声明什么；openExternal / openPath 会弹运行时同意框。

依赖版本冲突

Spectrum 组件跨版本有破坏性变更，建议锁定确切版本号而非用 ^/~。

npm / yarn 报错

多为 Node 版本不匹配；本机已用偶数版 v22，必要时改用 npm。

import 报错

UXP 里必须用 require 引宿主模块，不支持 ESM 的 import。
