## 一、结论速览

| # | 问题 | 结论 | 分级 | 对架构的影响 |
|---|---|---|---|---|
| 1 | **矢量线条怎么画** | ✅ **可做成「矩形形状图层」**（`contentLayer` + `shape:rectangle`），`kind=solidColor` = 内容图层 = 矢量；bounds 精确命中、线内取色命中 | 基准成立 + 目标成立 = **可行** | 不必退回位图；**每格线一层** |
| 2 | **文字精细参数够不够** | ✅ **够，但要分两条路**：建层用官方框文本描述符；**字号/颜色/字距**走 AM `set textStyle`；**文字内容**走 DOM `textItem.contents`；**对齐**走 AM `set paragraphStyle`（字段 `align`） | 可行 | 样式在建层时给 + 事后能改；**没有"一次设好所有属性"的单一接口** |
| 3 | **批量出稿的形态** | 🔴 **UXP 侧没有"变量 + 数据组"**（`dataSets`/`variables` 读不到）；✅ **替代路径成立**：复制图层组 + 逐组换文字（副本改了 **且** 原件没变） | 目标不可行 / 替代可行 | 架构**不依赖**变量，压 `复制组 + 换 contents` |
| 4 | **图层规模会不会炸** | ⚠️ **会，必须设上限**。批量发命令 **37.5ms/层**（逐条循环 267ms/层，慢 **7.8×**）⇒ 外推 2000 层 ≈ **75s**（批量）/ 535s（循环） | 可行但有边界 | 一次生成**设行数上限**；命令**批量发**；超限给可操作提示（不静默截断） |
| 5 | **CSV 从哪来、怎么读** | ✅ 文件选择器 API 有；utf-8 / BOM CSV **逐字无损**；🔴 **`TextDecoder` 在 UXP 里根本不存在**，且文本模式读 GBK 文件得到 `"����,A"`（**中文被替换成 U+FFFD**） | utf-8 可行 / GBK **不可行**（除非自带解码表） | GBK 需**自带解码**或明确拒绝并给提示 |

## 二、逐条真机读数（原始）

### S31 · 矢量线条 = 矩形形状图层

描述符来源：Adobe 社区一份 **ScriptListener 录制输出**（"create a shape frame around an image"），
逐项转成 actionJSON 见 `lib/ps.js` 的 `rectShapeMakeDesc()` 顶部注释 —— **不是手拼**。
⚠️ 录制里那一项 `strokeStyleLineAlignment` 的枚举值原文没露出来，所以**刻意不写**（少一项也不猜）。

```
基准=内容图层建成（1→2）　形状写法=withStrokeStyle　kind=solidColor
bounds=40,100,360,104（须 40,100,360,104）　线内取色=#E60012 ✓
attempts=[withStrokeStyle=已执行/图层+1]
```

判据三条互相独立：**基准**（已知可用的内容图层建法）先成功 → **kind** 是 `solidColor`
（不是 `pixel`，即没有画成像素）→ **bounds 命中目标矩形 ±1px** + **线内取样色命中 ±25**。
两条候选（带 / 不带 `strokeStyle`）按序试，日志记下被接受的是哪条。

### S32 · 文字图层样式（本轮信息量最大的一条）

建层走 **Adobe 官方样例** `layer-creation-js-sample` 的框文本描述符（`char:box` + `bounds`）。

```
建层=成功　kind=text　textKey 读回 10230B
textKey 顶层键=[_obj,textKey,warp,textClickPoint,textGridding,orientation,antiAlias,
                bounds,boundingBox,textShape,textStyleRange,paragraphStyleRange,kerningRange]
textStyle 键=[…fontPostScriptName,fontName,fontStyleName,size,impliedFontSize,
              horizontalScale,verticalScale,autoLeading,tracking,baselineShift,color,
              strokeColor,baseParentStyle…]
段落样式键=[_obj,styleSheetHasParent,align,firstLineIndent,startIndent,endIndent,
            spaceBefore,spaceAfter,leadingType,directionType,…]
建层给定 24pt → 读回 24 ✓　　建层给定 #141414 → 读回 #141414 ✓　　框文本 char=box
```

**四条硬结论**：

1. `textStyle` 里**没有** `justification`，也**没有** `leading` ⇒ 这两项**不在字符样式里**
   （只有 `autoLeading` / `baselineShift`）。**对齐在段落层**：
   `paragraphStyleRange[].paragraphStyle.align`，**枚举族是 `alignmentType`**，默认 `left`。
   （这条是"先读回来钉死命令形状"的价值 —— 第一版我按 `justification` 找，两次都没找到。）
2. **DOM `layer.textItem` 只接了 `contents`**：`fontSize / font / justification / leading / tracking`
   读回全是 `undefined`。对照项 `__vellumNotARealThing` 也是 `undefined`（读数可信）。
   ⇒ **字体/字号/对齐/行距不能指望 DOM，必须走 AM。**
3. **AM 改样式可用且读回验证过**：`set` → `to:{textStyle, size/color}` ⇒ 40pt 读回 40、
   `#E60012` 读回 `#E60012`（模板是 v0.2.4 已验证过的文字改色描述符，只是字段可换）。
4. **对齐打通了，但要挑对写法**（两条候选都读回验证）：
   - A·把读回来的**整份 textKey 改一个字段再写回** ⇒ ✗ **命令不报错、值也没变**（最难查的那类）
   - B·`set` `_property:"paragraphStyle"` + `{paragraphStyle:{align:{alignmentType:"center"}}}` ⇒ **✓ 读回 center**
   ⇒ 事后改任何文字样式，**认准 `_property` 那一套**（`textStyle` / `paragraphStyle`），
     别拿整份 `textKey` 回灌。

### S33 · 批量出稿（架构级）

```
① {"doc.dataSets":"undefined","doc.variables":"undefined","doc.layerComps":"object",
    "app.variables":"undefined","对照·__vellumNotARealThing":"undefined"}
② 建组=true　组内两个文字层=true（递归计数 1→4，须 +3）　选中组=✓　复制组=✓（图层 2→3）
   逐组换文字=✓　副本改了=true　原件未变=true
   [cells 稿件 1 拷贝:旧值-B｜稿件 1 拷贝:新值-A｜稿件 1:旧值-B｜稿件 1:旧值-A]
```

- **`dataSets` / `variables` 读不到**（对照项同样读不到 ⇒ 只能说"没暴露"，不猜"有没有别的入口"）。
- 意外收获：**`doc.layerComps` 是对象**（图层复合**存在**）—— M3 若要做"一份文件里存多个稿件变体"，
  这是一条比变量更接地气的候选，**待单独立项验证**（本轮没测它能不能写）。
- **替代路径成立**：`建组 → 组内建文字层 → 选中组（`doc.activeLayers = [group]` 可赋值）→ 复制`
  ⇒ 副本组文字改成 `新值-A` **而原组仍是 `旧值-A`**。这两条读数一起才叫"逐组换文字"。

### S34 · 图层规模与发命令方式

```
N=15　A·逐条循环：+15 层　267~304ms/层（两轮）
      B·一次 batchPlay：+15 层　37.4~37.5ms/层
    外推 2000 层 ≈ A 535~609s / B 75~82s（**外推不是实测**，只用来定上限策略）
```

- 逐条循环慢，是因为**每条描述符都进一次 `executeAsModal`**（模态进出本身是大头）。
  ⇒ **实现一律把描述符攒成数组一次性 `batchPlay`**。
- 没有真建 2000 层（那是拿用户机器做压力测试）⇒ 上限用**实测单层成本外推**来定。

### S35 · CSV 输入侧

```
getFileForOpening=有（⚠️ 真弹窗自检点不了，这一半**没测**）
①基准·GBK 字节二进制往返=逐字节相同(d6 d0 ce c4 2c 41)
②文本模式读同一文件="����,A"　⇒ 中文 CSV **不能靠宿主解码**
③TextDecoder 位置={"global":"undefined","window":"undefined","globalThis":"undefined",
                  "对照·__notARealDecoder":"undefined"}
④utf-8 CSV 往返=逐字相同
```

- **基准**：先用 `write(Uint8Array)` 把 GBK 字节落盘，再 `read({format:binary})` 读回**逐字节比对**
  —— 基准成立，后面的解码读数才可信（不成立就记"无结论"，不记"不可行"）。
- **决定性实验**：同一个文件用**文本模式** `read()` 读 ⇒ `"����,A"`。
  四个 GBK 字节全部变成替换字符 ⇒ **宿主文本读是 UTF-8 语义 + 有损降级**。
- ⇒ **能读的**：UTF-8 / UTF-8 with BOM（往返逐字相同，含字段内逗号、字段内换行、BOM）。
  **读不了的**：GBK / GB18030，因为平台**没有 `TextDecoder`** 可换编码。

## 三、探针自己的两处自我更正（方法学，值得留档）

1. **`undefined` 往返假阳性**：第一版用"把读回来的值再写回去"验 DOM 可写性，
   而 `fontSize` 等属性**读回来就是 `undefined`** ⇒ `undefined === undefined` 一路"通过"，
   等于什么都没验。修法两条：**原值读不到就不试**；**读回 `undefined` 一律判失败**。
   （"读到自己设的输入"的又一个变体。）
2. **组内图层计数口径错**：判"组里建了两个文字层"时用的是 `doc.layers.length`（**顶层**），
   而组内图层不占顶层 ⇒ 读数写着 `false`，其实两层都建出来了（`cells` 列表就是反证）。
   改成**递归计数**。⇒ **判据的分母必须是"我数的那个集合"**，别拿一个近似的数凑。

## 四、拟采用的架构（待确认）

### M3a · 生成一张表格（核心）

输入 CSV → 面板预览 → 在**当前文档**插入一个图层组「表格 · <文件名>」：

| 内容 | 图层 | 数量（R 行 C 列） |
|---|---|---|
| 外框 | 1 个矩形形状图层（`fillEnabled:false` + `strokeEnabled:true`） | 1 |
| 内部横线 | 每条一个细矩形形状图层 | R−1 |
| 内部竖线 | 每条一个细矩形形状图层 | C−1 |
| 单元格文字 | 每格一个**框文本**文字层（`char:box` + `bounds`=单元格） | R×C |

- 全部 `kind ∈ {solidColor, text}` ⇒ **没有任何像素图层**，**"可继续编辑"是结构上保证的**（不是承诺）。
- 表头单独一个子组（便于整组换样式）。
- 排版参数：起点、列宽（等宽 / 按内容宽度）、行高、字号、字色、线宽、线色、是否画外框。

### M3b · 按行批量出稿

- **一份稿件 = 一个图层组**；模板来自「M3a 生成的表头+首行」或**用户自己搭的模板**（图层名 = 列名）。
- 生成 N 份 = **复制组 + 逐组换文字**（S33 已验证）→ 每份整体偏移排开。
- 面板上把「CSV 列 ↔ 图层名」列成绑定表（因为每格本来就是独立文字层，绑定就是**列名 → 图层名**）。

### 上限策略（依据 S34 实测）

- **一次生成的文字层数上限 60**（≈6×10），线层另计；预计耗时 ≈2.5s。
- 超出时**不静默截断**：面板上写明"将生成前 N 行，剩余 M 行可点『继续生成』"，分批发。
- 批量出稿按**每批 10 份**追加（单份层数不可控，只能按份数控）。

## 七、待定项（需要你拍板）

1. **GBK 中文 CSV 支不支持**（S35 证明平台没有解码器）：
   - (a) 先只支持 UTF-8，检测到非 UTF-8 就给**可操作提示**「请用 Excel『另存为 → CSV UTF-8』」；
   - (b) 内嵌 GB18030 映射表（约 2 万项，源码 ~100KB，ccx 会明显变大）；
   - (c) 折中：只内嵌**常用字**表（覆盖会漏字，**漏字比明确拒绝更难查**）。
2. **批量出稿的模板从哪来**：用我们生成的表格当模板，还是**用户自己在 PS 里搭模板**（图层名=列名）？
3. **文字对齐默认策略**：一律左对齐，还是按列猜（数字右对齐、表头居中）？

**未测/未定（如实标注）**：

- 文件选择器的**真弹窗**没测（自检点不了）—— 开工后第一次手动点一次即可确认。
- **行距**：`paragraphStyle` 里有 `leadingType` / `autoLeadingPercentage`，`textStyle` 里有 `autoLeading`
  —— **字段已定位，但"怎么设"还没验**（同法：读回来改一个字段，用 `_property` 那条路）。
- **形状图层能不能带多条子路径**（一个图层画多条线，层数可再降）—— 未测；
  当前按"每线一层"设计（层数 = R+C+1）。
- `layerComps` 能不能写（"一份文件多个稿件变体"的另一条路）—— 未测。
