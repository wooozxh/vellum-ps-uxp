## 一、M2 地基实测（2026-10-10，自检 S19）—— 本节是硬事实，不是设计

`docs/10` §10.5 把路线 ②（镜像单写）押在一个**尚未单独实测**的环上：
「插件用 UXP storage 读自身 PluginData 的图片文件并渲染」。本次把它验掉了。

### 1.1 做法

在插件 PluginData 下造一份**假镜像**（真数据来自 `D:\vellum_workspace\_thumbs` 的
真实 webp + 一个手写 `manifest.json`），让插件读它、渲染它：

```
PluginData/library/
├── manifest.json          手写，按 §10.7 契约（1 个项目 / 1 个任务包 / V1 / 2 个文件 + 通用库 1 项）
└── thumb/
    ├── f1.webp            真实缩略图（VP8X 带 alpha，155×320，4814 B）
    ├── f2.webp            真实缩略图（VP8 有损无 alpha，78×160，2494 B）
    ├── f3.webp            同上
    ├── p1.png             手造基准（64×48，124 B）
    └── p2.jpg             PS 导出（64×48，11299 B）
```

### 1.2 结果

| 判据 | 读数 | 结论 |
|---|---|---|
| 清单读得出 + `JSON.parse` | 项目文件 2 条 / 品牌 1 条 | ✅ `readTextIn` 逐级进子目录可用 |
| 二进制字节数一致 | `4814B` 与磁盘一致 | ✅ |
| **文件头魔数** | `"RIFF"` | ✅ **拿到的是真二进制**（不传 `format` 会按文本解码） |
| 渲染 `webp-alpha`（VP8X 带 alpha） | dataURL ✗ / blobURL ✗ | ❌ |
| 渲染 `webp-plain`（VP8 有损无 alpha） | dataURL ✗ / blobURL ✗ | ❌ |
| 渲染 `png` | dataURL **64×48 ✓** / blobURL **64×48 ✓** | ✅ |
| 渲染 `jpg` | dataURL **64×48 ✓** / blobURL **64×48 ✓** | ✅ |

渲染判据是 `img.naturalWidth` 等于**预期尺寸**（不是只比 `> 0`），
容器是 `position:fixed; right:0; bottom:0; opacity:1` 的**真可见**容器
（`§10.2` 的坑：`display:none` 里 UXP 不加载图片，表现为超时）。

### 1.3 结论（三条，都要记住）

1. ✅ **「读自身 PluginData 的文件」成立** —— `getDataFolder()` → `getEntry` 逐级进子目录
   → `read({format: formats.binary})` → `ArrayBuffer`。**这是路线 ② 的地基，它站得住。**
2. ✅ **`ArrayBuffer → data URL` 与 `→ Blob → objectURL` 两条渲染路都通**（用 PNG/JPEG 验证）。
3. 🔴 **UXP 的 `<img>` 不解码 webp** —— **两种编码变体、两条 URL 路，全失败**；
   同一个容器里 PNG / JPEG 立刻成功。⇒ **这是平台约束，不是用法问题。**

> ⚠️ **首版探针我差点误判两次，记下来**：
> ① 第一版容器用了 `opacity:0.02`，webp 与 png **都没测**（当时只测了 webp）→
>    「渲染失败」既可能是格式也可能是可见度，**单变量实验不成立**；
> ② 第二版才补上 **PNG 基准**，把两个变量分开 —— 才发现 **png 是成功的**，
>    于是"容器不透明"被排除，只剩格式。
> ⇒ **教训：多嫌疑并存时，先造一个"必定成功"的基准把变量分开**，
>    否则会把平台约束误判成自己的 bug（或反之）。

## 二、路线确认与**一处必须修正**

- **路线：② 镜像单写**（`docs/10` §10.5 已拍板；③ 本地服务正式放弃）。
  即：**VellumDesk 写进插件的 PluginData，插件只读自己的目录** ——
  绕开「插件能否读 D 盘工作区」这个未知数（`file://` 已被实测拒绝）。
- 🔴 **必须修正「缩略图直接复用 `_thumbs`（webp）」这条**（`docs/10` §10.6 第 2 点）：
  因为 webp 在 UXP 里**渲染不出来**。修正后的做法：

  | 项 | 原设计 | 修正后 |
  |---|---|---|
  | 缩略图来源 | 直接复用 `_thumbs/*.webp` | 复用**像素**，但写镜像时**转码成 png 或 jpg** |
  | `_thumbs` 本身 | —— | **不要动**。它是 VellumDesk 自用的缓存（它自己渲染支持 webp） |

  ⇒ **`_thumbs` 保持原样**，只在**写镜像那一步**转码。这样两边的需求都不被破坏。

  **格式选择建议**：

  | 情形 | 建议 | 理由 |
  |---|---|---|
  | 缩略图**带透明**（实测 f1 就是 VP8X 带 alpha） | **PNG** | JPEG 不支持透明，会变成黑/白底 |
  | 缩略图**无透明**（照片类） | **JPEG**（q≈80） | 体积小得多；PNG 对照片类会膨胀数倍 |

  ⚠️ 是否值得按「有无 alpha」分派，取决于 VellumDesk 侧用 sharp 判 `hasAlpha` 的成本 —— 留作对方决策。

- ⚠️ **体积预算要重算**：`docs/10` §10.6 的「3000 个素材 / 23.4 MB / 首次约 2 s」
  **是基于 webp 平均 4.2 KB/张**。换成 PNG/JPEG 后单价上升
  （经验值：320px PNG 照片类约 100~250 KB；JPEG q80 约 15~40 KB）——
  **具体量级需用真实库实测**，不要直接沿用旧表。

## 五、需要 VellumDesk 侧配合的事（**另一个项目，须单独立方案**）

> `docs/10` §10 开头就写明：VellumDesk **没有对外接口**（全库 grep 无 `createServer` /
> WebSocket / `.listen(`），renderer↔main 走 IPC ⇒ **联动不可能只改插件一侧**。

1. **写镜像**：把清单 + 缩略图写进插件的 PluginData（`library/`）。
2. **缩略图转码**：写镜像时把 webp 转成 **png / jpg**（`_thumbs` 本身不动）。
3. **动态定位 PluginData 路径**：路径含 PS 大版本号（`PHSP\27\`）——
   插件侧已有正则小抄（§10.5 末）。
4. **变更通知**：监视素材变更 → 重写 `manifest.json` + 增量写缩略图（插件侧轮询 `stat` 一个文件）。
5. 🔴 **响应取图请求（v0.2.7 起升级为"必做"）**：监听 `library/handoff/req.json` 的变化
   → 按 `assetId` 反查 `absPath` → 拷原图到 `handoff/incoming.<ext>`（固定名，覆盖）
   → 写 `handoff/res.json`（**`reqId` 必须原样回填**）。
   插件侧已把这一半验通了；**没有这一步，"置入"在插件里就永远是"取原图超时"**
   （因为直连 `absPath` 被 UXP 平台挡死，见 docs/23 §二）。

## 六、未决 / 未自证（如实标注）

- ⏳ **PNG / JPEG 的真实体积量级**未实测（本机工作区里没有现成 jpg，p2.jpg 是 PS 导的纯色，
  不具代表性）。报告里的「100~250 KB / 15~40 KB」是经验值，**不要当结论引用**。
- ⏳ **base64 vs blobURL 的性能差异**未测（两者本次都成功，功能等价；体积上 blobURL 更省）。
- ⏳ **大量缩略图的滚动性能**未测（3000 张怎么进网格、要不要虚拟滚动）。
- ⏳ **「插入」端到端**整条链未跑完（含 PSD→智能对象）：插件侧已通到"Entry → 令牌 → place"，
  但**真正走一次 `req.json → res.json → incoming`** 要等软件侧实现（自检 S21 用的是我们自己沙箱里的图）。
- ⏳ **`getEntryWithUrl`（直读沙箱外路径）无结论**：连沙箱内基准都失败，分不清权限边界还是用法不对
  （契约 §9.1 第 10 条）。**不许**据此下"沙箱外不可读"的结论。
- ⏳ `dblclick` 置入未验；`object-fit` 是否真生效（图能显示，但有没变形没看）。
- ⏳ 窄面板（`manifest.minimumSize.width=260`）下的换行/字号未验。
- ⏳ 中文/长文件名、超宽超高的极端缩略图未测。
- ⏳ 本次探针跑的**假镜像**留在 PluginData 里（不进 git），供 M2 开发期继续用。
