## 一、做了什么

`tools/library.js`（新，约 700 行）+ `index.html` 的 `.lib-*` 样式 + `lib/handoff.js`（新）+ `lib/ps.js` 的置入能力。

### 1. 界面（`tools/library.js`）

| 区域 | 做法 |
|---|---|
| **库切换** | chips **由 `manifest.scopes[]` 动态生成** —— 不是写死"任务库/通用库"两个 tab。软件侧将来加第三个库（如"云端库"），插件**零改动**就能显示 |
| **分组筛选** | 通用库是「公司素材 / 我的收藏」，任务库是项目名；**只有一组时不显示筛选**（那是噪音，改成一行总计数） |
| **网格** | 3 列 `flex-wrap` + 百分比宽度。每格：缩略图（`object-fit:contain`）、右上角扩展名、左下角"原文件丢失"红标、文件名、尺寸·角色 |
| **选中详情** | 位置面包屑 / 尺寸 / 体积 / 角色 / 修改时间 / 标签 / **原图绝对路径** + 「置入到画布」 |
| **刷新** | 手动按钮 + **每 3 秒对一次 `scopes[].revision`**（契约 §一）；变了才重读，并提示"已更新" |
| **降级** | 镜像不存在 / 契约版本不认识 / 单库读取失败 / 渲染异常 —— 四条分支全都给**可读文案 + 重试**，不白屏 |

**记住"上次看的是哪个库"**（`library-pref.json`，写在 PluginData 根，**不是**镜像目录 —— 契约 §八 写者唯一性）。

### 2. 缩略图：顺序读 + 令牌作废

- `lib/mirror.js` 的 `thumbUrl()` 走 **`ArrayBuffer → Blob → objectURL`**（比 base64 省 33%）。
- **顺序读，不并发**：一屏几十张同时读会把面板拖住。
- **令牌作废**：`loadToken` 每次重渲染 / 切库 / 卸载都 +1，在途的加载任务立刻停手 —— 否则它会去写已经被移除的 `<img>`。
- 失败不留空：`无预览` / `格式不支持`（webp）/ `预览失败` 三种占位（契约 §5.5：缺失也要画占位格）。

## 二、🔴 本轮最重要的结论：`placeEvent` **不接受裸路径**

### 我原本的设计

两条策略，第一条是"省掉整条搬运"：

> ① 把 `asset.absPath` 直接交给 PS 的 `placeEvent`。UXP 沙箱读不了用户的盘，
> 但 `batchPlay` 是在 **PS 进程里**执行的，`_path` 由 PS 自己解析 —— 成功就一步到位。

**真机把它打掉了**（S21 第一版，21:32）：

```
临时文档 id=245　测试文件=401.png　图层数 1 → undefined　changed=undefined
via=placeEvent　err=Error: invalid file token used
```

⇒ **Photoshop 的 AM 层要的不是路径，而是 UXP 授权过的「文件令牌」。**

### 正路（已实测可用）

```
沙箱内 Entry ──createSessionToken()──► 令牌 ──► placeEvent 的 _path: "<token>"
```

真机 S21（21:37 / 21:39 两次一致）：

```
令牌=session-token/20…　测试文件=401.png（沙箱内 Entry）　临时文档 id=263
图层数 1 → 2　changed=true　新图层=「401」
```

描述符本身**照抄** `@alisaitteke/photoshop-mcp` 的工作实现（`dist/api/extendscript.js` 的 `placeImage()`，
ExtendScript 的 `executeAction(cTID('Plc '), …)` 逐句翻成 ActionJSON）—— 唯一改动是把 `_path` 的值从路径换成令牌。

### 这条结论对架构意味着什么

| 想置入的文件 | 能否拿到 Entry | 结论 |
|---|---|---|
| 插件自己 PluginData 里的（`handoff/incoming.<ext>`） | ✅ | 可以置入 |
| 用户经**文件选择器**授权的 | ✅ | 可以置入 |
| **用户工作区的 `absPath`**（`D:\vellum_workspace\…`） | ❌ | **置入不了** |

⇒ **契约 §六 的 handoff 搬运从"设计选择"升级为"平台约束"。** 软件侧必须实现"监听 `req.json` → 拷原图 → 写 `res.json`"这一步，
**它不是可选优化**。反过来说 —— 契约把原图送进 `handoff/`（= 我们的沙箱内）这个决定，
**理由比它自己写的更硬**（它原本的理由只是 §3.2「插件读不了用户的盘」）。

已写进契约：**§9.1 第 9 条** + **§六 的「前置待实测」** + **§2.3 进度表**；并在 `LINK-LOG.md` 发了三条 `[插件侧]` 公告。

### 于是 `tools/library.js` 现在只有一条路

`写 req.json → 等 reqId 匹配的 res.json → 拿 `incoming.<ext>` 的 Entry → 令牌 → place`，
每一步失败都在**面板状态行**上说清原因，例如：

```
✗ 取原图失败：等 10000ms 没等到匹配的 res（reqId=r-20261010T213123-b255）　—— 确认 VellumDesk 在运行、且已开启插件联动
✗ 原图已就位但拿不到可置入的文件句柄：…
```

## 三、S22：一个**主动标为"无结论"**的探针

我顺手问了一个更有野心的问题：**能不能直接读到沙箱外的文件**（那样连搬运都能省）。
做法是同一套 API 打两个 URL，**用沙箱内路径当"必定成功"的基准**：

```
基准·沙箱内 401.png = 未拿到（Could not find an entry of 'file:///C:/…/PluginData/library/thumb/401.png'）
沙箱外 PROGRESS.md  = 未拿到（Could not find an entry of 'file:///D:/ps-uxp-dev/PROGRESS.md'）
⇒ ⚠️ 本实验无结论：连沙箱内基准都没拿到 entry ⇒ 分不清是权限边界还是用法不对
```

**首版我把这条结论写成了「沙箱外不可读 ⇒ 直连置入不可行」—— 那是错的**，因为基准也失败了。
（这就是本项目第五次踩的同一类坑：**没有基准的失败实验 = 没做实验**。S19 那次也是补了 PNG 基准才把变量分开。）

改法：把结论**分成三档**（基准失败 = 无结论 / 基准成功+沙箱外成功 = 可行 / 基准成功+沙箱外失败 = 不可行），
并在契约 §9.1 第 10 条如实记为"待查"，**没有**据此改架构。

待查方向：URL 是否要编码、是否需 manifest 声明 `requiredPermissions.localFileSystem`
（当前 `requiredPermissions` 是空的 —— 那等于只给"插件自己的目录"这一档权限）。

## 四、顺带修掉的真缺陷：`log.js` 并发写互相覆盖

真机日志里出现了**被拦腰截断的行**：

```
task:87|brand:3 thread=vellum-link/1
```

（完整的那行 `library mount ok=true tab=task items=2 scopes=…` 整个消失了。）

根因：`appendLog` 是"读全文 → 拼一行 → 写回"，多条并发时读改写互相覆盖。
**自检本身就是并发写日志的**（多项交替），所以这不是理论问题 —— 它已经让我在排查时**看丢过一条关键记录**。

修法两条：① 内存缓存最新全文（省掉每次读盘）；② 所有 `appendLog` 排进**同一条 Promise 链**。

> 这条值得单独记一笔，因为它印证了一个更普遍的纪律：**反馈通道本身也要能被信任。**
> 一个会丢行的日志，会把"没发生"和"发生了但没记下"混成同一个现象。

## 五、另一个自己坑自己：S20b 量到了**上一个库**的数据

第一版 S20b 的等待条件是"网格里有东西"：

```js
const g2 = await waitFor(() => {
  const el = document.getElementById("vt-lib-grid");
  return el && el.children.length > 0 ? el : null;   // ← 旧网格还在 DOM 里，第一轮就命中
}, 5000, 200);
```

于是切到通用库却量到 **2 张**（= 任务库的张数）。**判据必须等"新的库渲染完"**：

```js
if (!onChip.classList.contains("is-on")) return null;
if (!el || el.children.length !== expect2) return null;
```

改完 PASS：`切到 task → 卡片=2（自数期望 2）`。

**同时也是"期望值要独立算"的一个例子**：S20 的期望值**全部从原始 JSON 自己数**
（递归找 `{id:number, name:string, ext:string}` 形状的对象），**不复用 `mirror.js` 的展平结果** ——
否则就是"拿自己的输出验自己"。

## 七、未自证（诚实清单）

1. **端到端置入没跑完** —— 只验到"插件侧链路通"（S21 用的是我们自己沙箱里的 Entry）。
   真正走一次 `req.json → res.json → incoming` 需要**软件侧**实现后配合。
2. **双击置入**（`dblclick`）没验 —— UXP 是否派发这个事件类型不确定；单击路径已验。
3. **`object-fit: contain`** 在真机是否生效没单独验（图片会"显示出来"已验证，但**是否变形**没看）。
4. **滚动下的 `watch` 行为**没验：刷新时会不会把滚动位置弹回顶部（不是不行，是没量）。
5. **镜像真的变了**（revision 递增）时的自动刷新没验 —— 只验了首次加载与手动刷新；
   `tools/fake-vellumdesk.cjs --task-rev 88` 就是为此准备的。
6. **字号/换行**在窄面板（`minimumSize.width=260`）下的表现没验。
7. 品牌 HEX 仍是占位色（唯一硬阻塞，只改 `tools/palette.js` 的 `DEFAULT_BRAND`）。
