### ★ 三条要记住的结论

**① `resizeCanvas` 的锚点：字符串没用，枚举值才行**

```
✗ resizeCanvas(w, h, "topCenter")   → 静默忽略 ⇒ 新空间上下各半（原设计踩的就是这个）
✅ resizeCanvas(w, h, constants.AnchorPosition.TOPCENTER) → 原内容贴顶、新空间全在底部
```

语义**用像素验过**（不是推断）：`TOP*` = 原内容贴顶（新空间在**下**）；
`BOTTOM*` 反向（新空间在**上**）；`MIDDLE*` = 上下各半。

**② 导出必须 `asCopy`**

```
saveAs.png(entry)           → 文档名 未标题-12 → review-probe-r8-B2.png  🔴
saveAs.png(entry, {}, true) → 名字/路径都不变                              ✅
```
不带 asCopy 的话，同事交付时**文件名已被插件改掉**，而这是**文件级属性，历史回退救不回来**。

**③ 参数条字体：v1 只能用 PS 的默认中文字体**

建层带 `fontName`、`set textStyle{fontName}`、读回 `textKey` 改字段再整份写回、
再加 `fontPostScriptName` / `fontStyleName` —— **四条路全无效**，
像素证明 12 张图渲染成**同一个字体**（本机为 `Adobe Heiti Std`）。
⇒ v1 用默认字体（**一定能出中文、不会方框**），代价是**不同机器可能不一样**。
要真正控住字体必须**录制动作**（你在 PS 里用文字工具改一次字体 → 动作面板「复制为 JavaScript」），
**这一步我做不了，得你来**。

## 三、设计（按实测修正）

### 3.0 与原设计的差异（三处修正）

| 原设计（docs/49 §3.2） | 实测后**改为** | 依据 |
|---|---|---|
| `resizeCanvas(宽, 高+条高, 向下锚点)` | `resizeCanvas(w, h, constants.AnchorPosition.TOPCENTER)` | R7 / R11 |
| 「铺白底」说得像个独立步骤 | **新区域=背景色**；所以要先**临时**把背景色设成白，**用完还原** | R4 / R10 |
| 参数条字体"建议用最保险的系统字体" | **v1 干脆不指定**，用默认中文字体；指定字体另开一轮（需录制） | R13–R16 |
| （原设计未提） | 导出**必须** `asCopy` | R8 |

### 3.1 主路（✅ 已选定，本轮实现这条）

```
点「导出审核版」
   ↓
跑一遍 docInspect()                     ← 参数条全部字段的来源（与状态条同一份）
   ↓
出血能推断出来？ ──是→ 直接用，不弹窗
   │否
   ↓ 弹窗（★ 先弹窗，用户答完，再进模态）
   出血： ( ) 无出血   (•) 有出血 [3] mm   ( ) 不确定
   ↓
【模态 A】① const mark = doc.activeHistoryState      ← 记标记（对象引用）
   ↓
【模态 B】② 读背景色 → 设成纯白（**记下原值**）
         ③ resizeCanvas(W, H + 条高, constants.AnchorPosition.TOPCENTER)
         ④ 建参数文字层（内容来自 docInspect；字体用默认）
         ⑤ 导出（saveAs.png(entry, {}, true) ← asCopy）
         ⑥ 还原背景色
   ↓
【模态 C】⑦ doc.activeHistoryState = mark            ← 一步还原
         ⑧ 读回 self-证：画布尺寸 / 图层数 / 背景色 都要回到原位
```

**顺序硬要求（照抄 docs/49 §3.2 并加强）**
- **先弹窗 → 用户答完 → 再进 `executeAsModal`**。反了会让用户在 PS 被锁住的状态下思考甚至卡死。
- **`set` 类 batchPlay 必须进模态**（R4 实测：`get` 不进也行，`set` 不进直接报错）。
  ⚠️ "读能跑"**不能**推断"写能跑"。
- 步骤 ⑧ 不是可选的：本项目铁律 **没报错 ≠ 生效**，还原必须**读回自证**
  （R6 验的正是这件事：画布尺寸 + 图层数一起回）。

**为什么敢"改用户的稿"**：R6 已实测「扩画布 + 新增图层」能用**同一个对象引用**一步回到原位。
风险仍然存在（若还原失败），所以必须 ⑧ 读回自证；还原失败就**明确告诉用户按 Ctrl+Z**，不装作没事。

### 3.2 备路：新建高稿 + 跨文档复制图层（**完全不动原稿**）

```
① 新建 (W, H+条高) 空稿（presetJSON 里 fill:"white" ⇒ 自带白底）
② 把原稿的图层跨文档复制过来（duplicateLayers；R12 已实测）
③ 建参数文字层 + 导出
④ 关掉这张临时稿（**原稿自始至终只被读**）
```

R12 像素实测：内容落在 **y0–299**、白条落在 **y300–359** —— 正是要的布局。
**优点**：绝对不碰用户的稿；**缺点**：原稿图层多/含智能对象时，复制可能慢或失真，
而审核版其实只需要**一张扁平的图**。

⇒ **已定（2026-10-16，§六 ①）**：本轮**只做主路**。备路作为"主路还原失败时的兜底"
或"用户明确勾选『不要动我的稿』时的选项"留档，**本轮不接进 UI**。

### 3.3 参数条布局（沿用 docs/49 §3.2 的图）

```
┌──────────────────────────────────────────┐
│              图片区（干净）               │
├──────────────────────────────────────────┤
│ 品牌主视觉_v3.psd    色彩模式 CMYK          │
│ 导出 2026-10-13      分辨率   300 dpi      │
│                      物理尺寸 21.0×29.7cm  │
│                      出血     含 3 mm      │
│                      配置文件 Japan Color  │
│                      依据     规范 v1      │   [审核用·非成品]
│ ⚠ 未转曲文字层 3 个 · 缺失字体 1 个          │
└──────────────────────────────────────────┘
```

- **条高按图宽比例**：✅ **已定 = `round(图宽 × 0.08)`，下限 72 px**
  （用户 2026-10-16 从三档样张里选定 8% 那一档；字号/行高/留白的派生公式见 §六 ④）。
  太小字挤、太大喧宾夺主；下限 72 px 是给窄稿（图宽 900 px 以下）兜底的。
- 字段来源全部是 `docInspect().findings`（`key → value`），**不再另算**。

### 3.4 出血三态弹窗

沿用 docs/49 §3.2。补一条实测依据：**出血量无法从文档反查**
（探针 C2 缺口：`doc.guides[i]` 只回 `{_id,_docId}`），所以"推断"只能来自
**建稿模板定义**（第 5 步才做）或**用户回答**。"无法判断"必须是独立结论，不许猜。

### 3.5 「依据」标注：复用 inspect 已有的 spec 常量（本轮已拍板）

你选的"先写死一个本地常量" —— **连新造的都不需要**：`lib/inspect.js` 里**已经有**：

```js
const DEFAULT_SPEC = {
  specName: "Vellum 出图规范",
  specVersion: 1,
  effectiveFrom: "2026-10-12",
  usage: "print",
  ...
};
```

参数条直接读它 ⇒ 第 5 步做 `spec.json` 时**只需把 `DEFAULT_SPEC` 换成"读文件"**，参数条**零改动**。

> ⚠️ **一处对不上要你定**：docs/49 §一 B 里写的示例是「规范 **v3**」，
> 而代码里的 `specVersion` 是 **1**。二者必有一个要改（§六 2）。

### 3.6 字体限制的后果（如实写明）

- 参数条中文**一定能显示**（PS 会用默认中文字体兜底，实测无方框）。
- 但**不同同事机器上的字体可能不同** ⇒ 参数条**字形**不统一。
  对"审核用"这个用途，**可接受**（它本来就不是成品图）。
- 🔴 **连带影响（重要）**：**M3a「生成表格」也走同一条 `fontName` 路径**
  （`lib/ps.js` 的 `textLayerBoxDesc`）⇒ **表格里的字体从来没生效过**，一直是默认中文字体。
  这不是本步引入的问题，但**本步才验实**，要记进 DECISIONS。

### 🔴 三条只有真机样张才能抓到的缺陷（详见 DECISIONS 同日三条）

1. **`\n` 不换行** ⇒ 三行被拼成一行并溢出裁切。**正解：用 `\r` 作段落分隔**；
   判据改成**读回 `textItem.contents` 数段落**。
2. **角标用"整宽 + 段落右对齐"会被排到画布外**（读回外框 `x=6403..6548`，画布宽 1600）。
   **正解：不用对齐枚举**，改成"右端一个只有角标那么宽的盒子、默认左对齐"。
3. **正文盒子必须给角标留宽**，否则红角标压在正文上。

### ★ 两处对 §三/§六 的修正（已回写到正文）

- **字号必须按 ppi 由像素换成点**（`pt = px × 72 / ppi`）——
  否则 300dpi 稿上 20pt = 83px，参数条会大得离谱。代表稿实测 **4.79pt**。
- **8% 是基准不是上限**：放不下时按实际行数加高（窄稿实测 72 → 84px）。
