> 会话：2026-10-10（第 14 次）

> 结论：**v0.2.4 已实现文字图层改色**；真机自检 **18/19**（新增 **S18 PASS**）、离线结构回归 **25/25**

## §一 先看现场：不是"失败"，是**我们主动拒绝的**

用户那几次点击在 `boot.log` 里长这样：

```

          after=#1F1A1A before=#FEF8F8  attempts=[contentColorA=已执行/像素有变化]   ← 成功
20:25:31  layer="1234" family=text kind=text path=-
```

**"填充不能用"这条已经修好了**（v0.2.3 按 `kind` 分派），剩下的文字图层是
**当时明确做了前置拒绝**（因为那会儿没找到可用的描述符）。

## §二 形状图层"突然能用了"？—— 其实一直是 `contentColorA`

这里有个容易混淆的地方值得写清楚：**S17 一直 FAIL，但用户的真形状图层一直是好的。**

| | **形状图层**（「矩形 1」，用户手画的） | **纯色填充图层**（S17 用 `make contentLayer` 程序造的） |
|---|---|---|
| UXP `kind` | `solidColor` | `solidColor` |
| `family` | `content` | `content` |
| `contentColorA` | ✅ **像素有变化**（真机确认） | ❌ 已执行 / 像素无变化 |
| `contentColorB` | —（A 已命中，不会走到 B） | ❌ 已执行 / 像素无变化 |

⇒ **同为 `solidColor`，这两个子类型的 AM 结构并不一样。**
S17 建的是「纯色填充图层」，**它不是形状图层**。所以：

- 用户的报告「形状图层可以了」**与** S17 的 FAIL **不矛盾**，两者说的是不同的东西；
- 这次我顺手把 S17 的标题改成带 `⚠️ 已知限制` 的措辞，避免以后再被读成"回归"。

## §三 文字图层为什么不能走 `fill`

**真机实测**（MCP `execute_script`，临时文档，跑完关掉不保存）：

```js
// 用 v0.2.3 那条**像素族**描述符去打文字图层
executeAction(charIDToTypeID('fill'), { using:{fillContents:color}, color:{RGBColor 230,0,18}, ... })
→ 错误: 发生了常规 Photoshop 错误。
         - 命令"<未知的>"当前不可用。
```

⇒ **PS 的「填充」对文字图层不可用**，`layer.kind` 不变（还是 `LayerKind.TEXT`）。
**当初那条前置拒绝的判断是对的** —— 它至少没让 PS 弹框。

## §四 正确描述符：**照抄官方**，我猜的两版全败

### 权威出处：Adobe 官方开发者文档

*Photoshop API v2 · Text Layer Operations*（`developer.adobe.com/firefly-services/docs/photoshop/...`）
给的 ActionJSON 原文：

```json
{ "_obj": "set",
  "_target": [
    { "_property": "textStyle", "_ref": "property" },
    { "_enum": "ordinal", "_ref": "textLayer", "_value": "targetEnum" }
  ],
  "to": {
    "_obj": "textStyle",
    "color": { "_obj": "RGBColor", "red": 255, "green": 207, "blue": 104 }
  }
}
```

### 我自己猜的两版（都"不报错、像素也不变"）

| 我猜的 | 错在哪 | 真机结果 |
|---|---|---|
| `_target:[{_ref:"textLayer",…}]` + `to:{textLayer, textStyle:{textStyle, color}}` | `_target` 少一级；颜色套错层级 | 不报错、像素无变化 |
| `_target:[{_ref:"layer",…}]` + 同上 | 同上 + 参考类也错 | 不报错、像素无变化 |

### 三个**必须照抄、不能发挥**的硬点

1. **`_target` 是两级**：第一级是 **`textStyle` 属性**（`_ref:"property"`），第二级才是 `textLayer`。
2. **颜色放在 `to.textStyle.color`**，**不是**套在 `to.textLayer.color` 里。
3. **JSX 侧调用顺序是硬的**：`putProperty` 必须**先**于 `putEnumerated` ——
   颠倒会直接报 `命令"设置"当前不可用`（这条反过来倒是好事：错得响，不像前两条那样静默）。

### 真机读数（判别性实验）

黑字打在白底 400×400 上，用**合成直方图的最低占用亮度**当判据：

```
base = [0, 255, 17]        ← 黑字，最低亮度 0
set（顺序正确） → [71, 255, 17]   ← 最低亮度 0→71 = #E60012 的亮度 ✓
set（顺序颠倒） → 报「命令"设置"当前不可用」
kind 全程 = LayerKind.TEXT        ← ★ 非破坏性，文字保持可编辑
```

**顺带修掉的一个 mock bug**：`tools/offline-smoke.cjs` 里模拟 `set` 的规则原来是
「只要带 `_property` 就写进 `colorState`」。v0.2.4 的文字命令 `_target[0]._property === "textStyle"`，
会被它当成颜色槽 → `colorState.textStyle = {...}` 污染状态。
改成**只认 `foregroundColor` / `backgroundColor`** 两个真颜色槽。

## §六 自证

### ① 真机自检 **18/19**（新增 S18）

```
2026-10-10 20:35:03  selfcheck DONE  18/19  dur=11909ms
S18 PASS :: 建层 kind=text（期望 text）　family=text（期望 text）
            命中路径=textColor
            改前=#000000 → 改后=#91000B　目标=#E60012
            改完 kind=text（期望仍是 text = 非破坏性）
            attempts=[textColor=已执行/像素有变化]
```

S18 在真机上钉三件事：`kind` 是 `text`、**像素真的变了**、**改完仍是文字图层**。

> 📌 `改后=#91000B ≠ #E60012` 是**正常**的：像素回读走 `imaging.getPixels(targetSize:1×1)`
> = **整层平均色**，而文字只占图层的一部分（含大量透明像素），平均值必然是混合色。
> 所以 S18 的判据是「**有变化**」而不是「等于目标色」—— `lib/ps.js` 的 `verify:"change"`
> 就是为这种情形设计的。

> ⚠️ 造文字图层有两个真机坑，都写进了 `makeTextLayer()` 的注释：
> ① 点文字的**锚点在基线上、字往上长** —— 300pt 的字在 400×400 画布里**完全在画布外**，
>    不 `move` 一次的话像素回读只会拿到空白，会**误报成"改色无效"**（我第一版就是这样）；
> ② 字号单位要用 `pointsUnit`。

### ② 离线结构回归 **25/25**

断言 20 现在验的是**命令形状**（这是唯一能拦住"静默失效"的办法）：

```
PASS  20 文字图层 → 发 textStyle 改色（两级 _target + 颜色在 to.textStyle 里，且不发 fill）
        命令=set　_target 级数=2　t0={"_ref":"property","_property":"textStyle"}
        t1={"_ref":"textLayer","_enum":"ordinal","_value":"targetEnum"}
        to._obj=textStyle　color._obj=RGBColor
        fill 命令 = 0 条（必须 0）
        状态栏 = "✓ 已把 「标题」 的文字颜色改为 #E60012（文字仍可编辑　未做像素校验）"
```

### ③ 语法 / JSON 检查全过，`manifest.json` version = `0.2.4`

## §七 已知限制（诚实清单，别当成"都好了"）

1. **S17 的「纯色填充图层」改色仍未解决** —— 真机两条描述符都"已执行 / 像素无变化"。
   **形状图层是正常的**（用户真机确认）。这是**已知限制，不是回归**。
2. **文字的选区语义**：文字颜色是**整层属性**，PS 不接受"只改选区内那部分字"。
   面板在有选区时会明说「未按选区裁剪」，不会假装按选区处理。
3. **只做"整层改一个色"**：层内**混排**（一段文字里不同片段不同颜色）没做 ——
   那需要走 `textStyleRange` 的 `from`/`to` 区间，属另一个功能。
4. **未测**：段落文字（vs 点文字）、多字体混排、带图层样式/变形的文字、
   **中文文字**（自检用的是字母 `M`，中文字形/字体回退没验过）。
