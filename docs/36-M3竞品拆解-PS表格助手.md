## 二、核心流程：**三步向导 + 画布上的选区拉框**

### 第 0 步（画布侧，最关键的一步交互）
> 图注原文：「用**选框工具**在界面上拉框，表示表格要绘制在这个选区内」

**用户用 PS 自带的矩形选框**在画布上拉一个虚线框 ⇒ 插件**读这个选区**当表格的**位置 + 尺寸**。
（不是让用户填坐标，也不是在面板里拖。）

### 第 1 步（面板）
- 提示：「第 1 步，请填写表格的行和列数」
- **行**：5　**列**：4
- **默认文字**：`文本`（图注：「单元格中会显示的"文本"」；V2 网页版说"**默认文本可以为空**"）
- 图注：「绘制表格需要设置三个步骤」「行和列的数字多点」（即行列可以给很多）
- 按钮：**下一步**

### 第 2 步（面板）—— 逐列设置
- **每列表头文字**（`表头1` `表头2` …，逐列可改）
- **每列宽度**：`自动` = 每列平均分配；也可逐列给 px
- **每列类型**（下拉）：`文本` / `姓名` / `性别` / `地址` / …（文章说"序号 / 姓名 / 性别 / 地址 /…"）
- 图注：「选择不同的类型，会**随机生成**不同的文字。比如选择姓名，会随机生成如：杜兰特、波波、库里、哈登；选择性别生成男/女；选择地址生成…」「**一帮随机名字，避免你手动输入**」

### 第 3 步（面板）—— 单元格与整表参数
- 展示**所有单元格**，**点某个单元格就能改它的文字**
- **表格高度**（行高）/ 表头高度
- **对齐**：居中 / 水平对齐 / 上对齐 / 左对齐…
- 图注：「可以设置选中其中某一行」「点击单元格可以改文字；也可以**绘制好之后选择文字图层后去改**」
- 按钮：**自动绘制**

### 生成结果（图注原文，最硬的一句）
> **「绘制好自动生成！所有图层均为矢量形状，文字的图层均为普通文本」**

⇒ 与我方 M3 定案（**每格一个文字图层 + 矢量线条、插入后可继续编辑**）**完全一致**，说明这个方向是对的。

## 四、对我们 M3 的直接影响

### A. 可以直接借的 8 条

1. **🔴 选区拉框当区域输入** —— 位置 + 尺寸一次给全，最符合设计师直觉。
   ⚠️ **我方尚未验证"读用户已有的选区"**：v0.3.0 的 S24 只验了「**建**选区」（`AM.setd(Chnl/fsel+Rctn)`），
   而这里是**读**一个用户手工拉出来的选区 ⇒ **必须先补一条探针**（UXP `Document.selection.bounds`）。
2. **三步向导**（行列 → 逐列 → 单元格/参数）比"一屏塞满参数"好用，**也给面板省地方**（窄面板适配的老问题）。
3. **列类型 = 随机假数据**（序号/姓名/性别/地址/手机号/日期/金额…）—— 纯数据生成，与排版解耦，
   成本低、体验提升大（设计师最痛的就是编 12 行假名字）。**可先做 4–6 种，本地词表即可。**
4. **样式三 tab（通用 / 表头 / 行）+ 保存配置 / 重置** —— 表格级 + 行级两层样式；持久化复用我方 `store.js`（palette.json 那套）。
5. **边框规则可配**（横线 / 竖线 / 都有 / 无）—— 直接决定线层数量，也是省层数的手段。
6. **外框圆角** —— 我方 `makeRectShapeLayer()` 的 `radius` 已支持四角半径 ✅（对方是"外框圆角半径"）。
7. **表头独立一层样式 + 独立图层组** —— 与我方"表头单独成组"的想法一致 ✅。
8. **前置校验要在本地判掉并说人话**（对方把"不能有合并单元格"写在教程里当注意事项）；
   我方纪律升级版：**能在本地判掉的前置条件，直接在面板上说清并给下一步动作**。

### B. 必须补进方案的 3 处（原 `docs/35` 方案漏了）

| 漏项 | 影响 |
|---|---|
| **行/表头背景色块**（含**渐变**） | 原方案只有"文字 + 线"，缺底色。每行 +1 层背景（表头 +1）；渐变要走 `gradientFill` 内容图层 |
| **填充距离（内边距 上右下左）** | 决定文字框 `bounds` 的收缩量 ⇒ 直接进布局计算（纯函数） |
| **表头高度 / 行高分别可设** | 原方案只说了"行高"，表头要能单独设 |

### C. 层数重估（对接 v0.3.8 实测的 37.5ms/层）

以 **表头 + 5 行 × 4 列** 为例（边框规则=横竖线都有）：

| 内容 | 层数 |
|---|---|
| 外框（形状层，可圆角） | 1 |
| 表头下横线 + 每行下横线 | 1 + 5 = 6 |
| 内部竖线 | 3 |
| 表头背景 + 每行背景 | 1 + 5 = 6 |
| 文字（(5+1)×4） | 24 |
| **合计** | **≈ 40 层** |

⇒ 与 `docs/35` 估的 60 层同量级；**"一次生成的文字层数上限 60"这条上限策略仍然适用**，
但**要按"总层数"而不是"文字层数"设闸**（背景/线也要算）。

### D. 我们的差异化（对方没有的）

1. **CSV 导入 + 编码处理**（对方走"手填 / 随机类型 / Excel 导入"，**没有 CSV**）；
   ⚠️ 对方网页版靠**服务端**解析 Excel，等于绕开了"UXP 没有 `TextDecoder`"这个坑 —— 我们绕不开。
2. **按行批量出稿（M3b）** —— 对方完全没有；这是我们多出来的那块。
3. **UXP 原生** ⇒ 面板/交互与 PS 同代，可继续编辑性更好（对方是 CEP，2015 时代起家）。
4. **面板内 CSV 预览**（对方是"参数在面板、结果在画布"，没有面板内预览）——
   我们数据来自文件、列多内容长，**保留预览仍有价值**，但可以只预览前 3–5 行。

### E. 一个交互上的分叉（需要你选）

| | A · 选区拉框（对方做法） | B · 落点锚（我方 v0.3.3 已有九宫格） |
|---|---|---|
| 用户操作 | 先用选框工具框一块，再调参数 | 选落点，尺寸由列宽/行高算 |
| 优点 | 位置+尺寸一次给全、最直观 | 零新能力依赖、已实现 |
| 风险 | **"读选区"未验证** | 尺寸与位置要分两次表达，不如拉框直观 |

**我的建议：A 优先、B 兜底** —— 有选区就用选区（宽度按选区、行高按参数），没选区就用落点。
代价是先补一条"读选区"探针（S36），失败则退回 B，**不会卡住整条线**。

## 五、更新后的待拍板清单（在 `docs/35` §七 三条之上）

1. **GBK 中文 CSV 支不支持**（同 `docs/35` §七-1）。
2. **区域输入走 A（选区拉框，需先验）还是 B（落点锚）**，还是 A+B。
3. **要不要做"列类型 → 随机假数据"**（序号/姓名/性别/地址…）；做的话先上哪几种、词表从哪来。
4. **样式要不要"保存配置 / 导出给他人"**（对方做得很好；我方要复用 `store.js`）。
5. **要不要支持 Excel 导入**（xlsx = zip + XML，得引解压；**成本明显高于 CSV**，且能顺带绕开 GBK 问题）。
6. 列类型/对齐的默认策略（同 `docs/35` §七-3）。
