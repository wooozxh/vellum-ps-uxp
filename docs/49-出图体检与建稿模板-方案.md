## 一、需求清单（已定案）

### A. 出图体检 · 常驻状态条

| 项     | 决定                                                                 |
| ----- | ------------------------------------------------------------------ |
| 形态    | 面板顶部**常驻显示**当前文档的体检结果 —— **不需要任何人记得去点**                            |

### B. 导出审核版 · 参数条

| 项     | 决定                                                                                      |

| 图片区   | **保持干净**（审完可直接交付）                                                                       |

## 二、先量（template-probe，真机读数）

**探针**：`template-probe/` ｜ **环境**：PS 27.2 / UXP 9.0.2 ｜ **耗时** 9.5s  
**总判定：7 通过 / 0 失败 / 1 无结论**  
**收尾**：探针自建的 8 个临时文档**全部关闭**，未碰用户已打开的稿子（报告 `cleanup` 字段可核对）。

| #      | 验的什么                               | 结果         | 关键读数 / 对设计的影响                                               |
| ------ | ---------------------------------- | ---------- | ----------------------------------------------------------- |
| C1     | `presetJSON` 基线（不带 guides）+ 体检字段形态 | ✅          | 800×600@300dpi 精确回读                                         |
| **C2** | ★ **`presetJSON` 能否携带 `guides`**   | ✅          | **传 4 条、回读 4 条** ⇒ 「建稿即写入出血线」成立                             |
| C3     | `presetJSON` + CMYK                | ✅          | `mode=CMYKColorMode`、`Japan Color 2001 Coated` 生效 ⇒ 印刷稿模板成立 |
| **C4** | ★ `activeHistoryState` 可写（整批撤销）    | ✅          | 图层数 1 → 2 → **1** ⇒ 「一次退回」成立                                |
| C5     | `duplicateLayers` 跨文档复制图层          | ✅          | B 的图层 `[背景]` → `[TP-SRC-LAYER, 背景]` ⇒ PSD 模板库成立             |
| C6     | 文字层字体名的读取路径                        | ✅          | **`textItem.characterStyle.font`**                          |

| C8     | `app.fonts` 的形态（字体缺失检测）            | ✅          | `length=583`，每项 `{_family,_name,_postScriptName,_style}`    |

### 附带发现（写代码要照这个来）

1. **体检字段的真实形态**：`doc.mode` = `"RGBColorMode"` / `"CMYKColorMode"`；  
   `doc.bitsPerChannel` = `"bitDepth8"`；`doc.colorProfileType` = `"workingSpaceCode"`；  
   `doc.colorProfileName` 是普通字符串；`doc.saved` 是布尔。
2. 🔴 **`presetJSON` 里的 `name` 字段被忽略**（传了名字，回读仍是「未标题-3」）  
   ⇒ 文档命名必须走 `createDocument` 的 `name` 参数。
3. 🔴 **C2 有一处缺口**：`doc.guides[i]` 只回 `{"_id":…,"_docId":…}`，  
   **读不到 direction / coordinate** ⇒ **无法从文档反查"出血距边缘几毫米"**。  
   ⇒ 出血量只能靠 ① 模板定义（我们自己写的，本来就知道）或 ② 弹窗问人。**这直接决定了 §三 的设计。**
4. **`app.fonts` 就是字体集合本身**，**没有 `getFontList()`**。  
   每项有 `_postScriptName` / `_family` / `_name`  
   ⇒ 字体缺失检测＝拿稿里的字体名去比对这三者。
5. **`createTextLayer` 建不出段落文字**：试了 `kind` / `type` / `paragraphText` + `width,height`  
   共 4 种写法，`textItem.isParagraphText` **恒为 false**，排版选项被**静默忽略**。
6. `textKey`（走 batchPlay 读）信息远丰富于 DOM：顶层键含  
   `bounds / boundingBox / textShape / textStyleRange / paragraphStyleRange / kerningRange / textClickPoint`。

### 🔴 探针自己的三处错判（保留痕迹）

1. 第一版 C2/C8 报 `Cannot convert a Symbol value to a string`，**差点当成"能力失败"** ——  
   实为探针 bug：**不要对 UXP 原生对象调 `Object.prototype.toString.call(x)`**（它读 `x[Symbol.toStringTag]`，  
   UXP 原生绑定访问 Symbol 键会抛）。已改为 `describeNative()`。  
   ⇒ 教训：**先分清"被测对象不行"还是"我的量法不行"。**
2. 第一版 C7 **只建了点文字就断言无结论 —— 测错了对象**（点文字没有文本框）。
3. 我一度把 C7 判成 PASS（判据"能读到两条范围读数"）—— **判据太松、属过度声称**，已改回 INCONCLUSIVE。

## 三、方案设计

### 3.0 一个数据源，三个出口

体检读到的数据只算一次，喂三个地方 —— 避免三套逻辑各写一遍然后各自跑偏  
（比如状态条说"未转曲 3 个"、参数条说"2 个"，那就完了）。

```
docInspect()  ──┬──► 面板常驻状态条
                ├──► 导出参数条
                └──► 交付规格单（后续）
```

### 3.1 出图体检（常驻状态条）

```
┌ Vellum 工具箱 ─────────────────────────────┐
│ 调色板 │ 素材库 │ 表格 │ 常用 │ …          │
├────────────────────────────────────────────┤
│ 当前文档 · 品牌主视觉_v3.psd                │
│ CMYK · 300dpi · 2480×3508px · 21.0×29.7cm  │
│ ⚠ 3 个文字层未转曲（提醒）                   │
│ ⛔ 缺字体：思源黑体 CN Medium（致命）        │
│ 出血：含 3 mm                               │
└────────────────────────────────────────────┘
```

**出血判定（四级，判不出就老实说判不出）**

```
读画布物理尺寸（像素 ÷ 分辨率 → cm/mm）
   ↓ 否
① 命中「成品尺寸 + 出血量」预设？ ──是→ 含出血 · 量已知
   ↓ 否
② 四边有贴近边缘的参考线？ ──────是→ 含出血 · 量 = 参考线距边缘
   ↓ 否
③ 命中「成品尺寸」预设（无出血）？ ─是→ 明确不含出血 → 提醒项
   ↓ 否
④ 结论：无法判断 → 提示「一键补标」，不猜
```

> ⚠️ **实测修正**：判据 ② 目前**拿不到参考线的坐标**（C2 缺口），所以 ② 暂时只能用"有没有参考线"，  
> 用不了"距边缘多少"。⇒ 出血量的可靠来源就两条：**模板定义** 或 **弹窗回答**。

**「无法判断」必须是独立结论** —— 直接对齐本项目既有纪律  
「诊断项允许'无结论'，但不许把'无结论'写成结论」。猜错比不报更危险，因为审图的人会信它。

**「一键补标」**：判不出时，插件按规范在四边拉上出血参考线。此后该稿就有了可判据。  
好处是**设计师不用记规矩，插件帮他补**。

### 3.2 导出审核版

```
点「导出审核版」
   ↓
跑一遍 docInspect()
   ↓
出血能推断出来？ ──是→ 直接用，不弹窗
   │否
   ↓ 弹窗（先弹窗，再进模态！）
   出血： ( ) 无出血   (•) 有出血 [3] mm   ( ) 不确定
   ↓ 用户答完
进入 executeAsModal：
   ① const mark = doc.activeHistoryState      ← 记标记
   ② resizeCanvas(宽, 高 + 条高, 向下锚点)      ← 扩画布
   ③ 铺白底 + 写参数文字层（中文显式传字体）      ← 加参数条
   ④ 导出
   ⑤ doc.activeHistoryState = mark             ← 一步还原
```

> ⚠️ **顺序硬要求**：**先弹窗 → 用户答完 → 再进 `executeAsModal`**。  
> 反了会让用户在 PS 被锁住的状态下思考（甚至卡死/超时）。  
> （"modal 作用域内能否弹窗"未实测，**也不必冒这个险**。）

**参数条布局**（图片区保持干净）

```
┌──────────────────────────────────────────┐
│                                          │
│              图片区（干净）               │
│                                          │
├──────────────────────────────────────────┤
│ 品牌主视觉_v3.psd    色彩模式 CMYK          │
│ 导出 2026-10-12      分辨率   300 dpi      │
│                      物理尺寸 21.0×29.7cm  │
│                      出血     含 3 mm      │
│                      配置文件 Japan Color  │
│                      依据     规范 v3      │   [审核用·非成品]
│ ⚠ 未转曲文字层 3 个 · 缺失字体 1 个          │
└──────────────────────────────────────────┘
```

**两个按钮在技术上优于"一起出"**：审核版路径是「扩画布 → 导出 → 还原」，  
**一次导出配一次还原**；若一个按钮同时出两份，反而要"还原后再导成品"，多绕一圈、多一次出错机会。

### 3.3 建稿模板（`spec.json`）

**分两层 —— 混着传是错的**（未知字段传给 PS 可能被忽略、也可能报错，本条未验证，故按最保守处理）

```jsonc
{
  "meta": {                       // ← 插件自己用，绝不传给 PS
    "specName": "Vellum 出图规范",
    "specVersion": 3,
    "effectiveFrom": "2026-10-12",
    "bleedMm": 3,
    "usage": "print",             // print | screen | social ⇒ 决定套哪套检查规则
    "safeAreaMm": 5,
    "layerStructure": ["背景","主视觉","文案","装饰","参考"],
    "exportPresets": [ … ]
  },
  "ps": {                         // ← 原样 JSON.stringify 后喂给 presetJSON
    "width": 2480, "height": 3508, "units": "pixelsUnit",
    "resolution": 300, "resolutionUnits": "inchesUnit",
    "depth": 8, "mode": "CMYK", "fill": "white",
    "profile": "Japan Color 2001 Coated",
    "guides": [ { "direction": "v", "coordinate": 5 }, … ],
    "artboards": []
  }
}
```

**原则：`meta` 里只放"插件会用它做判断或执行"的东西。** 纯给人看的说明别塞。

**建稿流程**

```
用户选「A4 带 3mm 出血」
   ↓ 插件由 meta.bleedMm 算出画布 = 216×303mm → 换算 px
   ↓ createDocument({ presetJSON: JSON.stringify(ps) })
   ↓ 参考线随建稿写入文档（C2 已实测成立）
   ↓ 按 meta.layerStructure 建规范图层组
结果：从第一秒这稿就在正确的轨道上 ⇒ 体检的出血判据天然成立 ⇒ 弹窗基本不出现
```

### 3.4 入口与外壳（**不新增插件**）

**硬约束（用户 2026-10-12 明确）**：所有功能都在 `com.vellum.toolbox` 这**一个**插件里，  
**不给同事装第二个插件**。这不只是"省安装"，有三条硬理由：

1. **权限是插件级的** —— 将来若要加 `network` / `fullAccess`，只影响一个插件的授权面
2. **分发是插件级的** —— 一个 `.ccx`，一次更新，不会出现新旧版本混装
3. **避免"装了 A 没装 B"的支持灾难** —— 多插件必然出现版本错配与能力缺失

而且外壳本来就是为这个准备的 —— `tools/index.js` 注释原话：

> 加第 5、6 个工具 = 新增一个模块文件 + 在下面数组里加一行，**外壳零改动**

**落点（全部已存在，**&#x4E0D;需要新结&#x6784;**）**

| 功能      | 落点                       | 现状                       |
| ------- | ------------------------ | ------------------------ |
| 体检常驻状态条 | `#vt-status`（三段式里的定高状态条） | **已存在** —— 就是现在显示「就绪。」那句 |
| 出图体检操作台 | 宫格新增一格「出图体检」             | 注册表加一行 + 一个模块文件          |
| 建稿模板    | 宫格新增一格「新建稿」              | 同上                       |

**分两步走 —— 不是临时壳**：

1. **现在**就把两格加进 `tools/index.js` 的 `planned[]`（灰行、点一下提示"还没上线"）  
   —— 这个机制**已经存在**（现有那条 `mcp` 灰行就是）
2. 实现后挪进 `tools[]`、`ready` 置 true —— **外壳零改动**

> 外壳已有「定高头部 + 可滚动中段 + 定高状态条」三段式，`docs/13` 也早写明  
> "后面加到 5、6 个工具也照样滚"。所以加到 6 格不需要改布局。

**状态条上的体检摘要建议做成可点**（点进「出图体检」工具页）——  
外壳已有这个交互先例：`#vt-chip` 就是 `role="button"` + 「点击查看运行环境」。

**测试（不需要手测）**

| 层      | 手段                                    | 用途                                                                                                                                     |
| ------ | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **主力** | `lib/selfcheck.js` 加 `S49` / `S50` 用例 | 走**真实 mount 路径**（`ctx.shell.showTool("inspect","selfcheck")`）→ 量读数 → 写 `report.json`。**这是 AI 能读、能断言的通道**（先例：S1–S48；S48 = M3b 出稿引擎真机验证） |
| 离线     | `tools/offline-smoke.cjs`             | 纯函数 + 命令形状断言                                                                                                                           |
| 辅助     | 真机手动                                  | **只用于看"好不好看"，不用于验"对不对"**（项目铁律：AI 能自己验的就别让用户点）                                                                                          |

**探针不是交付物**：`hello-uxp` / `env-check` / `link-probe` / `template-probe` 都是**研发工具**，  
不进交付清单，同事永远不会装到（项目已有 4 个先例）。

> 「把**插件的动作**暴露成 MCP 工具，让 AI 客户端能直接调用」——
