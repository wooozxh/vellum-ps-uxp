## 三、GBK 方案：**已原型验证**（不是"应该可行"）

### 做法
按 GBK 的**区位**建一张平面表：**金字节 `0x81–0xFE`（126）× 尾字节 `0x40–0xFE`（跳过 `0x7F` ⇒ 190）= 23,940 槽位**，
每个槽位存一个 Unicode 字符，**没有映射的槽位存 `U+FFFD`** ⇒ 解码就是一次 `charAt(索引)`，无分支表、无运行时依赖。

### 实测数字
| 项 | 值 |
|---|---|
| 槽位 | 23,940（其中**有映射 21,791**，占位 2,149） |
| 生成文件 `lib/gbk-table.js` | **71,684 B**（≈70 KB） |
| 当前 ccx 体积 | 351,339 B ⇒ 加表后约 **423 KB**（仍在正常范围） |
| 依赖 | **零**（不需要 webpack、不需要第三方库） |

### 校验（**穷举**，不是抽样）
用 **Python 的 `gbk` codec（外部权威）**逐对生成期望值，Node 侧按同一套字节**跑完 23,940 对**：
```
穷举校验 23940/23940 命中
样本 4/4：报告,序号 / 张三 10 / 名称,价格,备注 / 海南升学集训营
```

### 🔴 这一轮最值钱的方法学教训
第一版解码器把步长写成了 **`0xBF`(191)**，而真值必须是 **`190`**（尾字节空间在 `0x7F` 处**有个空档**）——
结果**每一对都解错**（`中文` → `譯蟂`）。
**如果我当时是用"自己生成的表"做往返校验，这个 bug 会 100% 通过**：
编码和解码用同一个错误索引，永远自洽。
⇒ **自己产出的表，验不了自己的解码器**；必须拿**外部权威的已知答案**逐项比对。
（"永远成立的样本验不出任何东西"的又一次现场版。）

### 落地口径（写进 M3a）
- 读文件**一律走 `read({format:binary})` 拿字节**，**不再依赖宿主的文本解码**（S35 证明它会把 GBK 毁掉）。
- 解码顺序：**BOM**(`EF BB BF` → UTF-8) → **UTF-8 严格校验** → 合法则自己解 UTF-8；
  否则按 GBK 解；两条都不成立才报错。
- 面板上**显示识别到的编码**（用户看得见，才不会出现"内容默默变成问号"）。
- UTF-8 解码器**自己写**（约 30 行，无表），因为 `TextDecoder` 不存在（S35 三处都查过）。

## 四、Excel 导入的成本（回答"高在哪儿"）

**xlsx 是什么**：一个 **ZIP 包**，里面有 `[Content_Types].xml`、`xl/worksheets/sheet1.xml`、
`xl/sharedStrings.xml`、`xl/styles.xml` 等。⇒ 读它 = **先解压、再解 XML、最后还原表格语义**。

| 环节 | 需要什么 | 真机读数（S39） | 代价 |
|---|---|---|---|
| **① 解压** | DEFLATE 解压 | `DecompressionStream` ❌ `CompressionStream` ❌ `Worker` ❌ ⇒ **平台一点不给** | 自带纯 JS inflate，或 vendor 一个 zip 库 |
| **② 解 XML** | XML 解析器 | `DOMParser` ❌ `XMLSerializer` ❌ `FileReader` ❌ | **没有解析器** ⇒ 只能自己抠字符串/正则抠 `<c>` `<v>` |
| **③ 还原语义** | —— | 无平台依赖，纯逻辑量 | 见下 |

**③ 才是真正的坑**（不是"解析"本身）：
- **共享字符串**：单元格存的是 `t="s"` + 索引，得去 `sharedStrings.xml` 取真值；
- **空单元格被跳过**：`<row>` 里只有有值的 `<c r="C3">` ⇒ 必须**按 `r` 的列引用自己补空格**，否则整行错位；
- **日期/百分比/货币是"数字 + 样式"**：`45231` 要靠 `numFmt` 才能变成 `2023-11-05`；不做这层，用户看到的就是 `45231`；
- **合并单元格**要读 `mergeCells` 并自己决定填哪个格 —— 竞品（官方教程）明写"**文件不能有合并的单元格**"，说明**他们也没做**；
- 隐藏行列 / 多 sheet / 富文本；再加 `.xls`（老的 OLE 二进制）**完全是另一条路**。

**另外两条"低成本替代"也被真机堵死了**：
- **剪贴板**：`uxp.clipboard` / `require("clipboard")` **都拿不到** ⇒ 「Excel 里复制 → 面板里粘贴」❌
  （这本来是最省事的方案，我特意去验了。）
- **服务端转换**：竞品网页版能"导入 Excel"，是因为它是**网页栈、有服务端**；我们是**纯插件侧，没有后端**。

**成本结论**：CSV = 一个纯文本状态机（约 80 行）+ 编码处理；
xlsx = **解压 + XML 抠取 + 语义还原（约 400–600 行）+ 一个第三方库**（官方样例是 `jszip@3.7` + **webpack**，
而本插件是**无打包器**的纯 `require` 结构 ⇒ 要么引打包器、要么验证 UMD 单文件能被 `require` 动，**后者未验**）。
粗算 **3–5 倍工作量**。

**唯一收益**：xlsx 内部 XML **恒为 UTF-8** ⇒ 天然绕开编码问题。**但这一点 GBK 表已经替我们解决了**，
所以这个收益对我们的价值 ≈ 0。

**建议**：**不做**。改为在面板上给一句可操作指引 + 本地前置校验
（"这个文件既不是 UTF-8 也不是 GBK 文本 ⇒ 请用 Excel「另存为 → CSV UTF-8」再导入"）。
若将来真要做，最省的可行口径是：**vendor JSZip + 只支持"无合并单元格、日期按数字原样输出"**，明确标为二期。

## 五、M3 架构（按上面七条修订后的版本）

### M3a · 生成表格
输入：`CSV`（UTF-8 / UTF-8-BOM / **GBK**）。
区域：**有选区就按选区**（宽 = 选区宽；列宽比例可调），**没选区就用落点锚**（v0.3.3 已有）。
产物：一个图层组「表格 · <文件名>」，内含

| 内容 | 图层 | 数量（表头 + R 行 × C 列） |
|---|---|---|
| 外框 | 矩形形状层（`fillEnabled:false` + `strokeEnabled:true`，**四角圆角可设**） | 1 |
| 表头下线 + 每行下线 | 细矩形形状层（线条规则可配：横/竖/都有/无） | 1 + R |
| 内部竖线 | 同上 | C−1 |
| **表头背景 + 每行背景** | 形状层（**纯色或渐变**） ← **v0.3.8 方案漏掉的一块** | 1 + R |
| 单元格文字 | **框文本**文字层（`char:box` + `bounds`，内边距=「填充距离」） | (R+1)×C |

- 对齐：**默认居中**，逐列可调（左/中/右，S37 已验）。
- ⚠️ **上限闸门按「总层数」算**（含背景与线），不再只数文字层；超限给"先生成前 N 行 + 继续生成"。
  依据：v0.3.8 实测 **37.5ms/层**（批量），上表这张表 ≈ **40 层 ≈ 1.5 秒**。

### M3b · 批量出稿
- 一份稿件 = 一个图层组 ⇒ **复制组 + 逐组换文字**（v0.3.8 的 S33 已验证：副本改了 **且** 原件没变）。
- 列 ↔ 图层 的绑定 = **列名 → 图层名**（每格本来就是独立文字层）。
- 按**每批 10 份**追加。

### 样式配置（用户点名要）
- 保存：`store.js` 写 `table-style.json`（PluginData）—— **已通**。
- 导出给别人：`getFileForSaving` 另存为 `表格样式.json`（或 `getFolder` + 写文件）—— **S38 已验存在**；
  导出后**把路径显示在面板上**。**不走剪贴板**（不存在）。
- 作用域：**通用 / 表头 / 行 三组**（借竞品的分层，比"一套样式"更好用）。

### 明确不做
- ❌ 随机假数据（决策⑤）
- ❌ Excel 导入（决策⑦，见 §四）
- ❌ 手动新建空表（降为可选 —— 没有假数据之后它的价值很低，除非你还要"只要一个空表框"）

### 附录 · 已验证原型的代码（防止丢失，M3a 直接搬）

生成器（Python，约 15 行）：
```python
chars = []
for lead in range(0x81, 0xFF):
    for trail in range(0x40, 0xFF):
        if trail == 0x7F: continue
        try:    chars.append(bytes([lead, trail]).decode("gbk"))
        except: chars.append("\uFFFD")
open("gbk-table.js","w",encoding="utf-8").write(
    "module.exports = " + json.dumps("".join(chars), ensure_ascii=False) + ";\n")
```

解码器（JS，**已验证**；注意步长 `190`、以及 `0x7F` 空档）：
```js
const T = require("./gbk-table.js");
function decodeGbk(buf) {            // buf: Uint8Array / Buffer
  let out = "", i = 0;
  while (i < buf.length) {
    const b = buf[i];
    if (b < 0x80) { out += String.fromCharCode(b); i++; continue; }
    if (i + 1 >= buf.length) { out += "\uFFFD"; i++; continue; }
    const lead = b, trail = buf[i + 1];
    if (lead < 0x81 || lead > 0xFE || trail < 0x40 || trail > 0xFE || trail === 0x7F) {
      out += "\uFFFD"; i++; continue;
    }
    const t = trail < 0x7F ? trail - 0x40 : trail - 0x41;
    out += T.charAt((lead - 0x81) * 190 + t) || "\uFFFD";
    i += 2;
  }
  return out;
}
```
