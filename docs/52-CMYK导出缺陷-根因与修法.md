# 52 · 「导出审核版」在 CMYK 稿上静默失败 —— 根因与修法

> 2026-10-17 用户真机报障（面板截图）：在自己的稿
> `2海南代理展架修改后84×184cm（3mm出血）.jpg`（4961×10866 @150dpi · **CMYK**）上点
> 「导出审核版」，面板报 **`导出文件读回是空/读不到（bytes=null）`**，
> 而「还原自证」三项全绿。本文是完整取证链、根因、以及修法选项。**修法待拍板。**

---

## 一、结论（先说结果）

**根因：Photoshop 的 PNG 存储命令不支持 CMYK 文档。**

- 直连 PS 逼出的**真实报错**（ExtendScript `doc.saveAs(file, new PNGSaveOptions(), true)`）：

  ```
  发生了常规 Photoshop 错误。该功能可能无法在这个版本的 Photoshop 中使用。
  - 命令「存储」的参数当前是无效的。    #-25923
  ```

- 同一台 PS、同一份参数：**RGB 稿存 PNG 成功**（3178 B）；**新建的 400×400 CMYK 稿一样失败**（`#-25923`）
  ⇒ 与「这张稿多大 / 什么内容 / 放在哪」都无关，就是 **CMYK × PNG** 这个组合本身。
- 同一张 CMYK 稿存 **JPG 完全正常**（5.3 MB）⇒ 不是"存不了盘"，是 **PNG 这个格式**。

**为什么表现为「报成功、盘上什么都没有」：**
UXP 的 `Document.saveAs.png(entry, {}, true)` **把这个错吞掉了**（不抛异常、正常 resolve）。
于是 `exportReview` 一路走到最后，只有 `entryBytes()` 返回 `null`。
⇒ 典型的**「命令没报错、结果却错」**——本项目最危险的一类失败，这次撞在 PS 自己的 API 上。

**影响面（比看起来大）：**

- **「导出审核版」对所有 CMYK 稿 100% 失败**——而 CMYK 恰恰是**要印刷的稿**（展架 / 易拉宝 / 海报）。
- **「导出成品图」同样失败**（它也是 `saveAs.png`）。
- 即：**这个工具最重要的那条使用场景，从来没成功过。**

## 三、🔴 附带查出的**我们自己的**测试漏洞（必须记住）

`createScratchDoc({ mode: "CMYK" })` **一直静默忽略 `mode`**：

```
模式实测：请求「CMYK」→ 真机是「RGBColorMode」
```

- 原因：`mode` 被直接塞进 `documents.add({mode: "CMYKColorMode"})` —— **字符串枚举被静默忽略**
  （又是本项目那条"需要枚举值时别硬凑、先查 `photoshop.constants`"的老坑；S66 顺带查出
  `Document.duplicate` 与 `Document.changeMode` 都**存在**）。
- 后果：**之前所有标着"CMYK"的探针其实都在验 RGB**，整个 CMYK 分支**从来没被覆盖过**。
  我先前据此向你汇报过"CMYK ✔"，**那条是错的，这里更正**。
- 已修（v0.9.1）：枚举值走 `constants.DocumentMode`，建完**读回**，不一致就 `changeMode` 纠正，
  纠正不了就在返回值里标 `modeMismatch` —— **绝不假装成功**。

**教训（建议升为通则）：自检里凡是"传了参数"的地方，都要**读回**一次。**
一个把请求参数吃掉的测试台，比没有测试更危险 —— 它会给出**虚假的绿色**。

## 四、修法（待拍板）

### 修法 1 · 改走备路：复制一张稿，在原稿之外转换与绘制 —— **我推荐这个**

- `doc.duplicate()`（已确认存在）→ 在**副本**上：`changeMode(RGB)` → 扩画布 → 画参数条 →
  按长边上限缩放 → `saveAs.png` → **关掉副本（不保存）**。
- 优点：
  - **原稿一根汗毛都不动**——连"临时改一下再还原"都不需要，`activeHistoryState` 那套还原机制
    以及它唯一的未验点（历史状态被挤出后行为如何）**整块风险消失**；
  - CMYK 天然解决（副本转 RGB 不影响原稿）；
  - 副本与原稿逐像素一致 ⇒「审核版必须真实」照样成立。
- 代价：多一次复制（5400 万像素稿约几秒 + 内存）；需新验：**跨模式复制的颜色**与副本上的版式。
- 风险：**低**。

### 修法 2 · 保留主路，加一步「临时转 RGB」

- 在 `saveAs` 前 `changeMode(RGB)`，保存后靠**已有的**「赋回历史状态」还原。
- 优点：改动最小，保留你拍板的「主路」。
- 风险：**模式转换是重操作**；`activeHistoryState` 能不能把 CMYK 原像素**还原回去没验过**；
  万一还原不了，**你的稿会被留在 RGB**（可 Ctrl+Z，但那是事故）；带文字层时的转换行为也要重验。
- ⇒ **不推荐先走这条。**

### 修法 3 · 只止血（**本轮已做**）

- 不再静默：失败时直接说清成因（「这张稿是 CMYK，PS 的 PNG 存储不支持 CMYK（#-25923）」），
  并**自动独立复核 + 重试一次**（复核是"问目录里有没有这个文件"，不再依赖 `read()` 的成败）。
- 适用：先别再骗人。**但它不解决"同事导不出审核版"**。

### 我的建议

**修法 1（备路）**。它是唯一**既解决 CMYK、又完全不碰原稿**的方案；
而"不碰原稿"正好把主路最大的一类风险整块消掉 —— 对"少加班、不返工"这个目标更对路。
「导出成品图」同理（同样是 `saveAs.png`，同样在 CMYK 上失败），修法一致。

## 六、实施与验证结果（2026-10-17，**v0.9.2 · 备路**）

**用户拍板：修法 1（备路）。** 已实施并真机自证。

### 改了什么

`exportReview` 从「主路（在用户稿上临时改 + 靠历史状态还原）」整体改成**备路**：

```
0 体检 → 1 版式/文字/主题（都在**原稿**上，只读）
      → ① 复制一张**副本** → ①b 副本若非 RGB 先 changeMode(RGB)
      → ② 设背景底色 → ③ 扩画布 → ④ 写参数条（正文/角标/依据+logo）
      → ④c 按长边上限缩放 → ⑤ asCopy 导出（含独立复核 + 重试）
      → ⑥ 还原背景色 → ⑦ 读副本飞行读数 → **关掉副本（不保存）**
      → ⑧ 切回原稿，读回自证「**三项都没变**」
```

- 新增助手：`duplicateActive()`（签名逐个试，不猜）、`ensureRGBDoc()`、`savePngWithCheck()`（保存+问目录复核+重试）、`closeQuietly()`、`activateQuietly()`。
- **删掉**了导出里的「记撤销标记 / 赋回历史状态」（`safeRevert` 保留但导出不再用它）。
- 「导出成品图」同样走备路（它也是 `saveAs.png`，在 CMYK 上一样会失败）。
- 面板文案改成「（在副本上作业，不动你的稿）」。
