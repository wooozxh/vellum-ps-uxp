# 46 · M3b「按行批量出稿」落地（v0.5.0）

> 用户拍板三条：**模板 = 选中优先 + 下拉可改**；**副本自动网格排开**；**副本名 `稿件 3 · 开学季`**。
> 按项目纪律：**动手前先把未知项用真机钉死**（S47 测量轮）→ 出方案 `docs/45` → 落地 → 自证。

**真机 S48 PASS**（51/53，另两条见 §六）；**离线 70/70**；ccx 0.5.0。

## 一、开工前先量（S47）

| 路径 | 复制 10 份 | 写 20 次文字 | 合计 |
|---|---|---|---|
| DOM 三步舞步（选中 → `duplicate()` → 改文字，每份 3 个模态边界） | 选中 520 + 复制 435ms | 1440ms | 2397ms |
| **AM 一次 batchPlay 复制**（按 `_id`） | **165–188ms（17–19ms/份）** | 一次模态写完 **1128–1209ms（≈56–60ms/次）** | ~1300ms |

四条事实（后面设计全基于它们）：
1. **AM `duplicate` 按 `_id` 成立且可合批**（17–19ms/份）；DOM 那套 95ms/份 + 每份 3 个模态边界。
2. **写文字才是大头**：DOM `textItem.contents` ≈**56–68ms/次** ⇒ 出稿耗时 ≈ N × 列数 × 60ms，**面板必须报预估**。
3. **改副本不动原件**（10 份规模复验）—— 这是硬条件。
4. 🔴 **`duplicate` 之后必须跨一个模态边界才读得到副本的子层**（同一模态里 `copy.layers` 读到空数组）。

## 二、落地形态

**数据流**：CSV（已有）+ 绑定表（列 → 模板里的**第几个**文字层）+ 模板（用户自己 PSD 的图层组）
→ ① 一次 batchPlay 复制 N 份（名字一次给好）→ ② 一个新模态里读完所有副本并写文字 → ③ 逐份"选中 → 平移"排开。

**新增**：`lib/batch.js`（**纯函数**：绑定校验 / 网格 / 命名 / 空格跳过 / 警告 / 闸门 / 预估）
· `lib/ps.js`（`layerBrief` `activeLayerBrief` `groupBriefByName` `listGroups` `maxLayerId` `dupLayerByIdCmd` `moveByIdCmd` `exportByRows`）
· `tools/table.js`（第三个折叠块换成真控件：模板识别 + 逐列**芯片式绑定** + 警告 + 预估 + 双动作接线；列抽屉里也放一份绑定）
· `index.html`（`.tchip` 芯片样式）。

**面板上的几个取舍**：
- 绑定用**芯片**（不是 `<select>`：UXP 里外观改不动；也不是浮层：面板在 `.tbl-body` 里会被 `overflow` 裁掉）。
- 超闸门（份数 >200 或写入 >400）**先问再出**：第一次点击只把按钮变成「仍然生成 N 个（约 Xs）」，第二次才跑（UXP 没有可靠的 confirm 弹窗，用状态表达比赌对话框稳）。
- 面板上写清：**预估耗时**、未绑定列警告、空格子"跳过不写"（保留模板原文）。

## 四、🔴 本轮最值钱的一条：**位移原语只认"当前活动图层"**

| 试法 | 结果 |
|---|---|
| AM `{_obj:"move", _target:[{_ref:"layer",_id}], to:{offset}}` | **不认 `_target`**（靶层不动） |
| DOM `layer.translate(x,y)`（对**非活动**对象调用） | **也不动**；而**活动层动了** |

⇒ 结论：**想移动谁，得先把它选中**（`doc.activeLayers=[layer]` 再 `translate`）。实现因此改成"逐份：选中 → 平移"。

**这里我自己犯了两个错，都是方法学上的**：
1. **第一条读数没有对照组**：第一轮探针里"靶层**恰好就是活动层**" ⇒ 报 ✓，其实证明不了"认 `_target`"。
   加上对照组（另造一层设为活动）后立刻翻盘成 ✗。**"存在"的判据必须配"一定不成立"的对照。**
2. **量了几何却把元素建在了错误的位置**：靶层是在建完模板组之后造的 ⇒ 新层落进了**当前活动的组**里，
   被一起复制进副本，读数全歪（副本多出两层、原件断言失败）。⇒ **造探针元素前先确认"活动层在哪一级"。**

另外两条小坑：`layerInfo()` **不带 bounds**（要用 `readActiveLayerBounds()`）；绑定值用**序号**时 `0` 是合法值，
`if (!bindings[c])` 会把"绑了第 0 层"当成"没绑"（离线断言当场抓出来）。

## 五、离线断言（65 → 70）

- **22h**（纯函数）：绑定 / 空格跳过 / 网格 / 命名 / 警告 / 预估——**期望值全部独立算**（3 行 × 1 有效列 ⇒ 2 次写入、297ms、dx 216/432/648）。
- **22h-2**：闸门（201 行 → tooMany，不静默截断）、"一列没绑"要拒且**说清模板里有什么**、没模板要拒。
- **22h-3**（执行，**mock 会真的模拟 `duplicate`**）：批次数 = 2（复制 + 位移）、复制命令全按 `_id`、
  位移逐叶层且值对、**每份写自己那一行的值**、**未绑定列不动**、**原件不动**。
- **22h-4**：负对照 —— duplicate 判据只放过"按 `_id` 且带名字"那 1 条（按名字选层/漏名字都要被拒）。

## 六、诚实边界 / 未验

- **面板整链（点芯片绑列 → 点「生成 N 个稿件」）还没有真机点过**：面板的挂载与几何由 S41 覆盖，
  引擎由 S48 覆盖，但"点下去"这条只有用户能跑一次（系统文件选择器那类的道理）。
- **S20e（素材库的项目筛选下拉）偶发 FAIL**：日志 62 次 PASS / 4 次 FAIL，失败读数正是一个
  **`0×0` 几何**（"同一行"那条），属**已知的"布局没落定就量"老坑**；不是本轮改动的回归。
  修法同 S41/S44（先等几何非零再量）——**本轮没动它，也没复跑**，留给下一轮顺手收口。
- **规模与性能没测**：N=20 份时的"逐份选中 + 平移"是 2 次 DOM 写/份，代价随文档大小涨（v0.4.7 的教训）⇒
  大批量（50+ 份）前要先量一遍。
- 圆角外框 / 背景渐变 / 样式配置导出 仍未做。
- 顺手观察未改两点（浅灰字压白画布对比过低；落点锚默认 420×320 在 400×400 画布上超框）。
