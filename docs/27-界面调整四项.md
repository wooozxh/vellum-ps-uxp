## 〇、先回答的提问：软件侧做通用库 UI，会不会影响插件侧？

**不会。** 两边**唯一的耦合点是契约**（`D:\vellum-link\LINK-CONTRACT.md`，`vellum-link/1` 已冻结）：

- 软件侧的 DB schema、库界面长什么样、素材怎么入库 —— 都是**软件侧内部实现**，插件看不见。
- 插件只读镜像三件套（`manifest.json` / `task.json` / `brand.json` + `thumb/`）；
  插件侧开发用的是**假软件桩** `tools/fake-vellumdesk.cjs`，不需要真软件在跑。
- 反过来同理：本轮改的全是插件自己的 UI，对软件侧零影响。

**只有三处需要对方先公告**（都属契约可见面）：① 通用库要不要**第三层**分组；
② `source` 要不要加新取值（现在 `company` / `user`）；③ 素材字段增减。

## 二、任务库的「项目」筛选下拉（用户第 2 条）

放在**顶部行、刷新按钮左侧**。

**为什么改成下拉**：项目个数会随工作量一直长，一排 chip 很快把面板顶部撑满（这次调整整体就是在减负）。
而通用库的顶层只有「公司素材 / 我的收藏」——少而稳、点一下就到，所以**那边仍然保留按钮**。

三个实现要点：

1. **形态判定靠结构、不靠 id**：新增 `mirror.scopeKind(data)` ——
   `task.json` 有 `projects` → `"task"`；`brand.json` 有 `groups` → `"brand"`；其它 → `"unknown"`。
   ⚠️ 写成 `if (scopeId === "task")` 的话，软件侧将来加库 / 改名会**静默失效**（界面照常渲染，只是少了那块）。
2. **复用 `S.group`**：它就是"顶层分组"这一个筛选条件 ⇒
   `itemsInGroup` / `visibleItems` / `filterLabel` / `pruneFilters` **一行都不用改**。
3. **只有一个项目时不画**（一个选项不构成筛选）—— 与「来源」行同一条判断。

**顺带的一个后果（需要用户知道）**：任务库的筛选区现在只剩一个总数计数
（项目条件已挪到顶部，**不许重复画一遍 chip**）。离线断言 40 把这条钉死了：
选完项目后筛选区里的 chip 数必须为 **0**。

> 📌 任务库目前**只有一层筛选**（`flattenTask` 的 `sub` 恒为空 —— 两级分组是**通用库**的，契约 §5.3）。
> 所以任务库里不会出现「任务包」下拉。若需要按任务包/版本再筛一层，是另一件事，说一声即可。

## 四、二级下拉与一级按钮同一行（用户第 4 条）

做法：新增 `.fchips` 容器（`flex: 1 1 auto`）装 chips，二级下拉用 `flex: 0 0 auto`
挂在**同一个 `.frow`** 的行尾 —— chips 自己占满左侧剩余宽度，下拉自然被顶到最右。

真机 S20c 的结构签名就是证据：

```
筛选区签名=frow{chip:"",chip:"公司素材",chip:"我的收藏",wrap{open=false},trig,pop,opt:"",opt:"节日素材"}
```

一个 `.frow` 里同时有 chip ×3 和 wrap/trig/pop/opt —— **同一个行**，下拉在第 4 位（行尾）。

### 🔴 连带必须改的一处：浮层改成**右对齐**展开

`.fsel-pop` 原来是 `left: 0`（从触发条左缘往右展开）。下拉一旦贴到**行尾**，
往右展开就会**越界** —— 而滚动容器 `.scroll` 同时有 `overflow-y:auto` 与 **`overflow-x:hidden`**，
越界部分**直接被裁掉**，用户只会看到"点开了但里面是空的"。

⇒ 改成 `right: 0`（往左展开），并给 `max-width: 230px` + 选项文字截断。
这条在离线断言 38 里是源码级守门：**`right:0` 存在且 `left:0` 不存在**。

## 五、把两个下拉收成一份实现（顺带的重构）

页面上现在有**两个**自绘下拉（项目 / 二层子类），原先那份是给子类专用的。本轮抽出
`makeSelect(cfg)` 共用，并把展开态从 `S.subOpen`（布尔）改成模块级 `openSel`（wrap 的 id）：

- 布尔状态的问题是**两个下拉会各自为政** —— "点开 A 再点开 B"会让 A 的浮层留在原地。
  现在 `openSelect()` 会先 `closeSelect()`，**同时只允许一个展开**。
- `trig` 里三个片段（`.fs-t` / `.fs-n` / `.fs-cv`）统一 `vertical-align: top` ——
  否则"截断用的 inline-block"与纯文本基线不一致，三个片段会高低错位。
- `.fs-t` 带 `overflow:hidden; text-overflow:ellipsis`：项目名可能很长，触发条有 `max-width: 150px`。

## 七、过程中修掉的三处自己的问题

1. **假软件桩只有一个项目** ⇒ 项目筛选**根本验不出来**（一个选项不构成筛选）。
   给 `tools/fake-vellumdesk.cjs` 加了第二个项目「秋季招生宣讲」（1 个任务包 / 1 张素材），
   于是"选它之后卡片从 3 变 1"才看得见。**测试数据也得能区分"对"和"错"。**
2. **离线断言 40 第一版用了 `!!document.getElementById(...)` 判"元素还在不在"** ——
   **错**。离线 mock 的 `byId` 是**只增不减**的注册表，`removeChild` 不会把它摘掉，
   所以脱离 DOM 的老节点**仍然能被 getElementById 找到**。
   ⇒ 改成判**是否还挂在文档上**。⚠️ 这条只影响离线（真机 UXP 的 `getElementById` 是正常的）。
3. **`libBarSig` / `libFlatSubChips` 用 `indexOf` 判 class，把 `.fchips` 误当成 `.fchip`** ——
   结构签名里冒出一个 `chip:null`，白让人怀疑"是不是多画了个空 chip"。
   ⇒ 新增 `hasClass()` 按 **class token** 判。
   （**同一族纪律**：判据要描述"我等的那个东西"，不是"看起来像的东西"。）
