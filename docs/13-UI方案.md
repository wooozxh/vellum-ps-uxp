# 13 · 界面（UI）方案 —— 「自写 CSS」设计系统

> **状态**：⚠️ **本文档已被 `14-方向B落地评审.md` + `15-方向B落地记录.md` 覆盖。**
> 本文的价值在于「为什么」——UI 技术路线与 UXP 的 CSS 能力边界（官方来源核查）。
> **视觉与实现以 `15` 为准**：设计稿用的是 `design-demos/B-native-pro.html` 那一套，不是本文的通用令牌草案。
> 两处已过时的判断：① 原计划保留少量 `sp-*` → 落地时改为**全自绘**；② 原计划用 `--uxp-host-*` 变量 →
> 落地时改为**自有令牌 + JS 主题探测（媒体查询兜底）**。
> **起因**：用户提出两个问题 ——
> ① 是不是只能用 Adobe 那种灰底蓝钮的界面，还是可以改成比较现代的 UI？
> ② 后续功能「一屏装不下」，面板能不能做上下滚动条？
> **结论（先说）**：
> - **① 不是。** Adobe 官方明确允许自带视觉语言；约束不在「允不允许」，而在 **UXP 的 CSS 是浏览器的子集**。
> - **② 能，而且现在就已经具备**（`#vt-body` 已是滚动容器），只需补一个 `min-height: 0` 加固。
> - **已拍板（2026-10-10）**：**路线 = ① 自写 CSS 为主 + 少量 `sp-*` 兜底**；**主题 = 跟随 PS 自适应**。

## 一、两个问题的答复（含证据来源）

### 1.1 「只能用 Spectrum 灰蓝吗？」→ 不是

- **官方原话**：*"You are free to use your own visual language in UXP plugins."*
  提交到 Creative Cloud 市场**不强制** Spectrum，只「建议」。
  来源：Adobe UXP 官方文档《User Interfaces》。

- UXP 里写 UI 有**三条路，可混用**：

| 路线 | 是什么 | 优点 | 代价 | 本项目 |
|---|---|---|---|---|
| 标准 HTML + 自写 CSS | 纯 HTML 标签 + 自己的样式表 | 自由度最高 | 主题/控件全部自己维护 | ✅ **主力** |
| `sp-*` UXP 内置控件 | UXP 内置的 Spectrum 控件（如现面板的「← 返回」）| 自动跟随主题、无障碍好 | 内部改不动，样式天花板低 | ✅ **少量兜底** |
| Spectrum Web Components | npm 上的 `@spectrum-web-components/*` | 组件最全 | 需要 npm + 构建 | ❌ 不做 |
| （进阶）WebView UI | 内嵌完整浏览器层 | 完整 HTML / CSS / 动画 | 架构最重、抬高最低版本 | ❌ 不做 |

**为什么不选 SWC / WebView**：本项目立项时技术选型已定为 **vanilla JS + 零构建**（见 `PROGRESS.md` 形态已定）。
引入 npm 依赖链会破坏「改一行 → load → 读日志」这条轻量闭环，**收益（组件更多）不如代价大**。
→ 若将来某个界面确实非它不可，**再单独立项评估，不在本次范围**。

### 1.2 「能做上下滚动条吗？」→ 能，且已有

现状 `vellum-toolbox/index.html` 里已经写好了：

```css
html, body { height: 100%; }                                       /* ① 高度链条的根 */
#vt-root   { display:flex; flex-direction:column; height:100%; }   /* ② 纵向骨架 */
#vt-body   { flex:1; overflow-y:auto; }                            /* ③ 唯一滚动区 */
```

这就是 **「定高头部 + 可滚动中段 + 定高状态条」** 三段式 —— 应对「一屏装不下」的标准做法，
后面加到 5、6 个工具也照样滚。

- **唯一要补的**：`#vt-body { min-height: 0; }`
  flex 子项默认 `min-height: auto`，内容超高时它倾向于**被撑开**而不是**滚动**；
  显式给 `min-height: 0` 是零成本防御性加固（不同布局引擎表现不一，写上是稳的）。
- **三条要点**：
  - 头部 / 状态条必须 `flex: none`（现在已是），否则会被内容压缩；
  - 滚动条是**系统原生**的，**不能自绘**成设计稿那种细滚动条（UXP 不支持 `::-webkit-scrollbar`）；
  - 面板尺寸由用户在 PS 里拖拽，`minimumSize 240×300` 已设，滚动会自适应。

## 二、UXP 的 CSS 能力边界（**设计法则的唯一依据**）

> UXP **不是浏览器**。它是「用 Web 技术写桌面」的平台，CSS 是一个**子集**。
> 下表是「能做 / 不能做」的清单 —— **本方案的所有设计取舍都由它推导**。

| 能力 | 状态 | 备注 |
|---|---|---|
| flexbox（含 `gap`）、盒模型、`overflow` | ✅ 支持 | 布局主力 |
| CSS 变量 `--var`、`calc()` | ✅ 支持 | 令牌系统的基础 |
| `linear-gradient` | ✅ 支持（UXP 8.1+）| 谨慎用（见 §七 平面优先）|
| `box-shadow`、`transform`（scale/translate/rotate）、`transform-origin` | ⚠️ **需开 `CSSNextSupport`** | **不开则静默忽略，不报错** |
| CSS Grid | ❌ 不支持 | 用 flex 模拟 |
| `transition`、`animation` / `@keyframes` | ❌ 不支持 | **拿不到平滑过渡** |
| `float`、`position: sticky` | ❌ 不支持 | 用 flex / absolute |
| `text-transform`、`font` 简写 | ❌ 不支持 | 文字大小写手写 |
| `@font-face` 自定义字体 | ❌ 不支持 | **只能用系统字体** |
| 自绘滚动条 `::-webkit-scrollbar` | ❌ 基本不可控 | 用系统滚动条 |

来源：Adobe《What's Unsupported in UXP》、UXP Changelog（PS 26.0 / UXP 8.0.1 新增 `CSSNextSupport`）、
PS 26.1 / UXP 8.1 更新日志。

**另有三条环境事实会影响界面**：

1. `window.devicePixelRatio` **恒为 1** → 位图图标在 HiDPI 屏上会糊。
   → **对策：面板内图标一律用内联 SVG**（矢量不受影响；UXP 支持 `SVGElement`）。
2. **UXP 26.1 / 8.1 起**新增 `ResizeObserver`、`IntersectionObserver`。
   → 前者可做「窄面板自动单列」，后者可做**长列表懒加载**（M2 素材库用得上）。
   **它们有版本门槛 → 一律走探测降级**（`docs/12` §四 C），不裸调。
3. 主题变量（跟随 PS 深浅色**自动更新**）：

```
--uxp-host-background-color        --uxp-host-text-color          --uxp-host-text-color-secondary
--uxp-host-border-color            --uxp-host-link-text-color     --uxp-host-link-hover-text-color
--uxp-host-widget-hover-background-color   --uxp-host-widget-hover-text-color   --uxp-host-widget-hover-border-color
--uxp-host-label-text-color        --uxp-host-font-size   --uxp-host-font-size-smaller   --uxp-host-font-size-larger
```

### 由上面推导出的 **四条设计法则**

| # | 法则 | 因为 |
|---|---|---|
| L1 | **不设计任何「过渡 / 动画」** —— 状态变化用「瞬变 + 对比」表达（色阶跳变、描边加粗、层级位移）| 没有 `transition` / `animation` |
| L2 | **不写死灰度** —— 用 `rgba(127,127,127,α)` 中性叠加代替 `#2b2b2b` | 同一份样式要同时活在深色 / 浅色面板里 |
| L3 | **面板内图标用内联 SVG**，不用位图 | `devicePixelRatio` 恒为 1 |
| L4 | **能不开 `CSSNextSupport` 就不开**；要开必须先在真机验证它确实生效 | 静默失效比报错更危险（`docs/12` §二 的 B 类风险）|

> **关于 L4 的取舍**：开 `CSSNextSupport` 能拿到 `box-shadow` 与 `transform`，对「现代感」确有帮助。
> **但它有版本门槛**（PS 25.x 上不存在），而本项目 `minVersion` 是 **25.0.0（PS 2024）**。
> → **本次决定：先不开**，把 UI 做到「零新特性也好看」；阴影作为**可选的渐进增强**（见 §七）。

## 三、设计令牌（Design Tokens）

放在新文件 **`vellum-toolbox/styles/tokens.css`**，用 CSS 变量集中管理 —— 以后调风格**只改这一处**。

### 3.1 颜色（三层，职责不混）

| 层 | 变量 | 取值方式 | 用途 |
|---|---|---|---|
| **宿主语义层** | `--vt-bg` / `--vt-text` / `--vt-text-2` / `--vt-border` / `--vt-hover-bg` | 引用 `--uxp-host-*`，**带中性兜底** | 面板底、正文、分隔线、hover |
| **品牌层** | `--vt-brand` / `--vt-brand-fg` | 取 `DEFAULT_BRAND[0]`（**待 HEX**）| 选中态描边、主操作 |
| **状态层** | `--vt-ok` / `--vt-warn` / `--vt-err` / `--vt-info` | 自定，**深浅两套** | 状态条、失败提示 |

**中性叠加阶梯**（替代写死灰度，落实 L2）：

```css
--vt-fill-1: rgba(127,127,127,0.06);   /* 极轻底 */
--vt-fill-2: rgba(127,127,127,0.12);   /* 分区块底（= 现状 #vt-status 用的那档）*/
--vt-fill-3: rgba(127,127,127,0.20);   /* hover 再深一档 */
```

**状态色双套**（深色面板用亮档、浅色面板用暗档），用 `@media (prefers-color-scheme: light)` 切换
（UXP 支持该媒体查询）：

```css
:root { --vt-err:#F09595; --vt-ok:#97C459; --vt-warn:#EF9F27; --vt-info:#85B7EB; }
@media (prefers-color-scheme: light) {
  :root { --vt-err:#A32D2D; --vt-ok:#3B6D11; --vt-warn:#854F0B; --vt-info:#185FA5; }
}
```

### 3.2 ~ 3.5 其它令牌

| 类别 | 刻度 | 说明 |
|---|---|---|
| 间距 | `4 / 8 / 12 / 16 / 24`（4 的倍数）| 现有代码在混用 7/10/14 → **收敛到刻度** |
| 圆角 | `--vt-r-sm:6px` / `--vt-r-md:8px` / `--vt-r-lg:10px` | 卡片 8、容器 10 |
| 字号 | `11 / 12 / 13`（+ 10 仅用于 badge）| 中文在 11px 以下会糊，**不设更小** |
| 字重 | **只用 400 / 500**（600 及以上禁用）| 小字号下 600 会「发胖」，反而显廉价 |
| 描边 | `1px`（分隔 / 卡片）、`2px`（选中）| 唯一「加粗」手段（无 transform）|

## 四、布局骨架（三段式，微调）

```
┌───────────────────────────────┐
│ #vt-head    标题 / 副标题 / 返回  │  flex:none（定高）
├───────────────────────────────┤
│ #vt-body    ← 唯一滚动区         │  flex:1  min-height:0  overflow-y:auto
│                               │
├───────────────────────────────┤
│ #vt-status  状态条（回读凭证）    │  flex:none（定高）
└───────────────────────────────┘
```

**改动只有两处**：① `#vt-body` 补 `min-height: 0`；② 内联 `<style>` 抽成 `styles/*.css`。

**响应式**：首页卡片现在 `flex: 1 1 44%`（两列）。窄面板下要落单列 —— **纯 CSS 即可**：

```css
.vt-card { flex: 1 1 140px; }   /* 容器宽度低于 ~2×140px 时自动落单列 */
```

不需要 `ResizeObserver`（那是留给更复杂的自适应的，M2 再评估）。

## 六、状态与交互（无过渡动画下的表达）

**因为没有 `transition`，每个状态的差异必须「一眼可辨」、不靠渐变：**

| 状态 | 手段 | 备注 |
|---|---|---|
| default | 1px 描边（`--vt-border`），透明底 | |
| hover | 底 → `--vt-fill-2` | 瞬变，不突兀 |
| active（按下）| 底 → `--vt-fill-3` + **描边加粗到 2px** | 用描边代替 `transform` 缩放（不开 flag 也能做）|
| selected | **2px `--vt-brand` 描边** + 品牌色小圆点 | 品牌色唯一大面积出现处 |
| disabled / 未上线 | `opacity:.45` + `cursor:default` | 已有 |
| focus | 描边 → `--uxp-host-link-text-color` | 键盘可达性 |

**反面清单（明确不做）**：渐变式 hover、按压缩放、入场动画、骨架屏 shimmer。
—— 在 UXP 里这些要么做不到、要么得靠 JS 硬凑，**性价比为负**。

## 七、动效策略（诚实说明）

- **硬约束**：UXP 无 `transition` / `animation`。**这一条不改。**
- **方案 A（默认，本次采用）**：**全瞬变**。现代感由「排版层级 + 留白 + 克制的色彩」承担，而非动效。
- **方案 B（可选，将来按需）**：对**极少数**「必须要有反馈」的场景（如设色成功），
  用 JS + `requestAnimationFrame` 手写 100–150ms 的**透明度**动画，**不碰布局属性**。
  → 只在用户明确说「这里要动一下」时再做，**不预置**。
- **明确不做**：入场动画、页面切换动画、任何循环动画。

## 九、验收标准（怎么证明「UI 改对了」）

| # | 标准 | 怎么证 |
|---|---|---|
| 1 | 内容超高时**只有中段滚动**，头部与状态条不动 | 自检：构造超长内容 → 断言 `#vt-body.scrollHeight > clientHeight` 且可滚 |
| 2 | 窄面板（240px）**无横向滚动条**、卡片落单列 | 自检：断言 `scrollWidth <= clientWidth` |
| 3 | 深浅两种主题下**文字都清晰可读** | 令牌对比度脚本校验 ≥ 4.5:1 + 人工各看一眼 |
| 4 | 所有交互态（hover/active/selected/disabled）**一眼可辨** | 人工看一眼（AI 点不了 PS 的 UI）|
| 5 | 视觉整体「现代、不像 Adobe 默认」 | **只能人工判断** —— 唯一必须你亲自看的 |
| 6 | 现有功能**零回归**（调色板自检仍 10/10）| 跑 `lib/selfcheck.js` |

> **诚实说明**：第 5 条我无法自证 —— **我读不到像素**。这条由你验收；其余 5 条我出证据。
