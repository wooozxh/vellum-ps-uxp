## 一、三个方向是同什么、不同什么

**同**：同一份数据（`prices-2026.csv`，6 行 × 5 列）、同样两件事（生成表格 / 批量出稿）、
同一套视觉令牌（直接取自插件现在的 `index.html` 深色系统：`--vt-panel:#323232` / `--vt-arc:#1473e6` …）
⇒ **选定后落进面板不会像两个产品**。

**不同**：**信息架构**。三个方向用的是"同样内容怎么组织"的三种取舍：

| | 方向 1 · 向导式 | 方向 2 · 工作台 | 方向 3 · 表格为画布 |
|---|---|---|---|
| 组织方式 | 按**步骤**（数据→区域→样式→出稿） | 按**区块**（可折叠，全在一屏） | 按**对象**（整表/表头/数据行/各列） |
| 一次看到 | 一个决定 | 全部（收起的带摘要） | 表格 + 当前对象 |
| 两个动作 | 拆开：生成表格在第 4 步顶部 | **底部常驻并列** | 底部常驻并列 |
| 样式入口 | tab（通用/表头/行） | 折叠块里的 tab | 对象树 |
| 绑定入口 | 第 4 步的列表 | 独立的折叠块 | **点列头 → 就地长出来** |
| 学习成本 | 最低 | 中 | 中（要学"点列头"） |
| 主要代价 | 改早期参数要往回翻 | 折叠状态要记住 | 5 列挤 + 隐藏动作 |

## 二、我的建议：**以方向 2 为骨架，吸收方向 3 的列操作**

理由三条，都对着你刚才的两个拍板：

1. **你选了"两件都做、并列"** ⇒ 两个动作就该**常驻并列**、随时可点。
   方向 1 把它们拆到第 4 步，等于"并列"只在一屏成立；方向 2/3 的底部常驻条才真正兑现这条。
2. **你选了"绑定到自己的版式图层"** ⇒ 绑定表是高频反复看的东西，藏在第 4 步会来回翻。
   方向 2 把它做成**独立可折叠块**，折叠标题上还带「5 / 5 已绑」的进度。
3. **方向 3 的"点列头就地设置"是这轮最好的一个交互** —— 但它不该独占一整套架构。
   建议**把它塞进方向 2 的列设置里**：绑定块里点某一列的名字，就地展开"列宽 / 对齐 / 绑到哪个图层"。
   这样"整表参数在折叠块、列级参数在列上"，既不挤，又保住了直觉。

> 也就是说：**方向 2 + 方向 3 的列抽屉** 是我推荐的组合。
> 如果你更看重"第一次用不会蒙"，那就纯方向 1；
> 如果你觉得"表格就是我天天盯的东西"，那就纯方向 3。

## 三、三个方向里，值得你留意的几个设计决定（都是我按已实测能力画的）

1. **区域来源给了两个选项**：`用画布选区` / `用落点锚`（v0.3.9 的 S36 已验证两端都可判）。
   面板上直接显示读到的选区矩形 —— 用户能确认"它真的读到我那个框了"。
2. **内边距是排版参数，不是装饰**：它决定文字框 `bounds` 的收缩量（4 个值 = 上右下左）。
3. **警告行只有两种状态**：有列没绑定 = 黄条 + 说清"不绑也能出稿，只是那列不进版面"；
   全绑 = 转灰（沿用设计规范的"告警条转为常规灰"）。**不把"没绑全"做成硬拦**，因为很多时候就是故意不绑。
4. **层数写在界面上**（「约 40 个图层」+ 拆解），因为 v0.3.8 实测 37.5ms/层，
   用户该在点之前就知道要等多久、会多出多少层。
5. **原版式不动**：出稿全是副本（S33 实测：副本改了、原件没变）—— 这句写进了界面文案，用户才敢点。
6. **5 列在 440px 里是真的挤**（这是真约束，不是画得不好）⇒ 方向 3 明说了要横向滚或折叠长列。
   这件事值得你在定方向时一并决定。
