## 二、垂直对齐：PS 没有这个属性，所以只能「挪框」

**关键事实**：PS 的框文本**永远从框顶往下排**，没有"框内垂直居中"这个属性。
⇒ 三档是靠**纯几何**做出来的（`lib/table.js`）：

```
行高(画布px) = 字号(px) × 1.32        // 我们在框里放一个"一行高"的框
顶对齐：框顶 = 行顶 + 内边距
垂直居中：框顶 = 行顶 + (可用高 − 行高)/2
底对齐：框顶 = 可用底 − 行高
```

**顺带修掉一个潜在大坑：字号单位从 pt 改成“画布 px”。**
这一层的几何（行高 28px、内边距 4px）全是画布像素，而 **pt 是物理单位** ——
300ppi 的文档里 12pt = 50px，会把 28px 的行撑爆。设计师也是按 px 想事情的。
⇒ 面板里"字号"按 px 显示，交给 PS 时按 ppi 折回 pt（`pxToPt`），**描述符形状一个字没改，只换数值**。
`describe()` 在 ppi ≠ 72 时会把折算结果写出来（不写清楚会被当成 bug）。

### S43：怎么证明"挪框"真的生效了

第一次用**像素**（把行切 4 条横带取最暗当索引）—— 结果三档全是 `85/85/85/85`，白跑一轮
（原因见 §三，是**我的 bug**）。改用量 **文字图层的墨迹 `bounds`**（对文字层给的是**字形实际范围**，不是我们设的框）：

| 垂直档 | 墨迹 y | 该行的 y |
|---|---|---|
| 顶对齐 | **62–80** | 60–120 |
| 垂直居中 | **167–185** | 150–210 |
| 底对齐 | **271–289** | 240–300 |

```
墨迹位移=209px（计划里框中心位移 208.24px，差 0.76px）
墨迹相对框中心的偏移=[-4.88, -4, -4.12]（三档之间差 0.88px）
```

⇒ **几何 1:1 落到画面上**，且那个 ~4px 偏移是三档**恒定**的 —— 那是 PS 行盒排版
（字形上重下轻）的固有偏移，不是我们的错。

🔴 顺便记一条判据教训：**第一版判据写"墨迹中心距行中心 ≤3px"，实测 4px ⇒ 误报失败。**
判据该问的是"**我们控制的东西**有没有正确落地"（框的位移），而不是"PS 的行盒怎么摆"。
**把与实现无关的量当作判据，就是给自己造 FAIL。**

## 三、🔴 我自己造的坑：一次"看起来一样"的字符串替换

S16/S17/S18 在 20:46 还是 PASS，**从 20:52 起集体 FAIL**，都报"像素回读未命中"。
加了一条"把最后一次读数的**错误原文**印出来"之后，一次就抓到：

```
最后一次读数=✗抛错：o is not defined          ← ReferenceError
```

**真相**：我给 `sampleRectAvgColor` 加 `composite` 开关时，用字符串替换改的是
`if (l && l.id !== undefined) req.layerID = l.id;` 的**第一处**——而 `ps.js` 里
`readLayerAvgColor()` 有一行**一模一样**的代码。替到了那里，而那个函数**没有 `o`**
⇒ 每次调用都抛 `ReferenceError`。

**这一个错同时解释了当时看到的三件事**：
1. S16/S17/S18 集体失败（它们都走 `readLayerAvgColor`）—— 且时间线与改动完全吻合；
2. S43 传了 `composite:true` **却没生效**（它其实一直在读"当前图层"= 文字层，
   字形之外全透明 ⇒ 均匀 `85`）；
3. 同一轮里 S40 的像素读是过的（它走 `sampleRectAvgColor`，那个函数没坏）。

修好之后：S16 立刻 `像素回读=#E60012 ✓`，S43 的像素诊断从恒定 `85` 变成 `255`，
全量回到 **47/48**（唯一 FAIL = 已知 S17）。

📌 **纪律（已进 `MEMORY.md`）**：**"看起来一样的两处"永远不要用字符串替换去改。**
要么用带足够上下文的一次性编辑，要么改完**立刻用 grep 验证两处各自的内容**。
另外：**读数必须能区分原因** —— 如果 S16 一开始就印错误原文，这个坑 5 分钟就能定位，
而不是让我在"像素玄学"上多跑了 4 轮真机（每轮 ≈5 分钟）。

## 四、顺带修掉一个真 bug：面板 unmount 之后回调还在跑

离线回归当场崩了：

```
TypeError: Cannot set properties of null (setting 'region')   ← tools/table.js refreshRegion
```

`refreshRegion()` 是异步的，`unmount` 把 `S` 置 null 之后它才回来赋值。
真机上"**点一下样式选项马上切走工具**"是同一个坑。
⇒ 加了 `alive()` 守卫（`!!S && !!refs`），所有 async 回调在**每个 await 之后**重新确认；
`mount()` 里 `await loadPref()` 之后也确认（读偏好期间用户可能已经切走）。
