# 04 · 文本图层为什么建不出来 —— 一次定位与修复

> 宿主：Photoshop 2026 **v27.2** · UXP **9.0.2** · 发生在 `hello-world` 插件
> 记录时间：2026-10-09

---

## 一、用户报的现象

点面板上「在当前文档插入 "Hello World" 文字」之后：

1. Photoshop 弹出**原生错误框**：`Hello World: 命令"设置"当前不可用。`
2. 画布上确实多了一个图层，名字也叫 `Hello World`，**但它不是文本图层，是普通图层**
3. 面板状态区还显示「✓ 已插入」—— **插件自己以为成功了**

其余按钮（刷新文档信息、弹窗打招呼）正常。

---

## 二、根因

问题不在「插入」这个动作，而在 `makeTextLayer()` 里那两段 `batchPlay`。

### 根因 1 —— `make` 造不出文本图层

```js
// 旧写法（错的）
{ _obj: "make", _target: [{ _ref: "layer" }],
  using: { _obj: "layer", name: TEXT, textKey: TEXT } }
```

在 PS 2026 v27.2 上，这个 descriptor **只会建出一个 `layerKind=1` 的普通像素图层**，
`textKey` 被静默忽略。但 `name` 生效了 —— 所以图层名看起来完全正确。

> 这就是为什么它骗过了当时的自检：**自检只比对了图层名**。

### 根因 2 —— 接着对普通层发 `set textLayer`，PS 直接弹框

```js
// 旧写法第二步（错的）
{ _obj: "set",
  _target: [{ _ref: "textLayer", _enum: "ordinal", _value: "targetEnum" }],
  to: { _obj: "textLayer", textKey: TEXT, textStyleRange: [...] } }
```

目标不是文本层 → PS 报「命令"设置"当前不可用。」。

关键在于**这个错误是 Photoshop 自己弹的原生模态框**，不是 JS 异常：
它会**阻塞整个 `executeAsModal` 作用域**，外面的脚本完全看不到进展，只能干等。
（探针第一轮就是这么被卡死的，与用户看到的是同一幕。）

而 `index.js` 里它被 `try/catch` 吞掉了，于是走到了「成功」分支，状态栏显示 ✓。

---

## 三、实测矩阵

不猜，直接让插件当探针（`hello-world/probe-text.js`），在真实 PS 里逐个跑、读回 `layerKind`：

### A 轮 · 谁能造出文本图层

| # | 写法 | `layerKind` | DOM `kind` | 结论 |
|---|---|---|---|---|
| A1 | `make` + `using{layer, name, textKey}`（旧写法） | 1 | pixel | ✗ 普通层 |
| A2 | A1 再加 `layerKind:{_enum:"layerKind",_value:"textLayer"}` | 1 | pixel | ✗ 普通层 |
| A3 | `make` + `using{textLayer, name, textKey}` | 1 | pixel | ✗ 普通层 |
| A4 | **DOM `document.createTextLayer({contents})`** | **3** | **text** | **✓ 文本层** |

三种 batchPlay 写法全军覆没，**只有 DOM 一条路通**。

### B 轮 · 文本层的属性怎么读写（在 A4 造出的真文本层上）

| 探测项 | 实测结果 |
|---|---|
| `textItem` | 存在 |
| `textItem` 的属性 | `characterStyle, paragraphStyle, warpStyle, _parent` |
| `textItem.fontSize` | **不存在**（`undefined`）→ 写它只是加了个野属性，不生效 |
| `textItem.characterStyle.size` | 存在，默认 `12`；写 `72` 后 **PS 回读确认** `{"size":{"_unit":"pointsUnit","_value":72}}` |
| 默认字体 | `AdobeHeitiStd-Regular`（中文版 PS，对 "Hello World" 显示正常） |

## 四、正确写法

```js
async function makeTextLayer() {
  // 1) 造层 —— 必须走 DOM
  const layer = await app.activeDocument.createTextLayer({ contents: TEXT });

  // 2) 字号 —— 挂在 characterStyle 上，不是 textItem 上
  try {
    layer.textItem.characterStyle.size = 72;
  } catch {
    /* 字号没设上不影响图层本身 */
  }

  return layer;
}
```

`createTextLayer({contents})` 会自动把图层名设成内容，所以不用另外传 `name`。

## 五、连带挖出的四个坑

### 坑 1 · 自检假阳性：只比名字，不比类型

旧自检写的是：

```js
const names = Array.from(app.activeDocument.layers).map(l => l.name);
ok = names.indexOf(TEXT) >= 0;      // ← 只查名字
```

于是「叫 Hello World 的普通图层」一路绿灯进了 `boot.log`。
**教训：判据要判到本质属性上。名字是表象，类型才是本质。**

已修正为双条件（`index.js` 的 `selfVerify`）：

```js
ok = named && isTextLayer(info);   // 名字对 **并且** 类型对
```

### 坑 2 · 判据必须对准数据的「实际形态」（本次连踩两次）

| 踩的坑 | 实际形态 | 错误写法导致的后果 |
|---|---|---|
| `layerKind` | batchPlay 出来是**数字** `1` / `3`；DOM 出来是**字符串** `"pixel"` / `"text"` | 第一版拿字符串去匹配数字 → **把唯一正确的 A4 判成 FAIL**（假阴性） |
| `size` | PS 回读是对象 `{"_unit":"pointsUnit","_value":72}` | 第二版按 `/\"size\":72/` 匹配 → **把已经成功的 B 轮又判成失败**（假阴性） |

两次都是**同一种错误**：判据凭想象写，没照抄数据的样子。
修法：判定函数同时接受两种形态（`isTextLayer()`），正则跟着真实返回写。

### 坑 3 · PS 原生错误框会「无声」卡死模态

`batchPlay` 失败时，PS 可能弹**原生模态框**。它不等同于 JS Promise reject：
- 从插件的视角看，`await` 永远不返回
- 从外部脚本的视角看，日志停在某一行再也不动
- 用户只会看到弹窗，不知道后面全卡住了

**排障手法**：本项目新增 `tools/win_dialog.py`，直接枚举 PS 进程的顶层窗口定位卡在哪：

```
python tools/win_dialog.py                # 列出所有顶层窗口
python tools/win_dialog.py 45948 --close PSDialogBox   # 关掉那个对话框（= 点"确定"）
```

实测 `PSDialogBox` 类名就是它。（`--close` 默认不动作，必须显式给类名/标题关键字。）

### 坑 4 · 插件目录是只读的

想给探针加一个「跑完自动摘掉 flag」的收尾，连撞两次：

| 尝试 | 报错 |
|---|---|
| `folder.deleteEntry("probe-text.flag")` | `folder.deleteEntry is not a function` |
| `folder.createFile("probe-text.done")` | `The file uses a storage provider that is read-only.` |

**两个结论**：
- UXP 的 `Folder` **没有** delete 能力
- `getPluginFolder()` 是**只读**存储 —— 插件既不能在自己的目录里建文件，也删不掉文件

**所以文件开关只能由外部（人或 AI）创建/删除**，插件自己是动不了的。
「已经跑过」这类印章只能写到**可写的** `getDataFolder()`（PluginData 目录）。

## 六、环境硬约束速查（可复用）

| 项 | 结论 |
|---|---|
| 造文本图层 | **只能** `app.activeDocument.createTextLayer({contents})`；batchPlay `make`+`textKey` 无效 |
| 文本层判定 | DOM `layer.kind === "text"`；batchPlay `layerKind === 3`（数字） |
| 文字字号 | `layer.textItem.characterStyle.size`（**不是** `textItem.fontSize`） |
| 文字内容 | `layer.textItem.contents` |
| 危险动作 | 在**非**文本层上 `set` 带 `textKey` 的 `textLayer` → PS 弹原生框并卡死模态，**别试** |
| 插件目录 | 只读，不能建文件、不能删文件 |
| 可写目录 | `storage.localFileSystem.getDataFolder()`（PluginData） |

## 七、证据链（三重）

1. **探针**（真 PS、真 API、临时文档）
   `probe  A 轮结束：可用写法 = A4 DOM：document.createTextLayer({contents})`

3. **用户真实点击 + 只读快照**

   `23:51:12  docs  active=HelloWorld.psd  总数=2  顶层=[Hello World:text, 图层 0:pixel]`
   → 用户点出来的第一个图层，类型就是 `text`。
