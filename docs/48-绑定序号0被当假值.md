# 48 · 绑定「序号 0」被当成假值 —— 模板第 1 个图层点不动

> 版本 v0.5.2 ｜ 真机自检 **53/54 连跑两轮（起始状态不同）** ｜ 离线结构回归 **73/73**
> 用户原话：**「模板的第一个图层不能被绑定，点击 UI 不更新。」**

## 一、先看证据：截图把根因钉死了

用户给的截图（`Clipboard_Screenshot.png`）里，5 列绑定的高亮状态是：

| 列 | 高亮的芯片 |
|---|---|
| 课程名称 | **3**. 12345 ← 序号 2 |
| 价格 | **2**. 55332 ← 序号 1 |
| 适用年龄 | **（不绑定）**（红框圈住这行） |
| 开课时间 | **（不绑定）** |
| 备注 | **（不绑定）** |

警告行 = 「有 3 列没绑定（适用年龄 / 开课时间 / 备注）」⇒ 已绑 2 列。

**关键**：序号 **1**、**2** 都绑上了，只有序号 **0** 绑不上 —— 不是"模板认错了"，也不是"层不存在"，
而是**序号 0 在代码里被当成了"假值"**。

## 二、根因：`if (v)` 把序号 0 判成了"没绑"

`tools/table.js` 里两处绑定控件的回调（**绑定表** + **列抽屉**）都是：

```js
if (!S.bind) S.bind = {};
if (v) S.bind[c] = v; else delete S.bind[c];   // 🔴 v = 0（模板里第 1 个文字层）是**合法值**
```

`v = 0` ⇒ `if (0)` 为假 ⇒ 走 `delete` ⇒ 什么都没发生 ⇒ 重渲染后高亮回到「（不绑定）」
⇒ 用户看到的就是「点了没反应」。

⚠️ 这条纪律 **`lib/batch.js` 里已经修过一次**（v0.5.0：`if (!v)` 把 0 当"没绑"，被离线断言当场抓出），
但**面板这一层漏了** —— 同一份状态有**两个入口**，纪律只落在了一处。

**同族**：`lib/batch.js` 里那个判"没绑"的函数叫 `bound(c)`，语义却是**"没绑"**
（`if (bound(c)) continue;` 读起来正好相反）⇒ 一并改名为 `isUnbound(c)`。

## 三、改了什么

| 位置 | 改动 |
|---|---|
| `tools/table.js` | 新增 `setBind(col, v)` —— **面板里唯一的绑定写入口**，显式判空（`""/undefined/null` 才算不绑定）；绑定表与列抽屉两个回调都改成调它 |
| `lib/batch.js` | `bound(c)` → **`isUnbound(c)`**（名字与语义对齐）；补注释写明"0 是合法序号" |
| `lib/selfcheck.js` | 新增 **S49**（真机） |
| `tools/offline-smoke.cjs` | 新增 **22h-6**（行为）+ **22h-7**（源码守卫，带负对照） |

## 六、方法学

- 🔴 **同一份状态有多个入口时，纪律必须收成"唯一写入口"** —— 这次两个绑定控件各写一遍，
  修了 `batch.js` 却漏了面板。抽出 `setBind()` 后，**下次只可能改一处**。
- **`0` 是合法值**这条坑在本项目已经出现过两次（v0.5.0 的 `lib/batch.js`、本轮的 `tools/table.js`）
  ⇒ 凡是"序号/索引/计数"的判空，一律**显式比 `""/undefined/null`**，不用真值判断。
- **判"没绑"的函数别叫 `bound`** —— 名字与语义相反是上一代 bug 的温床（见 `docs/42`/`docs/47` 同族）。
