**两条打包路都能产出等价且合规的包**：

| 方式 | 命令 | 说明 |
|---|---|---|
| 官方 UDT | `node node_modules/@adobe-fixed-uxp/uxp-devtools-cli/dist/uxp.js plugin package --manifest vellum-toolbox/manifest.json --outputPath dist` | Adobe 推荐路径；需要 UDT service 在跑 |
| 自研（离线） | `node tools/build-ccx.cjs` | 不依赖 service；有排除规则与回读校验 |

### 🔴 本期修掉的一个**发布级缺陷**：`host` 必须是对象

Adobe《Package a Plugin》明文：

> UXP plugin .ccx installers can target **only one host application at a time**; the `host` property in
> `manifest.json` **must be a single object** … Only **during development**, for convenience, you can
> assign to the host property an **array**.

我们的源 `manifest.json` 用的是**数组**（开发态合法）⇒ 之前 `build-ccx.cjs` 直接把它打进包里
⇒ 那个包**不是发布口径**。现已在 `build-ccx.cjs` 里补上"**包内**把数组转成第一个对象"
（源文件保持数组，不影响开发态加载），并独立复验过。

> 顺带澄清一个一直悬着的疑虑：**UXP 的 `.ccx` 不需要数字签名**。
> Adobe 文档：「UXP uses .ccx, which **does not require a package-level digital signature or timestamp**」
> （那是 CEP 时代 `.zxp` 的要求）⇒ 不需要 ZXPSignCmd、不需要证书。✅

## 二、⚠️ 前置条件：目标机器必须有 Creative Cloud Desktop

`.ccx` 由 **UPIA（Unified Plugin Installer Agent）** 安装，而 UPIA **随 Creative Cloud Desktop 分发**
（不能单独下载）。检查路径：

```
C:\Program Files\Common Files\Adobe\Adobe Desktop Common\RemoteComponents\UPI\UnifiedPluginInstallerAgent\
```

🔴 **本开发机上这个目录不存在** —— 也就是说**这台机器装不了 ccx**（一直以来都是靠 UDT
开发态加载）。要装正式版，目标机器需要：
1. 有 **Creative Cloud Desktop**
2. **正常版 Photoshop 装好、且至少启动过一次**（只有 Beta 会被判"no compatible app"）

**安装方法**（二选一）：

- 双击 `.ccx` → 交给 Creative Cloud Desktop 确认安装；
- 命令行（适合批量/静默）：
  ```
  cd "C:\Program Files\Common Files\Adobe\Adobe Desktop Common\RemoteComponents\UPI\UnifiedPluginInstallerAgent"
  UnifiedPluginInstallerAgent.exe /install "D:\ps-uxp-dev\dist\com.vellum.toolbox_PS.ccx"
  ```
- 装完**重启 Photoshop**；面板在 **插件（Plugins）菜单**里。
- 卸载：`UnifiedPluginInstallerAgent.exe /remove com.vellum.toolbox`
  （或 CCD → 管理插件 → ⋯ → 卸载）

## 三、🔴 装上正式版后**必须知道的三件事**

### 1. 插件的 PluginData 路径会变（**这条会影响 VellumDesk 联动**）

| 安装方式 | 数据目录 |
|---|---|
| 开发态（UDT 加载，现状） | `…\Adobe\UXP\PluginsStorage\PHSP\27\**Developer**\com.vellum.toolbox\PluginData\` |
| **正式安装（.ccx）** | `…\Adobe\UXP\PluginsStorage\PHSP\27\**External**\com.vellum.toolbox\PluginData\` |

（来源：Adobe InDesign UXP 文档的官列表述 + 本机 `PluginsStorage\PHSP\27\` 下确实存在
`Developer` / `Internal` / `Shared` 三个区，`Internal` 里是 Adobe 自家插件。）

⚠️ **而 VellumDesk 是写死 `Developer` 去找镜像的**（`handoff` 与镜像同目录）⇒
**装上正式版后，素材库会读不到任何东西**（镜像写到了旧位置/新位置对不上）。

⇒ 已向软件侧提需求（`LINK-LOG`）：**不要写死区名**，改成按
`PluginsStorage\PHSP\<ver>\*\com.vellum.toolbox\PluginData\library\` **通配搜索**，
或至少在 `Developer` / `External` 两个候选里都试一遍。

### 2. 数据不会继承

新目录 = 空 ⇒ 调色板的「我的颜色」、`library-pref.json`（上次看的库/落点）会**重置**。
（无害，会自己重建；但用户会看到"我的颜色空了"，先告知。）

### 3. 可能与开发态那份**并存**

开发态加载的是 `Developer` 区、正式装的是 `External` 区 —— 两份互不相干，PS 的插件菜单里
**可能同时列出两个「Vellum 工具箱」**（两个面板、两套数据）。

⇒ **建议**：装正式版之前，先在 UDT 里把开发态那份 `Unload` 掉（或 `uxp.js plugin unload`）。

## 四、发布形态（两种，按需要选）

| 形态 | 需要什么 | 适合 |
|---|---|---|
| **独立 `.ccx`**（本期交付的） | 一个文件，发给对方双击 | 内部/同事自己装 ✅ **推荐** |
| 上架 **Adobe  Marketplace** | 开发者账号 + 在 Developer Distribution 门户建 listing，把门户生成的 **插件 ID 抄回 manifest**（ID 不匹配会导致打包校验失败）；开发期用单独的稳定 ID | 对外公开发布（还涉及审核与分成，成本高得多） |

⚠️ 上架那条路的 ID 必须与门户一致 —— 我们现在用的是自己定的 `com.vellum.toolbox`，
**如果将来要上架，不能沿用这个 ID**（会被判无权限），要另起一个。
