# 14 · 方向 B「Native Pro」落地评审（本轮范围：外壳 + 调色板）

> **状态**：评审完成 —— **待用户决定是否进入实现**
> **评审对象**：
> - `design-demos/B-native-pro.html` —— 可交互版（5 屏）
> - `design-demos/B-native-pro-spec.html` —— 静态展示版（13 屏，含自带的「落地边界」一节）
> **本轮范围**：只做 **第 1 屏「功能选择」（= 外壳）+ 第 3 屏「调色板」**
> **结论（先说）**：**可以做，本轮没有「写不出来」的硬伤。**
> 需接受 **3 条 P0 换写法 + 5 条 P1 视觉降级**；另有 **4 项待实测**、**1 条 spec 低估需纠正**、**3 个设计决策待拍板**。

---

## 一、为什么判断「能做」（支撑面）

这套稿子全是 HTML + CSS + DOM 事件，**没有依赖任何 UXP 拿不到的能力**（无 Canvas / 无 WebView / 无网络）。
逐项核对下来，主力手法都在支持范围内：

| demo 用了 | UXP | 备注 |
|---|---|---|
| flexbox（含 `gap`）、`overflow` 滚动、`border-radius`、`z-index` | ✅ | `border-radius` 已由现有插件实证 |
| CSS 变量（`--panel` / `--c` 等）、`calc()` | ✅ | 令牌化的基础，正好接 `docs/13` |
| `:hover` / `:active` / `.is-on` 类切换状态 | ✅ | 无过渡，但状态本身生效 |
| **内联 SVG 图标**（`ICONS` 里 20 个 16×16 线条图标）| ✅ | 官方原话：UXP 的 SVG 渲染器**就是面向简单图标**的，正好匹配 |
| 系统字体栈（`Segoe UI` / `PingFang SC` / `微软雅黑`）| ✅ | 本来就用不了 `@font-face`，方向一致 |
| `innerHTML` 注入 | ✅（有保留） | 官方：Photoshop 里可用，但「不要依赖」；图标 SVG 简单，风险可控 |
| 纯 DOM 交互（点击 / hover / 右键菜单 / toast）| ✅ | 我们的**合成点击自检**能覆盖这一层 |

**没有 `position:fixed`、没有 Canvas、没有 data-URI 图片（logo 除外）** —— 这几条是最大的雷，正好都没踩。

## 二、P0 · 必须换写法（不改就写不出来）

| # | demo 用法 | 出现在 | 换成 |
|---|---|---|---|
| 1 | `display:grid` + `grid-template-columns:repeat(3\|4,1fr)` | **调色板**的品牌色 3 列 / 我的颜色 4 列网格 | `flex-wrap` + 百分比宽度（`flex:1 1 33.333%` / `25%`），最稳 |
| 2 | `display:grid` + `place-items:center` | **外壳**的返回键 / 图标按钮 / 导航项图标底 / 序号徽标 | flex 居中（一行改，量最大但机械）|
| 3 | `position:sticky` | 素材库筛选条 / 表格底栏 | **本轮用不到** —— 我们的外壳顶栏本来就是 `flex:none`，比 sticky 更稳 |

> spec 的 P0 已列全 1 与 3，与本表一致；**第 2 条是我补的**（它只提了「色块网格」的 grid，没提这些「纯居中」用途也是 grid）。

## 三、P1 · 视觉降级（能跑，观感打折）

| # | demo 用法 | 丢什么 | 应对 |
|---|---|---|---|
| 1 | `transition`（导航项 / 卡片 / 开关 / toast）| hover 的 0.1s 渐变 | 变瞬变 —— 与 `docs/13` 法则 L1 一致 |
| 2 | `box-shadow` | ⚠️ **见下方纠正** | 用 `outline` / 双层描边模拟 |
| 3 | `transform:translate(-50%)`（气泡、右键菜单）| 自动居中 | 绝对定位 + 手算坐标 |
| 4 | `::-webkit-scrollbar` 自绘滚动条 | 细滚动条 | 用系统滚动条 |
| 5 | `text-transform:uppercase` | 英文小标题大写 | 手写大写（**中文标签无影响**）|

### ⚠️ 纠正 spec 的一处低估：`box-shadow` 不是「可接受降级」

spec 写：「投影只用在浮层和面板外框，**去掉不影响识别**」。

**但对调色板不成立。** 调色板里色块的 hover 与选中态，**唯一载体就是 `box-shadow`**：

```css
.sw:hover { box-shadow: 0 0 0 1px #fff, 0 0 0 2px var(--ac); }   /* 白内环 + 蓝外环 */
```

去掉阴影 = **色块的 hover / 选中反馈直接消失**。而调色板正是本轮要做的一屏。→ 这不是降级，是**必须给替代方案**。

**更关键的一点（spec 没提）**：`box-shadow` 与 `transform` 虽可开 `featureFlags.CSSNextSupport` 解锁，
但该标志**自 PS 26.0 / UXP 8.0.1 才有** —— 本项目 `minVersion` 是 **25.0.0（PS 2024）**。
→ **在 PS 2024 上，开不开这个 flag 都拿不到 `box-shadow`。**
→ **所以不能把方案压在 flag 上，必须走描边替代（`outline` 或双层容器）。**

### 🔴 我还发现一条 spec 说「不受影响」但实际有版本门槛的：`linear-gradient`

spec 把 `linear-gradient` 列进了「不受影响」。但官方 Changelog 明确：**`linear-gradient` 自 UXP 8.1 / PS 26.1 才支持**。
→ 在 **PS 2024（UXP 7.2–7.4）上不生效**。本 demo 有三处用到：

| 用处 | 失效后 |
|---|---|
| `.app::before` 顶部 2px 品牌渐变条 | 顶条消失或变实色 |
| `.primary` 主按钮的竖向渐变 | 退化为纯色按钮（可接受）|
| `.tbl-foot` 底栏渐隐（M3）| 需要纯色分隔线替代 |

→ **对策：渐变只当"锦上添花"，全部准备纯色回退。** 这条会进 `docs/12` 的「最低可用版本」表。

## 四、待实测（4 项 —— 我在纸上无法拍板的）

| # | 测什么 | 为什么重要 | 不支持的后果 |
|---|---|---|---|
| 1 | **`letter-spacing`** | 这套「Pro 感」大量依赖 `.06em` / `.04em` 字距；**官方支持清单里没有它** | 很可能**静默忽略** → 小标题的精致感整体下降 |
| 2 | **`outline`** | 决定 P1 里 `box-shadow` 的替代方案能否落地 | 若也不行 → 只能用「外层容器 + 1px 边框」模拟双环 |
| 3 | **`innerHTML` 注入 `<svg>`** | demo 的图标系统全靠 `innerHTML = ICONS[...]` | 若失败 → 改 `createElementNS` 或把图标写死进 HTML |
| 4 | **`@media (min-width)` / 面板缩放表现** | 若可用，「窄面板自适应」不必写 JS | 若不可用 → 只能靠 `flex-wrap` 或 `ResizeObserver`(26.1+) |

> 这 4 项**能合并进现有 `env-check`** 一次跑完（约 10 分钟工作量）。
> 顺手还能测：flex `gap`、`opacity` 过渡（预期无效）、`background-image: linear-gradient()`。

## 五、本轮不涉及、但要知道的坑（M2 / M3）

- **素材库那 12 张「纯 CSS 缩略图」在 UXP 基本全废**：`mix-blend-mode`、`backdrop-filter`、`clip-path`、
  `radial-gradient`、`repeating-linear-gradient`、`data:` URI 纹理 —— **一个都不支持**。
  → M2 的缩略图要么用真图，要么用 Canvas 生成位图（Windows 上 Canvas 渐变 API 也有坑）。
- **⚠️ 但它也渗进了外壳**：首页每个导航行右侧的 `.ni-preview`（4 张小缩略图）用的就是这些纹理。
  → **本轮必须改成纯色小方块**（调色板那行的本来就是纯色，口径统一，可行）。
- `.hero-mark`（顶部 logo）是 **base64 PNG** → 换内联 SVG，顺带解决 `devicePixelRatio = 1` 的糊。
- `@media (max-width)` 之类的**宽度媒体查询**在本 demo 里没有用，所以不影响；但真实面板会连续缩放。

## 六、待拍板的 3 个设计决策

### 6.1 固定深色 vs 跟随 PS 主题（**与 `docs/13` 已定项冲突**）

demo 的配色是**硬编码固定深色**（`--panel:#323232`、`--bar:#2b2b2b`…），
而我们上一轮定的是**跟随 PS 主题自适应**。二选一：

| 方案 | 好处 | 代价 |
|---|---|---|
| **A. 令牌化，深浅两套** | 保住视觉语言，且融进深浅两种 PS | 浅色主题下「发丝线 + 低对比灰阶」要重调；工作量约 +30% |
| **B. 固定深色** | 实现最简单，与 demo 100% 一致 | 浅色 PS 里会是个「黑块」，可能显得突兀 |

### 6.2 中文字号（真实观感风险）

demo 大量用 **9.5 / 10 / 10.5px** 承载中文标签（导航描述、色值、提示行…）。
UXP + Windows 下中文 10px 会糊；我们 `docs/13` 的法则写的是「中文不低于 11px」。
→ 要么整体上调 1px（行高会更松，密度感略降），要么接受糊。

### 6.3 面板尺寸基准

demo 画布是 **440 × 764**；我们当前 `preferredDockedSize` **300×520** / `preferredFloatingSize` **380×560**。
→ 是否把基准改到 440 × 760？（`minimumSize` 仍保持 240×300 以便窄停靠）

## 七、我的建议

1. **方向 B 值得做。** 它的视觉语言（发丝线、紧凑行、小字号、行内快捷键）与 Photoshop 面板调性最贴，
   且**控件映射路径清晰**（搜索→`sp-textfield`、开关→`sp-checkbox`、主操作→自写按钮）。
2. **但先跑探针再落 CSS。** 上面 4 项待实测里，`letter-spacing` 与 `outline` **直接决定这版视觉成不成立**。
   先花 10 分钟把探针并进 `env-check` 拿到真机结论，否则可能写完一整版 CSS 才发现要回炉。
3. **范围收敛到 2 屏**：第 1 屏「功能选择」（外壳）+ 第 3 屏「调色板」—— 与用户说的本轮范围一致。
   素材库 / 表格 / MCP 三屏**不入本轮**（它们的坑更多，见 §五）。
4. **`minVersion` 保持 25.0.0**，因此：不开 `CSSNextSupport`、渐变只做增强、`box-shadow` 一律走描边替代。
