# 18 · 「填充不能用」归因 + 内容图层改色（v0.2.3）

> 2026-10-10 · 第 13 次会话

## §一 用户原话

> **填充不能用**

附截图：PS 弹出错误框 ——

```
Adobe Photoshop
vellum_toolbox: 命令"填充"当前不可用。
                                  [确定]
```

这里有个容易误读的点：**`命令"填充"当前不可用` 不是我们写的文案**。
我们的文案里没有"填充"这两个字单独出现（我们的命令名是
`Vellum 工具箱：品牌主色 → 填充当前图层/选区`）。
这句话是 **PS 自己**在说它的 `Fill` 命令（`_obj:"fill"` 的中文名就是"填充"）被拒了。

> 因此那个 PS 弹框就是我们的 `fill` 命令引发的，不是别的路径。

## §三 归因：形状图层是**内容图层**，PS 的「填充」对它们本来就不可用

两条外部事实交叉验证：

**① Adobe 论坛官方人员（simonhenke）原话：**

> **Vector layers are actually solid color layers (with vector masks)**

也就是说 —— **形状图层在 UXP 里的 `kind` 就是 `solidColor`**，
和「纯色填充图层」是同一个内容类型（`solidColorLayer`）。

**② 形状 / 纯色填充 / 渐变 / 图案都属于「内容图层」（contentLayer）：**

它们的像素是**由参数算出来的**，不是画上去的。PS 菜单里的「编辑 › 填充」
对这类图层不可用 —— 这正是那句 `命令"填充"当前不可用` 的来源。

### 为什么 v0.2.2 的像素判据没有提前拦住它

**它拦住了，只是拦住之后我们没把话说给用户听。**

v0.2.2 已经用 `verify:"change"`（像素必须有变化）判出了 `ok=false`，
`attempts` 里也写明了"像素无变化"。但：

- 失败原因**只写进了 boot.log**；
- 面板状态行虽然调了 `ctx.setStatus("✗ 填充失败：" + res.error)`，
  但当时的 `error` 文案是含糊的「可能是该图层类型不支持填充（文字/调整/被锁定的图层）」；
- 而且 PS 还**额外弹了一个框**抢走了全部注意力。

结果就是用户看到的是「PS 弹了个看不懂的框」，而不是「面板告诉我为什么」。

> **教训（记进 DECISIONS）**：判据正确 ≠ 反馈正确。
> 判据错了会造成假阳性；**判据对了但结果没送到用户眼前，等于没有判据**。

## §四 修法

### 4.1 按 `layer.kind` 分派命令（`lib/ps.js`）

```
pixel / background / smartObject   → 像素族 → `fill`（= 编辑›填充，尊重选区）
solidColor / gradientFill / patternFill → 内容族 → `set` 改内容图层的颜色
text                                → 前置拒绝（明确说"文字图层暂不支持"）
调整图层 / 组 / 3D / 视频           → 前置拒绝（说清是什么类型）
kind 读不出来                       → 只走内容族，**不拿 fill 去赌**
```

**铁律：内容族绝不退到 `fill`。** 那正是弹框的来源，而且它「不报错 + 不改像素」，
比直接失败更难排查。

### 4.2 内容图层改色写**两条**描述符，按序试

形状图层的填色到底存在哪，有两种说法，两边都有实物出处：

| 变体 | 写法 | 出处 |
|---|---|---|
| **A** | `to: { _obj:"solidColorLayer", color:{ RGBColor } }` | Adobe 论坛 / 经典 ActionManager 写法 |
| **B** | `to: { _obj:"shapeStyle", fillContents:{ _obj:"solidColorLayer", color:{ RGBColor } } }` | Adobe 社区 2024 年"形状填充/描边互换"脚本 |

我没有真机证据判断 PS 27.2 认哪一条（**形状图层没法在自检里凭空造出来**），
所以**两条按序试 + 像素回读判据**，让真机自己告诉我们哪条生效（日志里的 `via=contentColorA/B`）。

这比赌一条诚实，也不会出现"命令没报错就当成功"。

### 4.3 前置拒绝要在**发命令之前**做完

锁定图层 / 文字图层 / 调整图层 / 组 —— 这些在本地就能判掉，
**一条 PS 命令都不发**，自然也就不会有 PS 弹框。

### 4.4 失败原因必须露在面板上

`tools/palette.js fillHex()` 的失败分支改成给**可操作**的原因，例如：

```
✗ 填充失败：「锁定层」被完全锁定 —— 请点图层缩览图上方的小锁，取消「锁定全部」再试
✗ 填充失败：「标题」是文字图层，暂时不支持填充（计划中）。现在可以：右键图层 › 栅格化文字，或改用「设为前景色」+ Alt+Backspace
```

成功时也按族换说法：内容族说「已把「矩形 1」的**颜色改为** #XXX」——
因为那确实不是往像素上刷颜色，别让用户以为没干活。

## §八 ⚠️ S17 真机结果回来了：**假设对了一半，改色没生效**（2026-10-10 18:54）

用户重载插件后 S17 跑到了真机，`boot.log`：

```
selfcheck FAIL S17 内容图层（形状/纯色填充）改色 —— kind 判定 + 改色命中
  ::  kind=solidColor（期望 solidColor）
      family=content（期望 content）
      建层色=#202020 → 回读 #202020 ✓
      目标=#E60012
      命中路径=contentColorB
      像素回读=未命中
      attempts=[contentColorA=已执行/像素无变化  contentColorB=已执行/像素无变化]
```

**一半对，一半不对**：

| 结论 | 状态 |
|---|---|
| 内容图层的 `kind` 确实是 `solidColor` → `classifyLayer()` 的分派前提 | ✅ **真机证实** |
| `makeSolidColorLayer()` 能造出纯色填充图层、能正确回读 | ✅ **真机证实** |
| 两条改色描述符能让像素变化 | ❌ **都不生效**（都是"已执行/像素无变化"） |
| 前置拒绝那套（锁定 / 文字 / 调整层） | ✅ 真机日志也验证了：`family=text kind=text → preflight=拒绝(family=text)`（19:02 那次是文字图层，面板给出了可读原因） |
| 像素族 `fill` 仍然正常 | ✅ 真机日志：`family=raster kind=pixel ... 像素命中`（`doc="HelloWorld.psd"`，19:02:55） |

**所以 `docs/18` 的修法只完成了一半**：

- ✅ **"按 kind 分派 + 前置拒绝 + 失败可见"** 这部分是成立的、可用的；
- ❌ **"内容族改色"这条命令还没写对** —— `contentColorA`（`to:{solidColorLayer,color}`）
  与 `contentColorB`（`to:{shapeStyle,fillContents:{…}}`）在 PS 27.2 上**都被接受但不产生效果**。

**下一步该怎么查**（这条比结论本身更重要）：
`set` 命令"接受但不生效"说明描述符形状不对，而**猜是没用的** —— 正确做法是
**用 Alchemist / Script Listener 录一次"手动改形状填充色"的真实 actionJSON**，照着抄。
而这正是 `docs/20` 里那件事（打通 PS MCP / 让 AI 能直接驱动 PS）**真正的价值所在**：
有了那条通道，我就能在真机上**试一条、读一次像素**，而不是靠推测堆描述符。

> 已如实标注：**形状图层本身的改色仍未解决**（S17 用的是同族的纯色填充图层，
> 且它也已经证明"改色不生效"）。用户报的「填充不能用」在**像素族上已经好了**，
