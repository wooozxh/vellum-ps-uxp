## 一、这一轮把 M3a 做成了什么

用户拍板 **A（列绑定到自己 PSD 的版式图层）+ ②（生成表格 / 批量出稿 并列两个按钮）**，
UI 采「**方向 2 工作台为骨架 + 方向 3 的『点列头 → 列抽屉』**」。

落地的四个文件：

| 文件 | 是什么 | 能不能离线验 |
|---|---|---|
| `lib/gbk-table.js` | GBK→Unicode 平面表（23,940 槽位，由 `tools/gen-gbk-table.py` 生成，**不要手改**） | ✅ 穷举 |
| `lib/csv.js` | **自己解码 + 自己解析**：严格 UTF-8 / GBK 查表 / `encodeUtf8` / CSV 状态机 / `readBytes` | ✅ 纯逻辑 |
| `lib/table.js` | **纯函数布局**：列宽 → 每格文字框 / 每条线 / 每块背景 / 层数 / 上限闸门 | ✅ 纯逻辑 |
| `lib/ps.js` | `buildTable()`：把计划落进文档（**两阶段、全已验原语**） | ⚠️ 只能离线验**命令形状** |
| `tools/table.js` | 面板（工作台骨架 + 列抽屉 + 三个折叠块 + 底部双动作常驻） | ⚠️ 离线验结构、真机验几何（S41） |

数据流：

```
CSV 文件 →（read({format:binary}) 拿字节）→（BOM/UTF-8 严格校验/GBK 查表）→ 文本
        →（CSV 状态机，含引号内逗号/换行/双引号转义）→ 行×列
        →（normalizeRows 归一化：列数对齐、空串标记）→ 计划 layoutTable()
        →（一次 batchPlay 建层 + 同一 modal 内逐格改名/对齐）→ PS 文档里的图层组
```

## 二、🔴 一次卡死宿主的返工（这一节是全文最该读的）

### 2.1 出了什么事

v0.4.0 把**两处"没有官方样例、只有我推理"的加法**直接塞进主链路：
① `make textLayer` 的 `using.name`；② `using.paragraphStyleRange`；
然后 **~20 条命令一次 `batchPlay` 发完**。真机结果：

- 自检 **18:22:48 启动，18:23:01 之后再没有任何输出**（PS 内存 1.65G → 2.28G）
- 随后的 `plugin load` 报 **`Check the host application ... busy or in a modal state`**
  ⇒ **PS 进了模态出不来，只能人工去点掉那个对话框**（用户反馈弹窗像"命令…"）

根因：**一条命令让 PS 弹模态框 ⇒ `executeAsModal` 永远等不到返回 ⇒ 整个插件陪葬。**
（连"重新加载插件"这条命令都不通，所以**没有任何自愈路径**。）

### 2.2 我第一次的定位是错的，这里更正

我最初写的是"卡在**素材库**那一段"，依据是日志最后一行是 `tool open=assets`。
**这个推论不成立** —— 对照 17:53 那轮成功记录，`tool open=assets` **同样是 `DONE` 之前的最后一行**
（探针期间**不打点**，最后才一起刷出报告）。所以日志只能把卡点定位到
**`tool open=assets` 之后的静默区** = assets 界面探针 + **S31–S40**。

而 `18:22:48` 那一轮，**恰好是 S40 第一次上机**（S40 是 v0.4.0 新增的）。
⇒ 根因仍指向"新增的未验证描述符"，但**不能**说"卡在素材库"。
教训：**日志的"最后一行"只对"每步都打点"的流程有定位力**；不打点的段落里，只能圈范围、不能点名。

### 2.3 返工口径：只用已验原语

| 要做的事 | v0.4.0 的写法（未验） | v0.4.1 的写法（**已验**） | 证据 |
|---|---|---|---|
| 建形状图层 | `fillEnabled:false` + `strokeEnabled:true`（外框"只描边"） | **外框拆成 4 条细矩形**，与内线同一种描述符 | S31 |
| 建文字图层 | 塞 `name` + `paragraphStyleRange` | 只带 `textKey` + `textShape` + `textStyleRange` | S32 |
| 图层名 | 描述符里给 | 建完走 **DOM `layer.name`** | S29 |
| 选层 | —— | **DOM `doc.activeLayers = [layer]`** | S33 |
| 对齐 | 描述符里给 | AM `set _property:"paragraphStyle"` | S37（left/center/right 三档） |
| 组名 | —— | `make layerSection` 的 `name` | S33 |

⚠️ 另外两条纪律（写进 `MEMORY.md`）：

1. **新描述符一次只验一条，且单条发** —— 绝不与其它未验项一起塞进批量。
2. **自检（探针）自己也会把宿主卡死** —— 探针里出现未验描述符时，先写"只发一条命令"的小探针。
3. 本轮的工程化补救：`buildTable()` 里加了**分阶段日志**（`m3 build 开始 / ①批发完 / ②批开始 / 完成`）
   —— 万一下次再卡，**日志的最后一条就是分野线**（是卡在"发命令"还是"逐格改名"）。

### 2.4 为什么"外框 4 条"这个换成

一条"只描边不填充"的矩形需要 `fillEnabled:false` + `strokeEnabled:true` 这个**组合**，
而 S31 验过的是 `fillEnabled:true` + `strokeEnabled:false`。**没验过的组合一律不发**。
代价：外框从 1 层变 4 层（5×6 的表：40 层 → **51 层**）。
换来的是**零未验描述符** —— 值。
⇒ 连带后果：**圆角外框暂不生效**（那条描述符同样没验过），用户在样式里给了圆角会**如实出警告**、不静默降级。

## 三、离线：命令形状断言（发出去之前先钉死）

**这是本轮最有价值的机制**：真机的 `batchPlay` 是"黑盒 + 会把宿主卡死"，
所以描述符的形状必须在**离线**拦住。`tools/offline-smoke.cjs` 现在会**记录整批命令**
（`sentBatches`）并断言（新增 5 条 + 2 条）：

| # | 断言 | 判据 |
|---|---|---|
| ① | 形状命令只有 S31 验过的那一种 | 每条都是 `contentLayer` + `shape:rectangle` + `fillEnabled:true` + `strokeEnabled:false` |
| ② | 文字命令**不带** `name` / `paragraphStyleRange` | 5×6 表 35 条文字命令，带未验键的 0 条 |
| ③ | **命令条数 = 计划层数** | 多一条少一条都算错（5×6 表：18 条样例 / 51 条真实） |
| ④ | 逐格改名**顺序** | 组内第 0 个 = **最后**建的那格（`kids.reverse()` 反了就是整表串格，真机上极难查） |
| ⑤ | **负对照** | 人工塞 `using.name` → ① 的判据**必须命中**（判据提成具名函数复用，不是自证自己） |
| 22b | 表格生成已注册 | `registry.tools` 里有 + `ready` + **首页第 3 行可点** + `planned` 只剩 `mcp` |
| 22c | 表格面板**离线挂得起** | `mount()` 不抛异常 + S41 要量的 13 个选择器全在 |

🟡 我自己在这 5 条里踩了一个坑：阶段二是**每格一发** `batchPlay`（各有各的小 batch），
第一版只看了 `sentBatches[1]` ⇒ 漏掉后面 7 格，报"对齐命令 1/8 条"。**要 `slice(1)` 合并后再筛。**

## 四、真机读数

### 4.1 S40 生成表格端到端（新增，M3a 的核心）

```
PASS  S40 生成表格端到端 —— CSV 解析 → 布局 → 落地（层数/组/文字/图层名/对齐/线条取色）
 ① CSV=解析对（含字段内逗号与双引号转义）
 ② 层数=23/23 ✓（组 1 个，名字命中=true）
 ③ 文字="含\"引号\""（须 "含\"引号\""）✓
 ④ 图层名="文字 R3C3 含\"引号\""（须 同上）✓
 ⑤ 对齐=center（须 center）✓
 ⑥ 阶段二（DOM 改名 + AM 对齐）=12/12 改名 · 12/12 对齐 ✓
 ⑦ 线条取色=#4A4A4A（须 #4A4A4A，±25）✓
```

七项**全部读回命中**（不是"命令没报错"）。两条本轮才有的结论：

- **`kind` = 内容图层（矢量）**，不是 pixel ⇒ "可继续编辑"成立（表格线是真矢量形状层）。
- **图层名与对齐都由"已验原语"落地**：建层描述符保持 S32 的形状，名字走 DOM、对齐走 AM
  —— 代价是阶段二多一次循环，收益是**零未验描述符**。

### 4.2 S41 表格面板真机挂载（新增）

```
PASS  S41 表格面板真机挂载 —— 真实 mount 路径 + 关键控件几何 + 折叠块能点开
 挂载到 #vt-tbl=420×613px
 常显控件 13 个：缺 0、零几何 0
 折叠块点标题：g1 展开→内容 215px ／ g2 展开→内容 164px ／ g3 展开→内容 91px
 块内控件（展开后量）2 个：零几何 0
```

🟡 **S41 的第一次运行 FAIL 了，被判据自己的 bug**：它报 `vt-tbl-styletabs` 零几何（0×0）。
真相是那个控件躺在**默认收起的「样式」折叠块**里（`.tbl-grp.closed .tbl-gb{display:none}`）
⇒ **隐藏元素量出来当然是 0×0，那是"没显示"、不是"没渲染"**。
**判据的第二层**：量几何之前必须先确认**元素可见** —— 所以 S41 改成
"先量常显控件 → 再逐个**点开折叠块** → 展开后量块内控件"（顺带把"自绘控件点不点得动"一起验了）。
