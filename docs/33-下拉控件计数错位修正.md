# 33 · 下拉控件里「计数/箭头」比文字高一点（v0.3.7）

> 输入（用户）："素材库功能下的**所有下拉菜单控件**，文字旁边的**数字都会高一点**"（附图：`全部子类 1 ▾`）。

---

## 一、根因：`vertical-align: top` 对"纯文本"与"inline-block"是两个意思

触发条里原本有三个片段，注释还写着"一律 `vertical-align: top` 就能对齐"：

| 片段 | 原本的盒子 | `vertical-align: top` 的实际含义 |
|---|---|---|
| `.fs-t`（名称，截断用） | **inline-block** | 它的**盒子顶**贴行盒顶 ⇒ 盒内文字**垂直居中** ✓ |
| `.fs-n`（计数 "1"） | **纯文本** | 把**内容区顶**贴行盒顶 —— 内容区只有 ~13px、行盒 20px ⇒ 比居中位置**高约 3px** ✗ |
| `.fs-cv`（箭头 "▾"） | 纯文本 | 同上 ✗ |

**关键区别**：`top` 对齐的是"元素自己那个盒子的顶"，而"纯文本"没有盒子 ——
它对齐的是**内容区**（≈ font-size × 1.2）的顶。内容区比行盒矮，于是它被顶得更靠上。

⇒ 混用两种盒模型 = 用户看到的那 ~3px 错位。

> 旧注释那句"三个片段一律 vertical-align: top 就不会错位"是**错的**：
> 它只保证了"顶对齐"这个动作一致，没保证"被对齐的那个顶"是同一个东西。

## 二、修法：让三个片段用**同一套盒子语义**

```css
.fsel .fs-n,
.fsel .fs-cv {
  display: inline-block;   /* ← 变成有盒子的元素，top 的含义才和 .fs-t 一致 */
  height: 20px;            /* ← 与行盒等高（.fsel 的 line-height 是 20px） */
  line-height: 20px;
  vertical-align: top;
}
```

改完三者都是"20px 高、盒内文字居中、盒子顶对齐行盒顶"⇒ **视觉上必然齐平**。

## 四、可复用的结论

**在 UXP 里做"一行内多个片段并排"时，要么全是 inline-block、要么全用文本基线对齐，别混。**
只要有一个是 inline-block 而另一个是纯文本，`vertical-align: top` / `middle` 的落点就会差几像素，
而且**原因藏在"有没有盒子"这件事上，不在数值上** —— 调 margin 是治不好的。

（这条与 `docs/16` 里那条"基线不一致导致三个片段高低错位"是**同一族问题的下半段**：
那次把 `.fs-t` 做成了 inline-block，这次是漏了另外两个。）
