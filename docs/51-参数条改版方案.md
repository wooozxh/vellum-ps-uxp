## 三、设计（第 1–3 条）

### 3.1 主题判定（第 1 条）

```
取样区 = 图片区**最下面一条全宽横带**，高度 = max(条高, 图片高 × 8%)
         （在原画布上取，即"参数条将要贴上去的那一带"）
用 sampleRectAvgColor(取样区, {composite:true}) 拿平均色 → 相对亮度 Y
  Y < 0.5  ⇒ 图片底部偏深 ⇒ 条用**浅色**：底 #FFFFFF、字 #222222
  Y ≥ 0.5  ⇒ 图片底部偏浅 ⇒ 条用**深色**：底 #111111、字 #F2F2F2
```

- **角标颜色**跟着主题走（红在黑底上对比不够）：浅条用 `#C6202A`，深条用 `#FF6B61`。
- **取不到像素时**（`imaging` 不可用 / 读失败）⇒ 退回**浅条**（= 现在 的行为），
  并在结果里标 `theme.from="fallback"` 与原因 —— **不静默猜**。
- ⚠️ **如实说明局限**：这是"底部平均色"，遇到**上下渐变 / 照片类**的稿，
  平均值只是个折中；参数条上不会声称"已精确判定"。**要不要在参数条上印出主题依据，
  见 §五 待定项。**

### 3.2 版式（第 2、3 条）

```
┌──────────────────────────────────────────────────────────────┐
│                       图片区（干净）                          │
├──────────────────────────────────────────────────────────────┤
│ 文件名.psd ｜ 导出 2026-10-17 00:40          [审核用 · 非成品] │  ← 角标（按主题配色）
│ CMYK ｜ 8 位 ｜ 300 dpi ｜ 1600 × 1200 px ｜ …  │  ← 参数：**一律竖线分隔**
│ 未转曲文字层 1 个 ｜ 缺失字体 0 个     [logo] 依据 Vellum 出图规范 v3 · 生效日 │  ← 依据块**右对齐**
└──────────────────────────────────────────────────────────────┘
```

- **所有参数一律用 ` ｜ ` 分隔**（原来是 ` · `）。
- **"依据…"从第 3 行里摘出来**，做成**独立的一层**摆在**最后一行右端**，前面加 logo。
- **左右边距加大**：`左右留白 = 条高 × 0.16`（原 `0.125`）——见 §五 待定项 ①。
- 右端两块（角标 / 依据块）都要**占位**：正文盒子的右边界 = 整宽 − `max(角标宽, 依据块宽)` − 半个字间隙，
  免得正文压到它们（上一轮踩过）。

### 3.3 右对齐怎么做得准（关键实现）

```
① 建"依据"文字层：盒子先放在 [右边界 − 估算宽, 右边界]
② 读回 layer.bounds → dx = 右边界 − bounds.right
   ⇒ select + translate(dx, 0)（exportByRows 里已在用的原语）
③ **再读回 bounds 自证**（本项目铁律：没报错 ≠ 生效）
④ 放 logo：placeFile(icons/logo-mark.png) → applyLayerRect(
      { left: 依据.bounds.left − 间隙 − logo宽, 与依据同高居中…} )
⑤ 读回 logo 层 bounds 自证
```
- logo 尺寸取 `高 ≈ 行高`、宽按 256:164 等比；**具体大小见 §五 待定项 ③**。

## 四、第 4 条：审核版要不要压缩（**讨论稿，未定**）

### 4.1 先回答"目前是不是原图"

**是。** 现在「导出审核版」= 原分辨率 + 参数条，**PNG（无损）**，没有缩放、没有转格式。
`saveAs.png` 只支持像素尺寸不变地存 PNG。

### 4.2 你举的那个例子到底有多大

| 项 | 值 |
|---|---|
| 80 × 180 cm @ **150 ppi** | **4724 × 10630 px**（≈ **5020 万像素**） |
| 每边像素上限 | PS 的 PNG 上限 30000 px ⇒ 10630 **不会失败**，只会**又慢又大** |
| 体积量级（经验值） | PNG 约 **15–60 MB**；JPEG q90 约 **25–75 MB** |

⇒ 结论：**你说的没错，这个尺寸直接出 PNG 作为"审核版"是浪费** ——
审核版是给人**看**的，不是给人**印**的。

### 4.3 三条可选路线

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A 不动** | 现状：原图 + PNG | 100% 忠实 | 大稿几十 MB、打开慢、发不出去 |
| **B 按长边上限等比缩小** | 长边 > N 就等比缩到 N，仍存 PNG | 直观、无损失真、体积按**面积**平方下降 | 不是原分辨率（但参数条上会印实际比例，见下） |
| **C 换格式 JPEG** | 尺寸不动，存 JPEG q90 | 体积降 5–20 倍 | **有损**；**参数条上是小字**，细字边缘会有压缩伪影，反而伤"审核"这个用途 |
| **D = B + 阈值**（**我倾向**） | 长边 ≤ N 就不管；超过才缩，仍在参数条上**印出"已缩至 xx% · 实际 w×h"** | 小稿完全不受影响；大稿体积骤降；看版的人**不会误以为看到的是 100%** | 同 B |

**以你的例子算 D 的收益**（长边上限取 4000 px）：

```
4724 × 10630  →  1777 × 4000
面积      5020 万 px  →  711 万 px   （降到 14%）
PNG 体积  ~40 MB      →  ~6 MB
```

### 4.4 建议的默认值（等你拍板）

| 参数 | 建议 | 理由 |
|---|---|---|
| 触发条件 | **长边 > 4000 px** | 4000 已足够 100% 看细节 + 出小样；大多数社媒/常规印刷稿都不到 |
| 缩放比例 | **等比缩到长边 4000** | 不做非线性/算法压缩：UXP 侧没有可控的编码器，且"审核版"要的是**看到真实版式**，不是好看 |
| 格式 | **仍用 PNG** | 参数条上是小字，JPEG 会在细字边缘留伪影 |
| 参数条上 | **印"已缩至 38% · 1777 × 4000 px"**（只在缩过时才印） | 看版的人必须知道这不是原尺寸，否则"审核版"就骗人了 |
| **成品图** | **不动**（仍是原图原尺寸） | 交付用，必须原始；要缩也应该是另一处显式选择 |

> ⚠️ **实现上的一个已知难点**（也请你知悉）：缩放**不能**用"改用户稿的画布"那套
> （`resizeImage` 是重采样，虽然能靠历史回退，但超大稿会很慢/很吃内存）。
> 更稳的是走**备路**（新建高稿 + 跨文档复制图层，R12 已实测）后再缩放 —— 但那样
> "审核版必须真实反映原稿"这条要重新权衡（复制件可能有细微差异）。
> ⇒ **这一条我需要在实现前先做一次探针**，把"怎么缩"钉死。

## 七、v0.9.3 版式三修（2026-10-17，用户真机看图反馈）

用户拿到真稿导出图后报三条：① 文字整体**有些靠上**，应垂直居中；② **logo 位置偏了**（离「依据…」文字空出很远）；③ 追加：「**审核用 · 非成品**」文字要**稍大一些**（怕真被当成成品）。

**先量，不猜**（在真机导出的 1826×4000 样张上按像素量）：

| 症状 | 修的读数 | 修后读数 |
|---|---|---|
| ① 垂直不居中 | 正文**上留白 13 / 下留白 37**（差 24px） | **24 / 26** ✔ |
| ② logo 离得太远 | logo 右 → 依据文字左 = **54px**（≈一整个 logo 宽） | **15px**（≈gap） ✔ |
| ②' logo 还偏下 | logo 中心 112 vs 依据文字中心 104.5（**差 7.5px**） | 同心差 **0px** ✔ |
| ③ 角标太小 | 与正文同字号 | **×1.3**（正文 27.7pt → 角标 36.0pt） ✔ |

### 两个真因（都是"估算 ≠ 真实"）

1. **① 的根因**：`makeTextLayerBox` 只设**字号**、**没设行距** ⇒ PS 用**自动行距**，实际行距 ≠ 我们算的 `lineH`
   ⇒ 按「行数 × lineH」当块高去居中**必然偏上**。
   **修法（纯几何，不依赖任何没验过的描述符）**：建完正文层后**读回它的真实外框**（`readActiveLayerBounds`），
   算出「上下留白相等」需要的位移 `dy`，把正文层平移过去；**角标与依据块用同一个 `dy`** ⇒ 三者的相对位置不变。
   ⚠️ 为什么不去设 `leading`：项目里 `leading` 虽是已建立的**可写**字段，但**读不回来**（S32 实测 undefined）
   ⇒ 按铁律「没报错 ≠ 生效」无法证明它生效，**所以不走那条路**。
2. **② 的根因**：logo 的 x 是按**估算**的「依据」文字宽算的（`fullRight − 估算宽 − gap`），
   而依据文字层实际渲染后是按**真实**右边界贴的 ⇒ 估算偏大就多出一整个 logo 宽的空隙。
   **修法**：logo 的 x **按依据文字的真实外框**算（`logo.right = 真实左边界 − gap`，并夹住"不许压正文"）；
   **垂直同样对齐到依据文字的真实外框中心线**（只对 x 的话 logo 会偏下 7.5px）。
   ⇒ 又一次"**估算换成读回**"，与「右对齐不用对齐枚举」「导出问目录复核」是同一条通则。

### ③ 角标字号

- 新增 `STRIP.tagFontRatio = 1.3`（角标字号 = 正文字号 × 1.3），**只影响角标自己**（字号 + 占宽 + 盒高）。
- 角标盒子高度改用**它自己的行高**，否则字号变大后被盒子截断。
- 判据：`M5-28`（离线：倍数 = 1.3、盒高 ≥ 角标字号、不压正文）+ `M5-24` 跟着改。

### 回归判据（S59 扩了两条不变量 + 一条同心判据）

- **正文墨迹在条里上下留白相等**（容差 2px）
- **logo 右边界 = 依据文字左边界 − gap**（容差 2px）—— 不允许"多出一个 logo 宽"
- **logo 与依据文字同心**（容差 2px）

**自证**：真机 **71/72**（唯一 FAIL 仍是既有的 S17）；离线 **101/101**。
真机 S59 读数：`logo 与依据间隙=8（须≈7）　logo 与文字同心差=0px　正文上下留白=14/14`（两套主题都成立）。
物证：`docs/52-样张-用户真稿CMYK导出.png`（真稿导出）＋ `preview/52-strip-real-doc.png`（参数条裁切）。
